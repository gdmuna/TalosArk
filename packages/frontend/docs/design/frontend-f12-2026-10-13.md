# F12：启动恢复与模块化装配

日期：2026-10-13。

## 范围与决策

用户授权执行 F12 及数据源装配/加载的模块化调整。F13 交由其他 agent；
F14 的 view-host 暂时保留，本轮不启用、不删除或修改其实现。

采用先挂载最小桌面外壳、再加载主工作区必要数据的行为：标题栏和窗口控件始终保留。
失败呈现替代尚未就绪的业务视图；登录与回调不依赖业务数据加载。
三个读取阶段均允许手动重试，保持 account -> workspace -> workbench 顺序。

当前工作台快照同时供侧栏最近访问、命令面板和材料/库存/设备骨架使用，因此仍为
主工作区的共享就绪依赖，不按“仅工作台页面需要”处理。
未来页面特有远程数据应在对应业务模块及消费上下文加载，不扩充启动阶段清单。
静态路由导入不变，也不新增通用 DI 容器、自动模块发现或启动任务框架。

## 职责与接口

- `main.ts`：安装 Vue、Pinia、Router，装配 HTTP/auth，提供启动上下文；注册一次导航并拥有最终释放。
- `bootstrap.ts`：显式选择/注入 `ApplicationDataSources`，各数据源创建一次；绑定但不请求。
  支持按模块替换，未替换模块保留当前 mock，实现分阶段接入；
  维护阶段进度、失败反馈、共享进行中的 Promise 与成功检查点。
- `module/{account,workspace,workbench}/model/store.ts`：`connect(source)` 绑定依赖，
  `load(signal?)` 读取并应用该模块快照；`initialize(source)` 原接口保留为两者的组合。
  不更改写入、写后同步、工作区选择或业务返回值。
- `data/source.ts`：`load` 增加可选 `AbortSignal`，旧无参数实现仍满足契约。
  远程 adapter 应把信号交给传输层；model 使用已有 task 原语处理不遵循取消的 adapter。
- `layout/startup`：提供仅含 state/start 的呈现上下文及加载/失败视图；没有业务接口或底层请求。
- 路由 `requiresApplicationData`：控制业务数据就绪展示，不是认证/授权判定。
  Shell 观察该标记，进入主工作区时请求启动；公共 auth 页不触发读取。
- ESLint：具体 mock 仅允许应用装配 `bootstrap.ts` 选择；model 仍只依赖 data/source 契约。

数据源重绑和 store scope 释放会取消该模块进行中的 load。每次读取在应用快照前检查
取消状态，因此即便底层 Promise 晚到，也不会将旧数据写回。
应用启动释放取消整个进行中的启动流程，不再发布 ready/error，也不允许再次启动。
重新加载不重建数据源、不重跑已完成阶段，不注册导航或回放写入。

## F13 接入边界

HTTP/auth 装配与释放仍在 main，未改 refresh/logout、认证 barrier 或 Cookie 协议。
F13/P03 接入真实当前账户时，可以向 `createApplicationBootstrap(pinia, sources)` 提供
真实账户数据源，例如 `{ account: accountSource }`，不必在 main 选择其他 mock；
恢复认证必须先于依赖它的账户读取。业务 ready 不代表已认证。
会话变化的数据清理/重建仍须随真实认证策略设计，不能沿用 mock ready 冒充会话隔离。
本轮没有新材料/库存端点、分页契约、权限策略或后端写入。

## 验证

沿用 localhost:4444；Python 环境未安装 Playwright，使用现有 Node Playwright 与隔离
headless Edge 上下文进行一次性内联探针，不新增持久测试脚本。

- 真实 store + 故障/延迟 adapter：装配不读取，三个阶段各自失败后均可恢复；
  并发启动/重试共享一个 Promise，成功阶段只读一次，失败阶段读两次，就绪后启动不重复读取。
- 三个阶段分别在底层忽略取消时释放：等待立即结束，信号取消，晚到快照不写入，
  不执行后续阶段，也不能重新启动已释放的 bootstrap。
- 三个真实 store：重绑数据源和 scope 释放均取消旧 load；旧 initialize 和账户编辑、
  工作区切换、工作台任务完成行为保持。隔离模型探针共 51 个断言。
- 单独替换账户数据源：自定义账户只读取一次，工作区/工作台默认源正常加载，
  工作台资源仍为 18；未要求调用方重新创建其他模块的 mock。
- 真实应用分别注入三阶段单次读取失败：标题栏可见，业务侧栏尚未挂载，失败原因与
  重新加载入口可见；重试后完整业务视图出现，材料列表 q/hash 保留，不重复成功读取。
- 直接访问登录页，强制所有业务读取失败也不触发启动失败 UI；公共登录和标题栏正常显示。
  页面探针共 30 个断言，无 browser pageerror。
- 导航 popstate 监听：启动 1 次、数据失败重试后仍 1 次、实际应用卸载后 0 个有效监听。
- 加载失败/恢复截图位于忽略目录 output/f12-startup-{error,ready}.png，已检查视觉布局。
- 生产 vue-tsc、含架构门禁的 ESLint、Vite build 和 whitespace 检查通过。
  保留原有 Workbench.vue 未使用 ChevronDown 警告与 JS chunk 体积警告，未添加路由懒加载。

未运行失配的旧全量测试套件、真实后端/身份提供商或 Tauri 原生窗口验收。
没有用 mock 读取成功证明 F13/P03 已接通。
