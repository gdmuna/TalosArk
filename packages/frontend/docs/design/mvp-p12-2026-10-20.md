# P12 真实审批前端接入

日期：2026-10-20。状态：已实现，本地真实 Web 定向验收通过。业务及验证边界见[联合验收](../../../../docs/product/mvp-p12-acceptance-2026-10-20.md)。

## 归属与入口

`module/approval/data` 拥有公开 Zod 契约解码、身份/作用域和分页一致性检查；`model/read.ts` 负责随账户、工作区、查询和卸载取消读取，丢弃晚到结果；`model/operation.ts` 独立保存审批原命令与结果恢复，不把审批状态机放进 Workbench。

`ui/ApprovalComposeView.vue` 是多件申请编辑器，支持分页选择库存及逐条数量/目标位置、合资格审批人和关联重申请。`ApprovalDetailView.vue` 负责单据、完整审核、分页明细、逐条执行/放弃/撤销和处理历史。`ApprovalQueueView.vue` 提供待审批、待执行、我的申请。页面复用 DataTable、SelectField、StateBadge、Dialog、ButtonGroup，不新增一套表格或工作流组件。

库存位置选择器移至 `module/inventory/ui/InventoryPositionPicker.vue` 并从公共入口导出；原入库、直接动作和新审批表单共用它。它仍基于 Facility 当前授权、可用性和占用事实选择位置，真正提交/执行时服务端再校验。

工作台新增 `/main/workbench/request/new` 和 `/main/workbench/request/:requestId`。库存行菜单和注册的多选菜单只负责把选中的实物带入同一种动作的一份新申请，不等于多明细一键执行。工作台概览按独立真实来源增加审批摘要/最近待审批，普通任务与异常来源仍按已有可用性边界展示。

## 上下文与恢复

审批页面 URL 带 `organization`、`workspace`。Workbench 壳层先将这对 ID 与已授权目录匹配，并通过既有服务端工作区选择校验，再挂载审批视图；缺省 URL 由当前有效上下文补齐。刷新和深链接不会把某个申请 ID 错放到默认第一个工作区查询。URL 不是授权凭据；切换工作区后更新 URL 并卸载旧视图。

审核先读取最新表头和所有明细页，检查总数/行序。每条初始结论均为“待选择”，不能把未加载、未勾选或当前页外的行当作拒绝。“全单批准/拒绝”是用户显式选择，提交始终发送完整结论集。普通明细展示可以分页，但业务提交不被每页 100 条截断。

每次命令先在按用户隔离的 `sessionStorage` 保存作用域、原始 body 和幂等键；写入前无法保存就不发送。结果不明时保留原请求，恢复仍使用原 body/key。已有明确成功回执时，只读取操作结果和页面，不再发原写入。页面同步完整成功后才清除对应恢复项。退出/换账户清理身份归属的恢复数据，作用域变化不得把旧结果写入新页面。

转移使用完整实物和目标位置，消耗使用精确数量字符串。界面依赖当前能力投影控制按钮，临时阻塞原因独立于审批结论；这些提示不替代后端授权，也不伪造本地库存扣减。

## 验证与限制

Vue 类型检查、生产构建和本次源码定向 ESLint 通过。真实 Edge/Playwright 完成多件提交、部分审批、响应丢失恢复、成功后同步失败只读恢复、转移选位与执行、工作台查询、上下文延迟结果隔离及不同宽度截图检查。没有创建永久测试脚本，临时材料在 `output/p12-2026-10-20/`。

延续桌面壳层最小内容宽度，未重做移动端应用。没有服务端草稿、自动失效、跨单批量审批、多明细一键执行或通知送达能力。Tauri 和生产环境未验收。
