# P03：真实账户与 Web 会话接入

实施日期：2026-10-14。范围来自 [MVP 工作安排](../../../../docs/product/mvp-work-plan.md)。

## 这轮交付什么

- 用用户名或邮箱和密码登录；用户名保留大小写，密码不 trim。
- 打开受控开户的激活链接，设置首次密码，成功后自行登录；不自动开户或自动登录。
- 保留企业 SSO；已登录账户可请求设置首个本地密码，资格与最近登录限制仍由后端判断。
- 登录后读取真实 `/user/me`，不再展示模拟用户。
- 刷新页面和重新启动浏览器时，通过 HttpOnly RT Cookie 取得内存 AT。
- 退出调用真实接口，正确处理无响应体的 204；失败也清理本地，但不声称服务器已经撤销。

用户本轮确认了三条边界：先验收 Web；不自动绑定模拟组织；退出撤销失败仍本地清理且明确告知。
没有真实工作区接口时显示“暂无可用工作区”，这不是已经查询并确认用户没有成员关系。
工作区、材料、库存和工作台页面/Mock 适配器保留，但默认组合不加载它们；后续随 P04 等业务切片接入。

## 正常启动与刷新

1. 公共认证页不自动读取账户、工作区或工作台。
2. 受保护入口先尝试 Cookie refresh；该请求使用 `auth: none`，不带 AT，不等待自己的认证屏障。
3. 恢复成功后读取账户，并检查账户 ID 与会话一致，再展示业务壳。
4. 已登录期间，既有认证屏障合并同一标签页的并发刷新；刷新不能偷偷更换 session/user 身份。
5. 仅 AT 轮换不重置业务状态；登录、退出、失效或其他标签页账户变更才更换前端会话版本。

无 Cookie/401 确认为 anonymous 后进入登录页；网络/服务恢复失败、403 或异常响应保留 error 状态和原受保护 URL，由现有 ApplicationStartup 显示失败原因与手动重试入口，不把不确定状态当作未登录。失败不清除 Cookie、不写入退出标记，也不自动重放 refresh。手动恢复成功继续原目标页面，保留 query/hash。登录页不再重复呈现会话恢复错误/重试按钮，但保留表单/SSO 错误和退出提示。
账户读取失败只重试未完成的账户阶段，不重做已成功的恢复或登录。
所有涉及 RT 消费的请求都不自动网络重试；服务器已处理但响应丢失时，只能报告结果未确认，不能保证安全重放。

## 标签页协调与退出

同一前端 Origin、同一 API 根的 Cookie 操作使用一个 Web Lock。
登录、OIDC 开始/回调、refresh、logout、首次设密及恢复确认都通过既有 Auth owner 协调；
首次设密先在锁外取得有效 AT，锁内采用 fail 模式，避免等待自己的刷新而死锁。
激活不更换 Cookie，会话锁不替代后端的一次性凭据与事务保证。

`localStorage` 只存随机协调版本、`signedOut` 和服务器撤销是否确认；不存 AT、RT、密码、账户资料或激活/恢复 Token。
通过 storage 事件清理其他标签页的身份和旧数据；提交登录结果前也直接检查持久版本，不能仅等待事件调度。
机制依据：[Web Locks](https://developer.mozilla.org/en-US/docs/Web/API/Web_Locks_API)、[storage 事件](https://developer.mozilla.org/en-US/docs/Web/API/Window/storage_event)。

退出先失效本地会话和业务数据，再串行调用服务器：

- 204：标记服务器撤销已确认。
- 断网、期限、拒绝或协议错误：保留本地退出，提示“服务器会话撤销未确认”。
- 退出标记跨刷新和浏览器重开保留，防止尚存的 HttpOnly Cookie 自动恢复旧身份；明确的新登录成功后解除抑制。
- 晚到的旧登录、OIDC 回调和 refresh 不能覆盖退出或新身份；旧 logout 结果也不清除较新的登录。

退出结果只更新确认提示，不再次推进会话版本；同一退出版本的跨标签确认也不取消正在排队的新登录。
服务器撤销确认的持久写入仍在 Cookie 锁内，避免锁释放后的确认覆盖新的登录标记。

退出标记不是服务器授权凭据，也无法替代真正的服务器撤销。
无法使用 Web Locks 的非安全页面、被禁止的站点存储不静默退回不安全的跨标签页流程。
不同前端 Origin（包括不同端口）不共享 Web Lock/storage；不要把这个同源保证扩展成跨站协调。
后端现有 SameSite=Lax Cookie 未改动；本轮 localhost 同站验证不证明跨站 HTTPS 或 Tauri WebView 的 Cookie 能力。

## 数据和页面隔离

账户、组织/工作区和工作台 Store 都增加 reset，取消读作用域并清空旧记录、选择和错误。
等待中的读，即使数据源不理会取消，也不能重新发布旧快照；旧写入完成后也不能给新的页面状态写回同步结果。
这不撤回已经在服务器提交的业务写入，也不会把“重置”做成第二次写请求。
HMR/卸载释放 HTTP、会话协调、路由守卫、启动作用域和 Pinia。

激活和恢复链接先从 URL 移除，页面中不显示凭据；完成、失效或卸载时清掉页面秘密和密码。
手机/邮箱验证码及未接通的第三方入口禁用，不制造虚假登录功能。
账户设置可在无工作区时访问，资料与通知写入仍按真实能力禁用。

## 验证结果

2026-10-14，按用户实测修正服务不可用时的展示：认证门禁与会话版本监听此前将 error 和 anonymous 一起重定向；启动状态已经正确记录失败，但因跳转而被隐藏。现在仅 anonymous 重定向，保留 error 的原地址并复用 ApplicationStartup；删除登录页重复恢复提示和专用恢复按钮。一次性 Edge/Playwright 从真实页面复现原错误并验证修复，共 49 个断言，覆盖断网、503、403、异常响应、失败重试、错误态切换受保护路由、恢复后 query/hash、401 与首次设密入口、账户阶段独立重试、公开登录不自动请求、密码错误反馈及已登录期间刷新失败/恢复；没有 browser pageerror。启动提示展示时使用可用窗口宽度，390px/1366px 下标题和错误文案完整可见，无横向溢出；正常业务页面仍保留最小宽度。生产类型检查、架构 ESLint、Vite build 和 diff 检查通过，仅保留原有告警。截图位于 ignored output/startup-service-unavailable.png。仅使用拦截/合成 HTTP 响应，没有真实后端写入、Cookie/提供商或 Tauri 重新验收，没有新增维护中的测试脚本。

先前启动失败复核采用“网络失败进入登录页并保留恢复提示”的导航降级，15 项隔离检查在当时通过；该展示行为已被上述用户确认的启动提示替代，不能作为当前 UX 的验收依据。其余真实后端交付证据保留如下。

- 前后端/contract 构建、生产类型检查、前端架构 ESLint 与 diff 检查通过。
- Edge + Playwright 使用真实 test 库、Valkey、Fastify 和本地合成 SMTP，通过 **36 项浏览器检查**。
  覆盖真实激活/账密/账户、冷启动、Cookie 的 HttpOnly 和持久到期、页面刷新、浏览器进程关闭重开、
  双标签同时恢复且后端 refresh 最大在途数为 1、跨标签退出、断网退出后重开不自动复活、
  网络恢复错误/重试、403 不误判过期、首次设密的新会话，以及 1366px/390px 截图和窄屏溢出。
- **23 项定向模型/HTTP 检查**覆盖十二个并发过期 AT 读取只刷新一次、取消后的迟到恢复/登录/OIDC、
  退出未确认提示、旧退出结果不取消随后排队的新登录、严格空 204 解码、旧账户/工作区/工作台快照隔离，以及启动重置。
- OIDC 供应商使用合成 resolver；事务 Cookie、KVS 消费、账户和会话仍走真实后端。没有连接真实 Casdoor。
