## F03：资源预览

`module/workbench/model/resource-preview.ts` 的 `useResourcePreview` 接收 Resource/null
选择、调用方的资源集合和可选父上下文。它返回当前摘要、可写 selectedId 和 open。
资源解析始终要求工作区匹配，并从当前集合取得最新对象，而非继续展示旧对象副本。

- 工作区或父上下文变化，清除选择。
- 资源摘要被新对象替换时，更新预览内容。
- 资源删除或不再属于调用方集合时，清除对象与 ID；资源重回集合不会自动重开。
- 调用方 scope 释放时清除选择。
- 不持有 URL 或修改 query/hash，不改变一次性 Query 消费。

统一接入 ResourceDialog、ResourcePreview、材料/资源列表和材料详情内嵌实例预览。
材料详情额外将材料 ID 作为父上下文，实例集合仍由该材料的关联关系限定。
现有 ResourceDialog/ResourcePreview 的 Resource/null model、正常开关和详情跳转保留。
没有创建资源业务 module、后端端点、额外资源缓存或后台请求。

## F04：命令索引

`ui/command/useCommandIndex.ts` 在 Command provider 内拥有一个条目 Map。
每条保存搜索文本与组 ID；匹配分数、结果数和组可见性从同一索引派生。
CommandItem 负责更新登记信息和卸载注销，组不再另行维护重复成员表。

新增可选 `textValue`：它与 value 身份分开，与 keywords 一起响应式更新。
当前命令面板和面包屑选择器都传入动态标签；条目被过滤、其 ListboxItem DOM
被卸载时，CommandItem 的登记仍随 props 更新，不需要改 key 或强制重挂载。
命令面板将原先可搜索的状态文本保留在 keywords 中。

未传 textValue 的兼容调用使用 DOM 文本回退，并观察可见 slot 的文本变化。
动态标签必须传 textValue：DOM 不存在时无法观察 slot 文本，回退不是隐藏项目的动态标签契约。
显式 textValue 的当前调用不创建原生 MutationObserver；回退观察器随 scope 释放。
没有组的 CommandItem 使用空组上下文，仍可搜索、导航，不要求额外 Group 包装。

键盘导航、禁用项、输入与 composition 处理继续由原 Reka Listbox 原语负责；
没有第二套搜索索引、键盘引擎、IME 实现或新的排序匹配规则。
