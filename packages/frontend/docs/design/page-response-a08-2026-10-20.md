# A08 页码响应与请求一致性

日期：2026-10-20。状态：已实施。范围：库存列表、库存流水、材料批次列表和设施列表的前端 HTTP 数据源。

## 决策与依据

四个入口原先在三个位置重复检查响应页码、每页数量、条目上限、总数下限和同页 ID 唯一性。这些条件涉及一次读取的请求参数，不能仅由响应 schema 的字段类型判断。共同规则现由 `platform/http/page-response.ts` 维护；数据源在解码后调用它，并保留各自原有的中文 `HttpError` 消息与 `protocol` 类别。库存原有的单层转发函数已移除。

库存和批次入口使用发送给 HTTP 客户端的已解析参数作比较，因此 `page` 和 `pageSize` 的参照值与实际请求一致。设施入口直接比较传给请求的查询值。共同模块只接收本次查询、解码后的页和原有错误消息，不引入新的分页 schema、默认值或游标语义。

## 保留的行为与边界

- 四个入口都要求响应 `page`、`pageSize` 与请求一致，条目数不超过请求 `pageSize`，`total` 不小于本页条目数，同页 ID 不重复。与请求相同的空页仍可接受。
- 库存列表和批次列表仍在分页检查后校验业务范围与身份；库存流水仍检查工作区。设施仍先校验每个条目的组织范围，并保留安全整数 `total` 与非空 ID 的额外检查。各入口的错误消息和 `protocol` 类别不变。
- 材料主列表不使用这项校验。后端允许把超出范围的页码调整为末页，前端继续接受这种返回。游标分页和其他数据源不受影响。
- 这里的“对应本次请求”只指分页字段和本页内部一致性。响应没有回显客户端请求标识或全部筛选条件，因此校验不能证明服务端采用了正确的 `q`、状态等过滤条件，也不能证明数据最新。HTTP 客户端将响应交给发起它的请求 Promise；过期读取仍由现有取消和状态失效逻辑处理。服务端 `requestId` 是诊断标识，本次未把它当作客户端请求匹配令牌。

## 验证与收益

通过四个数据源的 `HttpClient` interface 注入一次性响应，验证正常页、空页、错页、错误 `pageSize`、条目超限、`total` 过小、重复 ID，以及原消息和 `protocol` 类别；另验证设施组织范围优先级与额外规则、库存/批次业务范围、材料主列表的页码修正，共 33 项通过。该验收使用模拟 HTTP 返回值，未覆盖真实网络和登录后的页面交互；临时用例未留在仓库。

定向 ESLint、Prettier、前端 `type-check` 和 `vite:build` 通过。构建仍有大于 500 kB 的分块提示，与本次改动无关。共同五项规则现仅有一处维护点，四个入口复用；没有改变后端或 contract 对外格式。
