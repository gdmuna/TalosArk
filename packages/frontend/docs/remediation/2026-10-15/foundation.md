# 公共基础与验收规则

配合 [主计划](README.md) 使用。此处是页面共性，不替代七个分册的逐页业务要求。

## 1. 设计依据的优先级

1. 用户后续已确认的交互与业务规则、真实契约和领域边界。
2. 当前 `design-foundation.md` 与 `src/style.css`：设计令牌、字体、颜色、控件。
3. 已认可的工作台概览：真实产品的信息密度、节制、对齐与留白。
4. 71 张稿的信息架构、模块比例、操作层级；结合 REVIEW-NOTES 去除生成错误。

稿件用于恢复内容和构图，不用于重新引入蓝灰整页滤镜、复杂投影、卡片套卡片、永久业务二级侧栏、旧 inline Inspector 或猜测的企业功能。现有设计系统也不能成为把设计稿删成空表格的理由。

## 2. 正文宽度要分四层管理

### 2.1 窗口与外壳

保留当前业务桌面外壳最小宽度机制；`min-w-4xl` 只是外壳下限，不保证正文可读。认证与启动状态采用流式布局，不强迫小窗口继承桌面业务最小宽度。此轮不宣布移动端业务全站适配完成。

### 2.2 页面画布

普通列表和概览使用独立于数据的居中画布：**可用区内 `width:100%`，基准最大宽度 1200px**，常规左右内边距 24px，窄窗口 16px。1200px 与已认可工作台对齐，不等于所有内嵌表格列自动伸长。

以下为实施目标，先在 R01 做工作区、成员、材料详情三个代表页验证：

| 类型 | 宽度与构图 | 宽度不足时 |
| --- | --- | --- |
| 普通列表/概览 | 1200px 上限，画布不随行数/列数缩小；960px 为舒适宽度测试线，不是所有层的硬 CSS min-width | 先调整工具栏，再让表格局部横滚；不缩字、不把根页面拉出隐蔽横滚 |
| 重型对象详情 | 1280px 上限；对象头、标签、正文同一左右对齐线；常见主辅比例约 2:1 | 正文可用宽度不足 1000px 改单列，次要摘要后置，标签横滚 |
| 拓扑/谱系/矩阵/操作工作区 | 利用可用宽度，上限 1440px；画布工具本身设稳定最小工作宽度 | 收起局部辅助面板/树，工具画布独立横滚，不压成三条窄列 |
| 单表单 | 可编辑字段区最大 720px；复杂双栏设置可至 1120px | 标签在字段上方；危险操作单独分区，不挤在同一行 |
| 短摘要/小数量卡片 | 每项稳定约 240-280px、常见高 88-104px，按实际内容校准 | 自动换行但不均分填满整行；容器不套装饰外卡片 |

不要把 `min-w-0` 批量改成某个固定最小值：它是 flex/grid 中允许子项正确收缩的必要约束。应给**页面画布、工具内容区**明确尺寸责任。`max-width` 不提供下限，`w-fit` 也不适用于整页画布。

1000px 是详情主辅区域的断点，不要求每个内部事实列表也一直单列。字段列表按自己的可用宽度在 640px 起采用两列，低于 640px 单列；不能因主区只占正文约 2/3，就把十项基本信息拉成十行并把批次列表推到首屏以外。

### 2.3 表格

保留固定列宽及用户调整结果；页面不再由列宽之和决定。表格小于画布时，与页面起始对齐线保持一致，不再把窄表格自己居中成“页面里的小岛”。若某类表确实需要填满画布，调用方明确指定名称/说明列承担剩余宽度，列宽下限与手动调整优先级要写清；禁止所有列平均拉伸和插入空白占位列。

这延续“业务整体居中、保留列宽”的意图，但纠正了把“整体”错误实现为一块随两列数据缩小的 `w-fit` 容器。页脚跟随表格，不人为铺满窗口。

R01 代表页不能以“列宽没变”为由接受工具栏横跨画布、表格只占左侧一小块的脱节。默认固定列宽的表格，其工具栏跟随实际表框可用宽度。需要满画布的表由调用方显式标记一列 `fill`（名称或说明；多个标记时取首个可见列），只由该列承担剩余宽度，受 min/max 约束；任何列开始手动调宽时，将当前自动填充宽度固定为本次手动布局，避免填充列反向吸收位移而使把手不跟随光标。显式 sizing 优先，清除该填充列 sizing 后才恢复自动填充。未标记列及其他表行为不变；不自动重置用户宽度。

### 2.4 工具栏与页脚

- 工具栏以页面/表格可用宽度为依据，筛选/排序/批量操作在左、搜索在右；主要创建动作在页面动作区，避免与字段工具重复。
- 空间不足时工具栏可有**有意设计的第二行**：第一行命令，第二行整宽搜索；禁止在按钮间随机挤出几段空白。
- 分页在正常桌面宽度同排：总数左，页容量/页码/翻页右；不足时仅拆成“总数+容量”和“页码+翻页”两组。页容量包括 100，无额外下拉 title。
- 对纯服务端分页，筛选、排序、总数必须来自同一查询语义；不能只过滤当前页却声称全量过滤。若 DataTable 缺能力，最小扩展组件契约，不擅自改成一次下载所有成员。

## 3. 视觉语言

### 3.1 颜色

- `muted` 用于 custom titlebar、侧栏、全屏启动/认证外层；`background` 用于业务画布；`card/popover` 用于真正抬起的工具/浮层。
- 主蓝色只突出主动作、当前导航、焦点与确实需要的标识；不把所有标题、图标、数值都染蓝。
- 状态使用已有语义色及 soft/foreground 配对。异常“严重/一般/提示”从**一份映射**同时驱动摘要图标、列表图标、badge、Sheet，不能各处各写一套橙/黄/红。
- 材料类别等无好坏之分的枚举使用稳定的分类色映射，基于已有 chart 系列配套的 soft/foreground（不足先集中补令牌并验对比度）；禁止借 success/warning 冒充类别色，也不按排序索引漂移。
- 截止时间普通前景色；逾期由明确的状态 badge 与筛选表达，不重新把所有时间变红。
- 不从每张 PNG 采样一套背景色，不新增页面专属 token 仓库。

### 3.2 字体、间距与边框

沿用 Source Han Sans、当前 14px 正文和 20px 行高等令牌。紧凑表格标题不要做成营销大标题；不使用负字距或按 vw 缩字号。常规模块间距 24px，相关控件 8/12px，表格横向内边距统一 10px。面板与重复卡片圆角不超过现有 8px 体系，已有品牌/壳体特殊圆角除外。

图标沿用现有 Lucide 体系和全局 1.5 线宽约定，不为单页重新显式设置一遍；品牌图形或第三方形变图标的必要差异另行处理。不混搭 emoji、手绘 SVG 和不同粗细的常规操作图标。

模块用标题、分隔线、网格和留白组织；只给重复对象卡片、模态框、真正的工具画布加边框。不要为了“丰富”再套一层卡片。长中文、邮箱、ID、面包屑必须截断/换行有规则，并提供可达的完整值。

### 3.3 图表与图像

能用数值和小型趋势表达就不放大环图。图表必须有可访问摘要、明确时间窗口/单位、真实聚合接口；缺数据不画随机曲线。图表库沿用已安装方案，谱系优先现有 Vue Flow/Dagre 依赖，不为这次整改增加另一套基础设施。

设备/设施/材料有真实图像时才显示；没有时用现有领域图标和稳定占位，不伪造资产照片。拓扑先保证二维位置可检查，不把“3D 冰箱插图”当软件 MVP 必选项。

## 4. 外壳、导航与对象上下文

- 使用当前分页式主侧栏管理导航；不照搬稿件中错位的横向超长管理导航，也不重新加一套永久管理侧栏。
- 全局搜索只放侧栏入口。顶栏保留历史、面包屑、通知/帮助/设置/用户；未实现按钮不能长期无响应。
- 普通列表已有全局面包屑和局部导航时，不重复三遍大标题。但管理对象名、组织上下文和真实主动作必须可见。
- 重型详情统一“对象头 → 本地标签 → 正文”，头部包含名称、ID、类型/状态、组织/工作区、主次动作；不能直接从空表格开始。
- 本地标签可映射 `view` query；保留其他 query，刷新与前后退恢复视图。对象 ID 在 path，不能依赖列表内存选择。
- 页面对象所属工作区、当前激活工作区、管理组织、操作身份分别表达。访问某个工作区详情不能静默切换全局工作区；切换动作必须明确。

## 5. 表格交互不可回退清单

本次以现有 DataTable 为基础，先修布局，不重新推倒已反复调整的交互。

| 项目 | 验收要求 |
| --- | --- |
| 选择 | 第一列复选框严格居中，整 cell 可点击；不与首业务列整 cell 预览冲突；批量作用范围明确是本页还是全部结果 |
| 预览 | 首业务 cell 的主标题 hover/focus 出下划线；整 cell 可触发 Sheet，内部链接/菜单不会冒泡双触发 |
| 筛选 | 摘要固定列对齐；字符串有“包含”等上下文；二级清除在右上，一级垃圾桶；枚举标题左全选/半选，筛选输入组件传 `mode="options"` 渲染复选项（不是给底层 Checkbox 新造 mode 属性） |
| 计数 | 保留当前按激活字段计数口径；“一个字段多勾选怎么算”仍是讨论项，不在视觉任务中静默改规则 |
| 个人视图 | 筛选/排序/可见性菜单标题旁问号，hover 与点击可读 tooltip，说明只影响个人视图，不影响同工作区其他用户 |
| 列可见性 | 有操作列时放操作表头，使用与行菜单不同的设置类图标；无操作列时工具栏入口。保留两种位置的互斥逻辑，不误删后备入口 |
| 行操作 | 明确主动作 + 行更多菜单，避免表头和每行都是难区分的省略号；不把所有动作做成 icon-only |
| 批量操作 | 顶部注册式菜单，无选择禁用，有选择显示数量，支持调用方权限/可用性；异常页也有，不恢复旧底部悬浮条 |
| 排序拖拽 | 表头、排序优先级、列可见性都有跟手虚影、低层落点提示、开始/结束/兄弟补间；无蓝色辅助线、禁止光标闪烁或结束一帧空白 |
| 判定 | 表头合法拖拽范围覆盖本表全部 cell；按移动方向综合光标与虚影中心，先越过的有效点触发，加入方向/稳定性约束避免来回抖动 |
| 边框 | cell 独立完整边界，静止时相邻边只呈一条 1px；拖动中内容保留最多 100 条，不通过隐藏内容掩盖边框；检查变换层级和像素对齐 |
| 调宽 | 把手在边界顶部居中，左右两半 hover 都可见，拖动离开表头仍显示；居中画布引起原点位移时用实际边界求位移，不能只累加原始鼠标 dx |
| 滚动 | 原生 X 容器包纵向 ScrollArea，两者 smooth/reduced-motion；表头/体同横向内容宽度；调宽后原生 X 可抵达真正最右端 |
| 高度 | 可用高度不足时记录区纵滚，至少预留现有 minRows/最小高度；页头页脚不被错误高度预算挤走；无溢出时不多 1px 滚动 |
| 渐隐 | 表内只保留操作列左侧既有曲线渐隐，紧贴列边界，无实色平台、0.5px 魔法偏移或双边框；不重新给表体上下加装饰渐隐/线 |

除非有明确复现，不为满足本计划再次重写拖拽算法。表格回归截图至少覆盖宽列跨窄列、窄列跨宽列、向左/右拖、滚动后拖、调宽到溢出、100 条记录与 125% 缩放。

## 6. 浮层、焦点与工具提示

- 预览统一 Sheet；短决策/单步提交用 Dialog；长录入可用 Sheet；锚定选择器用 Popover。G 图中的旧嵌入式 Inspector 仅参考信息内容。
- 遮罩覆盖应用和标题栏；Sheet 内容通过共享 chrome 高度从标题栏下方开始，不能写死只适用于一个窗口的 top。保留唯一 z-10000 窗口控件组，不在每个 Sheet 复制一套假窗口按钮。
- 弹层由 overlay-container 管理，测试 focus trap、背景 inert、窗口控件交互、Esc、返回触发点和嵌套弹层。窗口控件应在运行载体实际可用，浏览器预览不假装具备系统窗口能力。
- UserMenu→WorkspaceSwitcher 先完成菜单焦点交接，再打开目标浮层；不得回归“一闪即消失”。深层关闭应返回实际仍存在的触发点。
- Button 继续 `useTooltip` 显式开启、tooltip 提供内容、默认关闭。常用图标工具需要 tooltip + accessible name；普通文字按钮不强制包 tooltip。原生 title 不能作为唯一解释。
- 命令面板的键盘目标必须落在可见安全区。渐隐/分隔线不参与布局时，通过 viewport scroll-padding、item scroll-margin 或既有 focusInset 避让；连续按键避免多个 smooth 动画排队。不能只修鼠标滚动。

## 7. 状态和真实数据

每页必须设计并验证：首次加载、空数据、筛选无结果、无权限、网络失败、局部失败、已有数据重载、提交中、提交成功但同步失败。没有失败消息不等于成功。

空态要给当前对象/范围和可执行的下一步，而非通用大插画。不能读取总量就显示“暂不可用/未获取”及原因，不显示 0。无权限不透露本应不可见的名称/成员数量。已有数据的刷新失败可保留旧数据并标记时间/过期状态，不能清空成“暂无数据”。

已提交写入与读模型同步分离：同步失败只重试读取，不自动重发创建、邀请、授权、库存操作。前端禁用和隐藏只是体验，不替代后端授权。工作区切换必须取消/隔离旧请求，晚到结果不得污染新上下文。

## 8. 组件职责与文件组织

- `ui/` 维持低层外观/可访问性；`component/` 放确有复用的表格、对象头、状态、Sheet、文件等组合组件。
- `layout/` 管应用 chrome、导航、启动，不加入某个管理页面的列定义/权限规则。
- `page/` 负责路由组装和构图；`module/<domain>/` 持有数据源、状态、命令与领域 UI。`page/resource/` 是表现复用，不上升为另一个资源业务内核。
- TeamManagement 复用真实模型/命令，但将组织列表、工作区成员视图和角色详情的呈现区分开；不复制 500 行组件，不做一个几十个布尔参数的万能页面。
- 新增对象详情按上下文分组，例如 `page/management/workspace/`、`role/`、`member/`；它们只是建议路径，迁移现有文件时保持路由功能，不全站再做文件结构重构。
- 不为了未来页面创建通用 DSL/Registry、第二套 toast、第二套状态 badge、另一套 CSS 令牌或测试平台。两个以上真实调用方且逻辑足够复杂时再抽取。

## 9. 验收矩阵

| 维度 | 最低覆盖 |
| --- | --- |
| 视口 | 1024×768、1280×800、1440×900、1920×1080、2560×1440；侧栏展开/收起；125% 缩放；认证额外 390px |
| 主题 | 默认主题逐页截图；用户在 R02 开始前明确暂缓深色主题，本轮不以暗色验收为前置条件，也不删除既有支持；恢复该项时检查 token/图表/边界，不临时硬编码白色遮罩 |
| 数据密度 | 0/1/10/100 条、很长中文名称/邮箱/ID、多行说明、所有列隐藏至最小集合 |
| 权限 | 无组织、组织普通成员、工作区读者、工作区管理员、组织所有者；跨组织不可见与越权深链 |
| 输入 | 鼠标、键盘 Tab/Enter/Esc/箭头、中文 IME、拖拽、触控板；reduced-motion |
| 可靠性 | 断网、5xx、401/403/404、重试、双击提交、成功后读取失败、切换工作区后晚到响应 |
| 截图 | 页面整图 + 关键局部，至少 E-03/E-04/E-05/F-01/F-02 的设计逐项勾选；不能只测 CSS 是否存在 |

任何截图出现随机换行的分页、数据少导致画布骤缩、卡片无意义铺满、主辅区没有层级、按钮无行为、未知显示成成功、弹层压住窗口控件，都不得宣称该页通过。

## 10. R01 视觉门禁

R01 必须先按主计划的代表页完成现有内容的构图，不止更改容器尺寸。逐页留下一张图的区域检查表：设计意图、当前差异、实际修改、保留的用户约定、数据/路由缺口、运行证据。E-01 的现有模块主辅关系提前到本包；E-03 已有身份信息不得继续退化成两列纯文本；E-10 不迁移服务端分页也应先保证身份、状态、角色可扫读，长内容不撑坏布局；B-04 保留满宽对象头/本地导航，正文建立主辅关系。A-01 保留已认可构图，A-03 复验摘要、工具栏和列表的对齐。

这些要求不授权添加缺失聚合、不把成员表换成客户端全量分页、不恢复旧常驻 Inspector。实际接口缺失时，用隔离数据验证构图并标记证据类型；生产不可用态不得冒充空数据，隔离预览不得成为生产 fallback。完整 125% 或权限矩阵没通过就保持待验收。
