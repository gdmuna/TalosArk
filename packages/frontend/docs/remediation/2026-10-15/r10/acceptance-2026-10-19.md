## 缺口和本轮改动

生产入口没有注册旧的 `WorkbenchDataSource`，`Workbench.vue` 又用旧 store 的
`loaded` 条件阻断四个页面。此前只在基线注明缺 reader、等待 P17，没有给它安排
可执行的整改包，这是计划遗漏。本次新增 R10 并实际解除整页阻断。

- `data/source.ts` 增加独立的 `WorkbenchOverviewDataSource`；入口组合已发布的
  材料概览、库存列表和工作区设施列表，不增加后端接口或客户端总快照。
- `model/overview.ts` 拥有三个独立读状态。每次请求捕获组织/工作区，重试、切区、
  session reset 导致工作区清空、销毁时取消旧请求；被取消的迟到成功/失败不发布。
- 概览在挂载时读取，不加入应用启动门槛。不把整个工作台绑定到任一业务的成功。
  未注册来源、加载、真实空态、403 和临时/协议错误分别呈现；错误不显示零值。
- 使用 `material.active`、库存 `total`、设施 `total`。库存数量包含台账全部状态，
  设施是当前工作区可访问且未归档的设施，可能含停用设施，不命名为可用位置。
- 材料/库存行进入已有详情，设施行进入保留工作区授权上下文的存储浏览。
  新建材料由既有页面接管并重新验证能力；工作台不实现重复写入规则。
- 材料适配器补充最近记录的组织/工作区身份检查。原有库存与设施适配器继续负责
  schema、分页与身份校验；验证责任没有下放给卡片组件。
- 没有真实最近访问来源，因此保留“最近更新的材料”名称。工作队列显示明确的
  未接入状态，没有恢复 fixture、假计数或假命令。旧总快照只供显式来源使用。

## 隔离验证

只在新建的临时浏览器标签中拦截非 Document 请求，没有修改生产数据源或数据库。

| 场景 | 结果 |
| --- | --- |
| 材料网络阻断 | 材料显示错误，库存/设施保留各自成功的真实状态 |
| 清除阻断，材料重试 | 仅一条材料概览请求返回 200，没有重读库存或设施 |
| 材料响应 403 | 显示无查看权限，清除原数据和新建入口；其他区域可用 |
| 200 但 payload 不合 schema | 显示数据格式错误，不伪装为空列表 |
| 材料最近记录属于其他工作区 | 适配器拒绝响应，原数据清除，样本名称不出现在页面 |
| 三类非空响应，各一条记录 | 卡片显示服务端 active/total=7/17/8，不把页面长度 1 当总数 |
| 库存记录 | 正确显示材料名、库存编号及字符串数量 `2.5 瓶` |
| 记录入口 | 实际渲染链接分别为材料 ID 详情、库存 ID 详情、`storage-topology?facility=:id` |

真实库存摘要与设施摘要也分别点击验证，进入库存列表和存储浏览，没有权限错误。
概览带尾斜杠的深链仍渲染概览，不会误判为未开放队列。

临时内存探针加载真实 `useWorkbenchOverview`，使用 Vue app injection 和 Pinia，
未留下测试脚本。检查独立成功/403/协议失败、单区重试、组织和工作区同时切换、
来源无视 AbortSignal 的迟到结果、组件 scope 销毁及无来源状态，全部通过。
这些是前端隔离证明，不是后端多租户权限证明。
