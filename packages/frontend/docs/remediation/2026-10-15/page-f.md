# F 组：权限、设施、审计与系统治理

共 15 张稿。当前管理中心的大多数页只是空骨架，不能以“有标题、Table 和禁用按钮”验收。所有配置项必须有真实配置所有权；组织管理员不自动拥有修改全服务基础设施配置的权力。

## F-01 角色与权限

[设计稿](../../../../../output/design/frozen-v2-71-2026-09-29/F-01.png) · `/main/management/role` · [页面](../../../src/page/management/Role.vue) / [现有组件](../../../src/module/workspace/ui/TeamManagement.vue)

- **图中业务**：角色列表/权限矩阵视图，角色/关联成员/作用域等摘要，角色名+说明、作用域、权限组、成员数、更新和操作。
- **当前差异**：主要是角色、作用域、权限字符串和编辑/归档 icon 的原生表，创建弹层是一组未充分分组的复选框；缺对象详情、矩阵与委派上下文。
- **目标布局**：1200px 稳定画布；摘要少量固定宽度；列表为默认，矩阵是另一个明确视图；角色名+说明首列，组织/工作区范围 badge，权限分组摘要，人数与更新时间有来源再显示。主要动作为新建角色，行操作保留保护规则。
- **交互**：点角色到 F-02，成员数到有该角色的成员列表；创建/编辑按真实定义目录分组与搜索，展示用户可读动作名，内部 code 只作可选技术详情。无权动作不是随意可勾选的空格。
- **依赖**：P06 角色/权限目录可接线；角色说明、绑定计数、更新字段与跨角色矩阵查询需核对/补充。前端不得硬编码一套“管理员/研究员”角色顶替真实目录。
- **验收**：protected 角色、不可授予权限、归档在用角色、scope 不可变、委派权限上限和并发更改；列表/矩阵展示同一权限事实。

## F-02 角色详情·权限矩阵

[设计稿](../../../../../output/design/frozen-v2-71-2026-09-29/F-02.png) · `/main/management/role/:roleId?organization=:organizationId&view=permission`，R03 已从初始显式 Mock 接通真实详情读接口，见 [当前验收记录](r03/acceptance-2026-10-18.md)。每个角色固定一个 scope，仅呈现真实权限目录中的适用项；固定表头/首列与局部横滚已落实，不虚构材料动作或角色继承。完整身份矩阵等尚未覆盖边界仍见验收记录。

- **图中业务**：角色对象头（名称、说明、作用域、状态）、权限矩阵、关联成员、继承关系、变更日志。
- **目标布局**：1280px 详情画布；对象头后本地标签；矩阵资源类别为行、动作组为列，固定表头/首列、局部横滚；底部保存/取消不盖滚条。辅助说明只解释当前选中权限，不堆大段教材。
- **矩阵规则**：仅渲染已注册授权定义；某资源不支持某动作显示“不可用”或空占位，不是未勾选复选框；全选/半选以可编辑项为分母。先用现有 organization/workspace 动作验证，不编造未来材料全部操作。
- **交互**：成员 view 只读或按权限进入绑定操作；变更日志进 F-11/F-12；角色定义编辑与在工作区绑定不同。支持检索、组选择、dirty/撤销和服务端拒绝后的状态还原。
- **依赖/延期**：当前没有角色继承业务，不展示生效的虚构继承链；该 view 登记为阶段保留，获批前不开放。成员计数、日志与单角色详情需明确读接口。
- **验收**：查看者、角色管理者、不可委派项、保护角色、大矩阵、小窗口与键盘操作；有效授权不通过 UI 矩阵自行推导覆盖后端结果。

## F-03 资源授权

[设计稿](../../../../../output/design/frozen-v2-71-2026-09-29/F-03.png) · `/main/management/resource-grant` · [源码](../../../src/page/management/ResourceGrant.vue)

- **图中业务**：资源/类型、被授权主体、权限、来源、有效期、状态；筛选、添加授权、选中授权摘要。
- **当前差异**：固定空数组与禁用新建按钮，不是资源授权管理。
- **目标布局**：统一列表画布；资源名+ID 首列，主体（工作区/角色/用户等实际支持类型）和范围清晰，权限摘要可展开，来源/过期/撤销状态可扫读；Sheet 显示来源对象和可操作范围。
- **交互**：新增必须先资源→主体→能力→有效期→预览影响；仅选择本主体可授予的权限，撤销有影响确认。选中资源进入 F-04，选中主体进入对应详情。
- **依赖**：资源层能力尚未随 P06 完成；P07 起逐项接入。UI 不自行支持所有主体/通配符/节点继承规则。
- **验收**：直接/继承/共享来源（仅已支持来源）、即将到期/过期/撤销；筛选不给无权用户泄漏资源名；批量操作需明确后端授权和部分失败规则。

## F-04 单资源授权详情

[设计稿](../../../../../output/design/frozen-v2-71-2026-09-29/F-04.png) · 当前无路由 · 建议 `/main/management/resource-grant/:resourceId?view=authorization`。

- **图中业务**：资源身份头；授权/基本/关联/历史标签；管理工作区、直接授权、继承来源摘要；授权表、继承表、选中项详情。
- **目标布局**：资源身份必须在首屏；主体是分组授权清单，辅助摘要解释谁管理、从哪里获得权限。沿用当前管理主侧栏，不照搬旧稿永久二级侧栏或把管理导航重复成超长 Tab。
- **交互**：授权行可查来源，直接授权可按权限更改；继承结果不是可随手编辑的 checkbox，需进入来源。资源基本详情与授权管理往返保留对象引用。
- **边界**：当前资源/node 继承不是 P06 已交付能力；先展示可证实的直接/范围授权，继承方案待业务落地，不把稿里的“继承”填成固定成功标签。自有资源/可见资源/管理资源分别表达。
- **依赖**：资源身份、授权解释读模型、可授予动作与主体查询、授权写入和审计；缺项逐项跟后端登记。
- **验收**：同权限多个来源、来源不可见、过期/撤销、资源被归档、只有管理元数据权但无内容读权；不误把 UI 显示的权限当最终执行决策。

## F-05 共享策略

[设计稿](../../../../../output/design/frozen-v2-71-2026-09-29/F-05.png) · `/main/management/sharing-policy` · [源码](../../../src/page/management/SharingPolicy.vue)

- **图中业务**：共享范围、各资源类型默认读/操作/申请规则矩阵、默认期限与附加策略；它是组织治理，不是普通用户个人偏好。
- **当前差异**：两块禁用表单，无真实策略；稿中“跨组织共享”本身是已知未批准元素。
- **目标布局**：范围/身份区在上，资源类型×策略矩阵为主，期限与附加项在下；左标签右控件，不把每行变卡片。只使用当前支持的资源类型/能力。
- **交互**：修改有影响范围预览及保存/取消；区分改变默认值与追溯修改已有授权，未经定义不自动撤销全部旧共享。
- **依赖**：策略模型与更新 API 待确认；**不增加跨组织共享、公链、自动审批**。组织内范围也需明确授权语义，不是把单选框打勾即完成。
- **验收**：只读/可编辑、部分资源类型不可配置、默认期限无效、已有共享不受影响/受影响的实际规则都可解释；不能假保存。

## F-07 Facility 详情

[设计稿](../../../../../output/design/frozen-v2-71-2026-09-29/F-07.png) · 当前无路由 · 建议 `/main/management/facility/:facilityId`，具体 view 按获批模型确定。

## F-08 存储设施治理

[设计稿](../../../../../output/design/frozen-v2-71-2026-09-29/F-08.png) · `/main/management/storage-governance` · [源码](../../../src/page/management/StorageGovernance.vue)

- **图中业务**：结构、规则、模板三个视图；结构视图左树、中节点规则、右层级预览；节点类型、允许子类、容量/位置规格、模板版本、管理关系。
- **当前差异**：已有 220px/中间/220px 空框，节点类型和“规则继承”预置但没有后端支持，容易误导为已存在能力。
- **目标布局**：1440px 工具工作区，左树约 240px，中间最少可读表单约 480px，右预览约 280px；窄时收辅助区，不把三个区压扁。structure 选中节点后显示真实父子关系和可编辑字段；rule 按实际规则分组；template 有名称/版本/适用节点/状态/更新时间与详情。
- **交互**：新节点先选择父节点与允许类型，重命名/移动/容量改变预检影响；占用位置不可静默删除。模板套用有预览，不在点击选择模板时直接写库。

- **依赖**：P08；模板/高级治理不是看到截图就自动纳入首发，基础树和位置可先闭环，后续 view 独立登记。
- **验收**：空树、选中父节点失效、循环移动禁止、容量小于占用、无权编辑、并发位置占用；预览与实际将写入结构一致。

## F-09 设备接入

[设计稿](../../../../../output/design/frozen-v2-71-2026-09-29/F-09.png) · `/main/management/device-access` · [源码](../../../src/page/management/DeviceAccess.vue)

- **图中业务**：接入清单作为背景，四步向导“基本信息→连接配置→验证→完成”；显示识别结果与能力。
- **当前差异**：只有空表和禁用新增，无向导与验证状态。

- **图中业务**：时间区间、操作者、动作、资源、工作区、结果筛选；审计列表与选中事件摘要、导出。

## F-13 通知策略

[设计稿](../../../../../output/design/frozen-v2-71-2026-09-29/F-13.png) · `/main/management/notification-policy` · [源码](../../../src/page/management/NotificationPolicy.vue)

- **目标布局**：组织规则矩阵为主，按事件分组，接收人/渠道使用成熟选择控件，批量勾选有明确范围；个人偏好复用同一组件和存储，不重复两套状态。
- **交互**：组织强制规则与个人可选偏好清楚区分；渠道不可用给具体受限原因；保存只改变策略，不显示“邮件发送成功”。
- **依赖**：P16 事件目录、接收主体、渠道能力和配置模型；Mail 探针错误允许服务启动，不意味着邮件渠道健康或消息送达。
- **验收**：无邮件渠道、强制项、只读、接收角色被归档、未知事件类型；关闭某个人渠道不绕过组织安全通知要求（是否强制须业务定义）。
