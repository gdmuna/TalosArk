# E 组：组织、工作区与成员

共 11 张稿，是优先整改区域。当前 P04/P06 已有真实组织创建、成员、邀请和角色能力，不能继续按“管理骨架”交付标准验收。另一方面，完整详情字段尚未全部有接口，必须逐项承认缺口。

## 先确定对象层级，不再让列表代替详情

以下为**拟新增**的路由方案，当前并不存在：

| 设计 | 建议地址 | 对象上下文 |
| --- | --- | --- |
| E-04 | `/main/management/workspace/:workspaceId?view=overview` | 明确 workspaceId，展示组织，不隐式切换当前工作区 |
| E-05 | 同上 `view=member` | 当前查看的工作区成员，不是全组织成员 |
| E-06 | 同上 `view=role` | 本工作区角色与成员绑定，区分组织级角色定义所有权 |
| E-07 | 同上 `view=resource` | 工作区资源及关系，不等于可见的所有资源 |
| E-08 | 同上 `view=sharing` | 发出/收到的组织内共享，分别说明权限来源 |
| E-09 | 同上 `view=setting` | 该工作区设置，不是组织或个人设置 |
| E-11 | `/main/management/member/:memberId?organization=:organizationId&view=overview` | 组织成员身份；memberId 的契约含义须确认，不能拿 User ID 冒充 membership ID |

页面内部可以分组为 `page/management/workspace/`、`member/`，模型仍归 `module/workspace/` 或对应领域模块。先做清楚的对象路由与复用数据能力，不做万能详情框架。

## E-01 管理中心概览

[设计稿](../../../../../output/design/frozen-v2-71-2026-09-29/E-01.png) · `/main/management/overview` · [源码](../../../src/page/management/Overview.vue)

- **图中具体业务**：组织/工作区/成员/待邀请/风险摘要；工作区概览清单；成员与邀请分布；近期审计；待处理授权；集成健康。重点是管理员能知道哪里需要处理，而不是只展示资产数字。
- **当前差异**：四项均分卡片里若干值为 `—`，只有狭窄工作区表，其余为占位块；没有建立主辅层级，也没有完整管理动作链。
- **目标布局**：1200px 画布；顶部摘要按固定宽度自然排列，不为了凑五张塞满。主体左约 2/3 工作区清单+近期审计，右约 1/3 待邀请/待处理授权与集成状态；没有实际待处理业务时减少模块，不摆空卡片墙。
- **内容要求**：每个统计注明当前组织范围；成员数是有效组织成员，邀请单独计数；工作区只显示可查看项，不从列表页当前页条数算总量。审计显示动作/人/对象/时间/结果与详情入口。
- **交互**：摘要进带筛选的 E-03/E-10/F-11；工作区名进 E-04；集成健康进 F-14 对应项目。无权限模块不泄漏总数。
- **依赖**：组织/工作区列表可接线；成员/邀请总量须专用聚合口径；审计查询、待授权、集成健康目前不能因已有底层模块就判为存在。
- **验收**：组织切换时所有摘要与清单统一；一个工作区时布局不塌缩；没有邀请和邀请未加载不同；禁止把空计数当风险为零。

## E-02 组织设置

[设计稿](../../../../../output/design/frozen-v2-71-2026-09-29/E-02.png) · `/main/management/organization-setting` · [源码](../../../src/page/management/OrganizationSetting.vue)

- **图中具体业务**：组织身份头（logo/名称/ID/状态）、基本资料、组织加入规则、保存/取消，以及独立的危险生命周期区域。
- **当前差异**：大多为空/禁用字段，表单没有真实组织详情来源；加入规则和注销功能也未获得当前契约支持。
- **目标布局**：身份头与表单同一画布；基本区左 logo/名称，右侧标签对齐字段；单字段表单约 720px，组织事实/说明可作右辅栏；危险区域底部独立，禁止普通保存与删除同权重并排。
- **字段要求**：名称、说明、标识、创建信息按可用契约读；不可编辑 ID 用可复制事实，不用灰掉的 Input 伪装可编辑表单。Logo 无真实资产时显示组织首字图标。
- **交互**：编辑→dirty→取消还原→保存→读取同步失败，整套状态需完成；组织创建规则和当前仅邀请开户保持一致，不开启自助申请/全员加入。
- **依赖**：当前创建/列表不能替代组织详情与更新 API；组织归档/注销、所有权转移未批准，不启用危险按钮。若延期，明确列入后端需求，不假装保存成功。
- **验收**：非组织所有者只读/无权口径一致；切组织不带上旧草稿；刷新深链、名称过长、提交错误定位可用。

## E-03 工作区列表

[设计稿](../../../../../output/design/frozen-v2-71-2026-09-29/E-03.png) · `/main/management/workspace` · [源码](../../../src/page/management/Workspace.vue)

- **图中具体业务**：工作区名称与说明/图标、所属组织、负责人、成员数、资源数、状态、最近更新时间；新建、搜索筛选、排序、行更多与详情入口。
- **当前差异**：只用 220px 名称+180px 组织列，完全没有对象详情入口；页面 `w-fit` 跟着约 402px 表收缩，标题/搜索/分页失去布局。当前行还混合多个可访问组织，必须显式说明范围。
- **目标布局**：稳定 1200px 列表画布；标题行左侧组织/范围上下文，右侧“新建工作区”；新建组织保留在切换器/清晰的次要菜单，不与本页主动作竞争。工具栏和表格起止线统一。
- **表格方案**：名称+一句说明约 260-300px，组织约 160px，负责人约 140px，成员/资源数约各 100px，状态约 100px，更新约 170px，固定操作区。是初始建议，最终按真实内容校准；超宽走原生横滚，不为了所有列在 1024px 塞下而缩字。
- **范围方案**：默认当前管理组织；如保留“我可访问的所有组织”，必须有明确范围选择并始终显示组织列。切范围更新授权/查询，不能用某组织标题展示所有组织行。此为呈现方案，接口能否按组织取全量需核对。
- **行交互**：名称/整首业务 cell 打开预览 Sheet，明确“查看工作区详情”；行主动作进 E-04；“进入工作区”是单独动作，成功后才切换全局工作区。行菜单按权限显示管理入口，不把只读成员带进假设置表单。
- **现成/缺口**：名称、ID、organizationId、说明和创建能力已有来源；负责人、人数、资源统计、状态/更新时间不全部在当前列表契约内，须增加真实读字段或暂不显示相应列，绝不能从当前可见成员/资源数组猜总数。只完成现有字段布局属于第一阶段，不能标为 E-03 完整完成。
- **验收**：1 条/0 条/跨组织/长名/隐藏多列/100 条都保持页面稳定；创建成功读取失败只重试同步；分页最多有意两行，不能随机拆成四行；可直达 E-04 并刷新。

## E-04 工作区详情·概览

[设计稿](../../../../../output/design/frozen-v2-71-2026-09-29/E-04.png) · 当前缺失 · 采用本分册开头拟定的 workspace 对象路由。

**稿件列出的业务不是一张工作区表，而是以下完整结构：**

| 区域 | 应呈现的具体内容 | 整改要点 |
| --- | --- | --- |
| 对象头 | 图标、名称、状态、ID、所属组织、编辑/成员/更多 | 第一屏明确在管理哪个工作区，不用全局 activeId 偷换对象 |
| 本地导航 | 概览、成员、角色、资源、共享、设置六视图 | URL 可恢复；标题和标签不被放进一张装饰卡片 |
| 基本信息 | 名称、ID、组织、负责人、创建时间、说明 | 可复制 ID；长说明换行，未知负责人不自动填创建者 |
| 资源统计 | 材料、库存、设备等受支持资源分类与数量 | 只按真实资源目录与权限聚合，稿中示例“样本”不自动变成首发类型 |
| 成员概况 | 有效成员人数、头像摘要、角色/管理员入口 | 头像可真实首字 fallback；人数和分页列表不是同一口径 |
| 最近活动 | 时间、操作者、动作、对象/结果 | 来自审计/业务事件读模型；跳转对象详情 |
| 使用趋势 | 明确指标/单位/窗口的时间序列 | 有数据再画，不放随机线；延期时登记缺口，不以静态图凑完 |

- **目标布局**：1280px 详情画布；上排基本信息、资源统计、成员概况约 1:1:1.2，给成员头像矩阵足够宽度；窄时基本信息整行，其余顺序后置。下排最近活动与趋势约 3:2，保留稿中的并列关系。该分区是信息比例，不强制每块外套卡片。
- **交互**：成员入口到 E-05；统计到 E-07 对应类别；编辑到 E-09；进入该工作区明确切换操作。breadcrumb 可回组织工作区列表，返回保留范围。
- **依赖**：需要 workspace 详情、成员/资源摘要、活动和趋势查询；当前 P04 列表不足。前端可先建路由与已支持成员视图，但完整 E-04 必须等相应契约；不让另一个 agent 猜数据。
- **验收**：组织 A 当前激活区与详情 B 不同仍不串数据；无进入权限但有管理读权按真实模型处理；不存在/不可读不回落到当前工作区。至少提交全页、成员入口、窄宽度三张截图。

## E-05 工作区详情·成员

[设计稿](../../../../../output/design/frozen-v2-71-2026-09-29/E-05.png) · 当前仅 TeamManagement 能按范围管理成员，没有完整工作区详情承载。

- **图中具体业务**：当前成员表（头像/姓名/邮箱、角色、加入信息、操作）；待处理邀请单独区域（邮箱、邀请者、有效期/状态、重发/取消）；顶部邀请/添加与搜索。
- **目标布局**：沿 E-04 对象头与六标签；成员清单为主，邀请不是挤在每个成员行里的状态。可采用“成员 / 待邀请”局部切换，分开计数；正常空邀请区不占半页高度。
- **表格/Sheet**：成员首列头像+姓名/邮箱两层，角色 badge 成组但有截断展开，状态单独列；选中 Sheet 呈本区角色与成员身份，可进入 E-11，不展示无关组织私密数据。
- **复用方式**：复用 `module/workspace` 的团队查询/命令；将 TeamManagement 的范围选择从详情内容中移除或锁定为 path 对象，不再在工作区详情里让用户不知不觉改到另一区。
- **权限底线**：组织所有者可组织邀请；工作区管理员只添加已有组织成员并分配本区已有角色，不能以“邀请”偷偷给平台开户。默认基线角色与可委派权限使用后端返回，不能让任意管理员勾选所有角色。所有者不可移除/离开。
- **依赖**：P06 查询与命令接线；头像、加入时间、邀请者等若当前字段未公开则列读模型缺口。组织邀请和工作区成员添加虽共用弹层外观，必须用不同文案/命令。
- **验收**：只有读权限、管理员不能授予未持有权限、跨区成员、过期/撤销邀请、移除后无访问权限；重发旧链接失效，邮件“已提交”不写“已送达”。

## E-06 工作区详情·角色

[设计稿](../../../../../output/design/frozen-v2-71-2026-09-29/E-06.png) · 当前无独立对象 view；TeamManagement 有角色列表能力。

- **图中具体业务**：角色名称/说明、成员数量、权限组、操作；分配角色、进入权限矩阵。
- **目标布局**：六标签下给本区角色一张紧凑列表，列清楚“角色定义作用域”和“在本区绑定人数”；权限摘要用领域名+动作数量，不能一长串内部英文 code 占满单元格。
- **交互**：点角色到 F-02；分配进入成员绑定选择，展示可委派角色及原因；查看成员按该角色过滤 E-05。
- **权限**：工作区管理员可以绑定组织已定义的工作区角色，但不自动获得组织角色定义编辑权；按钮“编辑定义”和“分配到成员”必须区分。组织角色不能当工作区角色绑定。
- **依赖**：P06 可接真实角色/授权目录；人数、说明、最近更新时间若无字段需补读模型。资源/node 动作尚未贡献时不能显示假“材料管理员全权限”。
- **验收**：保护角色、归档角色、不可授予角色、零绑定角色；角色编辑生效后成员有效权限随真实策略更新，不依赖前端刷新假权限。

## E-08 工作区详情·共享

[设计稿](../../../../../output/design/frozen-v2-71-2026-09-29/E-08.png) · 当前无路由/真实清单。

- **图中具体业务**：向其他工作区共享与从其他工作区接收，资源/目标或来源/权限/到期/状态/操作分组。
- **目标布局**：发出/收到两个明晰视图；表列资源、对象工作区、能力摘要、授权来源、有效期、状态；顶部解释仅用必要的当前组织范围标识，不放大段功能说明。
- **交互**：发出共享可撤销/变更（按权限），收到共享可查看来源/申请变更；不能让接收方“撤销源授权”。批量撤销需后端能力与明确确认。
- **权限边界**：当前组织内共享，不增加跨组织共享、匿名链接或自动批准。共享过期与资源归档分别表达。
- **依赖**：资源授权业务待对应 P07/后续切片，不是 P06 成员角色闭环已完成的部分。
- **验收**：即将过期/已过期/被撤销/来源不可见，动作原因清楚；只读人员不会泄漏其他工作区成员或权限详情。

## E-09 工作区详情·设置

[设计稿](../../../../../output/design/frozen-v2-71-2026-09-29/E-09.png) · 当前无路由/更新表单。

- **图中具体业务**：名称、ID、说明、可见/加入策略；辅助使用配额信息；独立转移/归档等危险区域。
- **目标布局**：身份可复制事实与编辑字段分开；左侧基本表单、右侧只读状态/使用事实，底部保存/取消；危险区域与日常表单不共一个主按钮组。

## E-10 组织成员列表

[设计稿](../../../../../output/design/frozen-v2-71-2026-09-29/E-10.png) · `/main/management/member` · [包装页](../../../src/page/management/Member.vue) · [现有呈现](../../../src/module/workspace/ui/TeamManagement.vue)

- **图中具体业务**：成员头像/姓名/邮箱、组织角色、工作区关系、状态、加入时间、邀请与操作；可查看成员摘要。
- **当前差异**：大组件用原生 Table 展示姓名/邮箱/角色/状态，组织与工作区通过范围选择混合；缺成员详情、关系信息、统一 DataTable 工具与成熟分页布局。
- **目标布局**：稳定组织上下文；成员/邀请分开，工具栏统一；首列双层身份+头像，角色/工作区可折叠 badge，状态独立，时间正常前景，操作主次明确；列表可进 E-11。
- **交互**：邀请 G-11、添加已有组织成员到某工作区、分配角色、移除、离开分别按 P06 实际命令。需确认对象/影响范围，不能把“移出此区”写成“删除用户”。
- **数据要求**：保留服务端搜索/分页；切 org 重置页码/选择。加入时间、所属工作区摘要不在当前查询中就补读模型，不能对每行 N+1 拉全量或把当前活动区当成员所有工作区。
- **依赖**：P06 即修/接线；独立详情与有效权限需要补读接口。保护规则在后端，UI 提示只是解释。
- **验收**：组织所有者不能移除/离开，普通管理员不可越权；邀请失败、已接受、过期重发、账号与邮箱不匹配；成员被移除后页面正确回收访问，不假登出整个账户。

## E-11 成员详情

[设计稿](../../../../../output/design/frozen-v2-71-2026-09-29/E-11.png) · 当前无详情路由。

- **图中具体业务**：身份头（姓名/头像/邮箱/状态/组织/加入信息）；概览、组织身份、工作区关系、活动、有效授权；身份事实、工作区成员表、近期活动和权限来源。
- **目标布局**：对象头与本地标签在上；概览左身份与关系，右有效权限摘要；工作区关系 view 提供区名/角色/状态/加入信息；活动为成员在当前组织内可公开的审计，而非平台个人日志。
- **交互**：分配组织角色与分配工作区角色两个明确范围；进工作区详情不静默切当前区；有效权限可展示来源，但不可直接编辑最终计算值。
- **权限/模型**：组织成员 ID 不等于 User ID；组织中停用/离开不等于禁用平台账户；跨组织成员关系不能串读；当前 P06 禁止所有者移除/离开继续遵守。
- **依赖**：成员详情、工作区关系、有效授权解释、成员活动读模型；不要从多个当前页数组拼接成“完整权限”。
- **验收**：同用户在两组织有不同角色；成员离开后历史仍有稳定身份；不存在/不可见、被移除后的深链、字段局部不可读均不泄漏数据。
