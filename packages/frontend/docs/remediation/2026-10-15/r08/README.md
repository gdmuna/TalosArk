## R08-A 实施

起点 `0c338981`，开工工作树干净。仅修改前端及本包记录；沿用现有 Auth API、Cookie 协调、公开 schema 和 Field 组件。

| 场景         | 实施结果                                                                                                                                      |
| ------------ | --------------------------------------------------------------------------------------------------------------------------------------------- |
| 认证页面     | 复用 module/auth 的 AuthPage，统一身份标识、标题、448px 表单宽度及间距。认证外壳独立纵滚，390px/320px 和短窗口可访问底部动作，标题栏保留      |
| 密码输入     | 登录补显隐按钮；激活、首设与重设共用 PasswordForm，校验错误关联具体字段并聚焦首个错误，保留自动填充与字符规则                                 |
| 原页面返回   | 密码登录、找回后返回登录均保留合法 next 的 path/query/hash；外站、反斜线、数组和非允许的认证路径回落 /main                                    |
| SSO          | 在当前标签的 sessionStorage 保存 state 与返回路径，回调匹配后一次消费；code/state 先从 URL 清除。回调失败有返回登录入口，响应校验错误保持静默 |
| 首次设密     | 显示已加载的当前账户邮箱；服务端返回已有密码或需重新认证时卸载表单，提供对应恢复入口。具体错误码优先于通用 403 文案                           |
| 激活/重设    | token 清除 URL 后才开放提交，只保留页面内存；完成或凭据失效移除表单，刷新不重放，策略拒绝保留草稿                                             |
| 邀请         | 显示组织、工作区、邮箱及有效期；恢复/预览失败可重试；保持服务端统一的失效或账户不匹配口径，提供切换账户                                       |
| 接受后的同步 | 接受成功进入完成态并清除待处理意图；同步失败复用 DataSyncNotice，只重读工作区列表，不重发 accept；取消/过时代次不能写回新页面                 |
| 启动恢复     | 服务不可用停留原受保护 URL，复用 ApplicationStartup；重试从失败读取阶段继续。新增显式返回登录，保留目的地，不因网络失败自动退出               |
| 空目录       | 区分尚未加入组织与暂无可用工作区；已有组织可查看工作区，有创建能力才开放对应创建动作；账户设置始终可达                                        |
| 退出         | 立即清除本地身份并 replace 到登录；保留服务器撤销反馈及自动恢复阻断机制，断网不循环重试                                                       |

未增加认证方式、资格预检接口或后端权限。邮箱/手机/微信/Google 的既有禁用预告入口保留。

## 验收与边界

详见 [验收记录](acceptance-2026-10-23.md)。隔离响应仅在测试浏览器替换，没有注册生产 Mock，没有向真实组织写入数据。

首次设密尚无预先资格读取字段，因此由既有提交契约返回后进入结果态，不据账户资料推断。邀请 token 继续只在 SPA 内存传递；刷新或外部 SSO 后需重开邀请邮件，未将其持久化。

真实 Casdoor 回跳、邮件送达与一次性凭据撤销、真实权限矩阵、跨标签会话竞争、Tauri 和系统 125% 缩放仍待验。R08-C 的当前结果见下文；不能把隔离 Web 验收等同于整个 R08 真实端到端验收完成。
