## 实现边界

- 页面组合库存 reader 与 Inspector；库存仍拥有查询与授权，材料 module 不依赖设施或发明新的库存快照。
- 附件 DataSource 的 sign 接收可选 partNumber，底层 `platform/file-transfer` 只传签名 PUT 和读取 ETag，不携带应用凭据。
- 上传模式是用户显式选择，不定义未讨论的自动分片阈值。零字节继续 single；单文件上限仍为已确认的 100 MiB。
- 恢复只覆盖同标签页会话；不保存文件二进制、签名 URL 或 token。写入确认后的列表失败只重新加载，不再次上传/绑定。
- 存储必须向浏览器暴露 ETag；部署 CORS/HTTPS/签名可达性仍需真实环境验收。

## 验收

静态实施已完成：前端 `type-check`、6 个改动源码的 ESLint、Prettier、`git diff --check` 与生产构建均通过；Vite 仍提示现有约 1.53 MB 主 chunk 超 500 kB。没有新增长期测试脚本。

重审补充：已用无登录凭据的独立 Edge 浏览器上下文加载真实源码，完成 18 个隔离场景。材料附件的原生 XHR 在浏览器中实际执行，但业务数据源与存储响应均为临时替换，不接触真实组织或真实对象存储。批次库存记录通过公开 Stock/StockPage schema 校验。临时脚本、结果和截图位于忽略的 `output/r06-re-audit/`，没有加入长期测试套件。缺少 ETag 的失败用例已覆盖，但这不等于实际部署的 CORS 验收。

后续 S3 专项已补真实本机存储验证：Edge 从实际应用源执行签名 PUT/下载、ETag/CORS；后端真实两片上传、整文件 SHA-256、合并响应丢失后的 finalizing 恢复及校验失败拒绝发布均通过。后端仓储使用内存替身，没有向真实组织写入附件。运维初始化与错误映射另见 [R06 重审补记](audit-2026-10-21.md#s3-专项修复补记)。

后续 [P10 补充验收，2026-10-22](../../../../../../docs/product/mvp-p10-acceptance-2026-10-22.md) 已使用非超级管理员合成账户、真实登录、测试数据库及独立 RustFS，完成 12 组 Web、6 组 HTTP 和对象字节核对，关闭此前完整本地分片 UI/绑定/下载/解绑/撤权缺口。原 R06/S3 隔离证据的性质不变，不能把本次台账校准算成重新验收。
