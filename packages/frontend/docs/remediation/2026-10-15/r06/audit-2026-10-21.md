## 规范审查

| 发现 | 判断 | 处理 |
| --- | --- | --- |
| 单次与分片上传复制 XHR 生命周期 | 重复实现，后续修复容易只更新一侧 | 共用私有 `uploadPut`，分别提供单次完成和 ETag 读取；完成/取消/超时共用一次性收尾 |
| 持久化 `Job.parts`，恢复时却从未使用 | 没有承担职责的重复状态 | 删除本地分片镜像，恢复只使用服务端当前清单；继续保存原请求、会话和绑定回执 |
| 分片 ETag 检查重复，依赖错误文案识别错误 | 不必要的扫描与文案耦合 | 清单校验后检查目标 ETag 一次；传输错误直接按文件/分片生成，不再捕获并匹配错误字符串 |
| 普通 Batch 与 `MaterialInventoryPanel` 有部分列和操作装配重复 | 低优先级维护风险，暂不属于必须抽象的缺陷 | 保留：两者的列、批次上下文、入库动作与页面布局不同。本轮不建立通用表格业务框架 |

## 需求与正确性审查

| 级别 | 原问题与影响 | 修复 |
| --- | --- | --- |
| P1 | 新增分片读取后，取消保护不完整；账户变化期间的迟到响应可能再次写入旧任务状态 | 分片 PUT、进度读取和完成返回后检查取消；上传进度同时检查请求身份和取消状态 |
| P2 | 恢复非连续分片时按分片编号累计，进度倒退；最后小分片的权重也不正确 | 使用已确认字节数加当前分片上传字节数；全片确认后设置 100% |
| P2 | 未校验服务端分片清单，重复、越界或大小不符的记录会进入完成请求 | 按服务端计划验证编号、重复项和每片实际字节数；不一致时停止完成并保留原会话 |
| P2 | 批次库存普通网络失败仍保留旧记录，但总数曾清零；修正后又遗漏权限错误清空记录却保留总数 | 普通失败保留记录和总数并显示旧数据提示；读取结束且记录已清空时，总数同时清零。本轮浏览器先复现“无记录但共 1 项”，修复后验证归零 |
| P3 | 文档把普通来源 Batch 与 Cell Bank 专业 Batch 的路径混用，并保留未标明历史的 single-only 描述 | B-11 指向 `BankBatch.vue`；P10 原说明标记为历史基线，Frontend Context 更新为当前实现 |

## 隔离验证

使用现有本地 Vite 服务与独立 headless Edge 上下文，通过 Playwright 加载真实 store、原生 XHR、附件界面、Batch 界面、DataTable 与 Inspector。替换的业务数据源和存储响应不访问真实组织或对象存储；库存记录与分页结果通过公开 `StockSchema` / `StockPageSchema` 校验。存储请求检查未携带 Authorization 或 Cookie。

18 个场景通过，浏览器 `pageerror` 为 0：

1. multipart 按服务端计划执行四次 PUT，字节数为 4/4/4/2，返回 ETag 进入完成清单。
2. 重建 Pinia owner，从同标签页 sessionStorage 恢复第 3、4 片已确认的上传，只补第 1、2 片，进度不倒退并达到 100%。
3. 重复分片在 PUT/complete 前被拒绝。
4. 末片大小错误在 PUT/complete 前被拒绝。
5. 分片编号越界在 PUT/complete 前被拒绝。
6. finalizing 恢复使用原 completionParts，无须原文件，不新建会话或重传分片。
7. 完成响应丢失后重建 owner，恢复原 finalizing 会话并完成绑定，不重复 PUT。
8. 账户切换后旧进度读取才返回，不重新填充 jobs、错误或忙碌状态。
9. 存储未暴露 ETag 时保留任务，停止完成和绑定。
10. 原 single 流程仍执行一次完整 PUT 并完成绑定。
11. 普通 Batch 显示服务端总数，查询带 materialId/batchId。
12. 切换页码发送服务端页码；搜索重置到第一页并传递搜索条件。
13. 首 cell 打开真实 Inspector，更多菜单包含详情与预览。
14. 同范围网络刷新失败保留旧记录和总数，并显示明确提示。
15. 403 后清空记录与总数，不显示旧记录。
16. 附件界面默认 single，可以显式选择 multipart。
17. 在附件界面选择 multipart 并上传，进入原上传 owner，按计划分片后绑定及同步列表。
18. HTTP 附件适配器的 single/multipart 签名请求分别发送 `{}` / `{ partNumber }`，保留传入的 AbortSignal。

临时运行材料位于忽略目录 `output/r06-re-audit/`：`verify.cjs`、`results.json`、`batch-loaded.png`、`batch.png`、`attachment.png`。这些是可丢弃的本地验收产物，不是长期维护的测试套件。

## S3 专项修复补记

2026-10-21，用户另行授权修复实际存储故障。此节是上述前端重审之后的后端/契约/开发配置补充，不改变原隔离验收的证据边界。

- 只读查询确认：旧会话保存的 `talos-ark-staging` 不存在，而当前本机使用 `talos-ark-dev`；环境变量变更不会回写旧会话。基础开发配置另有不可达地址及不匹配凭证，现与本机开发配置统一；公开地址改为对象 API 端口且不重复包含桶名。生产/测试配置未在本专项修改。
- 当前桶补齐实际应用源的 CORS，允许 PUT/GET/HEAD、声明类型/校验头并暴露 ETag。新增显式 `storage:check` / `storage:init` 运维入口；不在服务启动时创建桶，不修改公共访问策略或旧会话。
- progress 不再隐式创建分片上传。前端取消直接调用取消接口，不先读取依赖存储的进度；服务端仍决定能否取消。存储缺桶独立记录，File 到 Material 的错误链输出安全的 HTTP 503，前端提供配置检查与取消重选提示，不再误报通用 500。
- 实际验证：Edge 在真实应用源下的签名 single/multipart PUT、ETag、私有复制/签名下载、abort 通过；原空白浏览器会话的登录 401 与存储检查分开记录。后端真实存储另验证 5,243,017 字节两片上传、完整 SHA-256、合并响应丢失后的 finalizing 恢复，以及错误哈希阻止发布；仓储为内存替身。
- 运维 CLI 的缺桶检测、显式创建、CORS 合并与旧来源保留、重复执行、非法来源拒绝、错误凭证不建桶通过；错误映射与无初始化查询等 11 项隔离回归、前端取消 4 项场景通过。临时资源均清理，材料/组织/会话数据库未写入。脚本和检查记录位于忽略的 `output/storage-diagnosis/`。

上述结果不等于真实登录下的完整附件 UI、绑定/撤权及部署 HTTPS 验收。旧失败任务需由用户取消后重选文件，本专项不静默迁移或取消它们。修改环境后须完整重启 dotenvx/watch 启动进程，不能只等待源码热更新。
