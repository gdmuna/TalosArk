## 已确认解决

1. `main.ts` 注入 `createHttpManagementDataSource`，普通工作区、成员、角色详情通过共享响应契约读取真实 HTTP；正常路由没有回退 Mock。
2. 工作区成员携带规范的 `organizationMemberId`；从工作区成员行进入独立成员详情时，路由使用该身份，不再混用 `WorkspaceMember` / `User` ID。
3. 工作区内成员、邀请及角色操作连接 P06 真实 source；工作区资料和角色编辑携带 `expectedUpdatedAt`。
4. 后端在组织/工作区授权之后查询、计数和分页；写入使用事务、权限复核、修订条件和同事务审计。静态复核未发现可确认的租户隔离或事务错误。
5. 设施、库存、设备继续显示未接入；活动响应使用净化投影，未把原始审计 details 返回前端。

## Standards

### S1 [P2] 活动分页权限失效后仍显示旧内容

位置：`src/page/management/detail/read.ts:122-132`，配合 `ActivityList.vue:21`。

`useDetailRead` 在 401/403/404 时清空 `data`，但 `useDetailActivity` 另有累计 `items` 和 `nextCursor`。其监听器对 `undefined` 直接返回，活动表又始终渲染累计行。已加载活动后，下一页因权限撤销返回 403，页面仍保留旧活动与旧游标。

这违反真实接入设计的“401/403/404 清理旧对象”和旧上下文失效要求。明确的授权失效应清空累计行及游标；暂时性网络失败则可以保留已加载页。

一次性内存探针转译实际 `read.ts`，使用 Vue effectScope 与可控 source，没有创建文件：

```text
首批成功：items=1, nextCursor=next-page, error=''
下一页 HttpError(403)：data=undefined, items=1, nextCursor=next-page, error=forbidden
预期：拒绝后 items=0, nextCursor=null
```

没有另列推测性代码气味。此探针验证的是前端错误清理，不代表真实环境权限撤销矩阵已经验收。

## Spec

### P1 [P2] 活动权限清理不满足交付承诺

独立需求复核也发现 S1。对应[真实接入设计](../../../../../backend/docs/design/mvp-r03-management-detail-2026-10-18.md)中的“401/403/404 清理旧对象”。主对象不必同时刷新，因此不能依赖父页面重算 activityKey 才清理旧活动。

### P2 [P2] 从详情返回会丢失列表范围和查询

位置：`src/module/workspace/ui/TeamManagement.vue:45-71`、`:231-245`；返回入口见 `src/page/management/detail/DetailPage.vue:38`。

详情跳转将组织与工作区传给目标 URL，但来源列表的组织、工作区、搜索等仍保存在组件局部状态中。列表重新挂载后重新初始化范围并执行 `team.select`，恢复不到进入详情前的列表上下文。`lastLocation` 不能恢复从未存入 URL 或可恢复状态的值。

对应 R03 的“列表面包屑仍回列表上下文”、E 组的返回保留范围要求。真实浏览器复现：

```text
/main/management/member
成员范围：组织 -> 选定工作区；搜索：admin -> 搜索
点击真实成员“详情” -> 点击左上角“成员”快速返回
实际：范围恢复为“组织”，搜索变空；来源 URL 始终没有查询条件
预期：恢复原工作区范围及已应用的搜索/分页上下文
```

成员路径已实际复现；角色页复用同一组件，其范围、筛选与视图也应一并复核。跨组织返回问题来自相同局部状态初始化，但本轮没有用两个真实组织复现。

## 修复复验

同日按用户授权修复上述两项问题：

- S1 / P1：详情读取保留结构化读取错误。活动分页在明确的 401/403/404 后清空累计行及当前/下一页游标；普通分页不清空已有页，网络或 5xx 失败保留已有结果。请求代次检查继续阻止旧对象的迟到结果或错误影响新对象；失权清理本身不自动重试。
- P2：成员、角色列表的路由页解析并保存组织、工作区、已提交搜索、分页容量/页码、成员/邀请页签及角色筛选/视图。普通条件更新采用 replace，保留其他 query 与 hash。TeamManagement 接收受控条件，恢复值在首次查询之前传入 store；搜索草稿和弹层仍为局部状态。工作区详情内嵌团队视图继续使用固定对象范围。
