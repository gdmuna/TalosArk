# R03 对象上下文

日期：2026-10-17。状态：**Mock 对象上下文已实施，真实接口与权限验收未完成**。本轮用户决定：根据现有 Prisma schema 推导前端读模型，数据使用 Mock；不补后端接口。这是对原 R03“先补读接口”顺序的明确调整，不改变后续真实接入要求。

模拟详情具有独立入口与明确标识，固定模拟 ID 相互关联。真实列表、真实数据源、认证及全局工作区不改接 Mock；真实记录不会被静默替换为模拟对象。更改仅保留在当前应用实例内，刷新重置。

## Schema 约束

- Workspace：名称、说明、组织、创建/更新时间、归档时间；没有负责人、配额、加入策略或所有者字段。
- OrganizationMember 与 WorkspaceMember 分别使用自己的 ID；User ID 只作为账户引用。成员离开后保留历史身份，不删除账户。
- Role 是组织持有的定义，scope 区分组织/工作区；WorkspaceRoleBinding 连接到工作区成员。没有角色说明或继承模型。
- 设施由组织持有、工作区管理；FacilityWorkspaceAccess 只有设施/工作区/级别/创建时间，没有通用资源共享、到期时间或跨组织共享。
- 资源统计是模拟完整读模型的投影，不把列表当前页条数当总量；审计仅模拟当前组织的已净化业务事实。图表只汇总资源 `createdAt`，不是使用量、使用率或库存趋势；成员最终有效权限不由前端猜测。

## 入口与实现边界

真实工作区、成员、角色列表各有单独的“模拟详情”入口，**不把真实行的 ID 转换成模拟 ID**。独立深链如下，均保留应用原有认证与启动边界：

| 对象   | 地址                                                                                                             | 默认视图 / 其他视图                                    |
| ------ | ---------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------ |
| 工作区 | `/main/management/workspace/019a0000-0000-7000-8000-000000000011`                                                | 概览；`view=member/role/resource/sharing/setting`      |
| 成员   | `/main/management/member/019a0000-0000-7000-8000-000000000102?organization=019a0000-0000-7000-8000-000000000001` | 概览；`view=identity/workspace/activity/authorization` |
| 角色   | `/main/management/role/019a0000-0000-7000-8000-000000000033?organization=019a0000-0000-7000-8000-000000000001`   | 权限矩阵；`view=member/activity`                       |

- `module/workspace/data/detail/` 管理模拟完整数据、查询投影与内存命令；`model/management-detail.ts` 是前端读模型，不是发布的 HTTP 契约。
- `module/workspace/prototype.ts` 是单独的显式原型入口，仅管理详情的私有组合层可以选择。正常 `index.ts`、`main.ts`、bootstrap 和真实数据源不导入它。
- 原有 TeamManagement 状态逻辑提取为工厂；真实 Pinia store 仍用相同实现，详情页创建自己的局部状态并连接模拟 source。成员/邀请/角色操作不复制整页，不改变真实写入与同步失败语义。
- `page/management/detail/` 只共享这三个页面的对象头、面包屑选择器、事实列表、活动表及草稿确认，不是通用对象详情平台。
- 对象头和本地导航占满内容区宽度，正文独立滚动并居中，正文最大净宽 1280px。详情不读取全局 activeId 代替路由对象 ID，不切换全局工作区。
- 选择器切换同类对象保留进入来源；跨对象链接更新来源；快速返回恢复来源的完整 URL。列表面包屑仍回列表上下文，而非冒充快速返回。
- 无效对象或错误组织参数显示不可用并清除旧对象。编辑支持保存、取消、离开确认；放弃会真正还原草稿。模拟邀请不发送邮件，不展示可用邀请链接。

## 后端交接清单

下表是需确认的读能力，不预先发明 endpoint、分页格式或最终授权规则。列表现有契约不应被偷偷扩大为完整详情。

| 读模型          | 当前 Prisma / 既有能力依据                                | 真实接入前需补齐或确认                                                               |
| --------------- | --------------------------------------------------------- | ------------------------------------------------------------------------------------ |
| 工作区对象      | Workspace 与 Organization                                 | 独立 ID 查询、可读字段、归档/无权/不存在口径、更新资料命令及可编辑能力               |
| 工作区摘要      | WorkspaceMember、WorkspaceRoleBinding、Resource、Facility | 有效成员/资源/本区绑定总数的统计权限和口径，不能用分页项数替代                       |
| 工作区成员/角色 | P06 TeamDataSource + 组织持有 Role                        | 固定组织/工作区上下文、角色定义与本区绑定区分、工作区成员到组织成员 ID 的稳定映射    |
| 成员详情        | OrganizationMember、User、WorkspaceMember、角色绑定       | 当前调用者可读的账户字段、加入/离开状态、完整工作区关系；不得查询无关组织身份        |
| 角色详情        | Role、RolePermission、成员绑定与已注册授权定义目录        | 单角色查询、保护/可编辑/可授予能力、绑定总量与分页、更新冲突规则；不增角色继承       |
| 资源与设施访问  | Resource / Facility / FacilityWorkspaceAccess             | 资源关系归属、元数据可见性、设施 READ/OPERATE 解释及允许命令，无通用共享有效期       |
| 活动            | AuditEvent                                                | 可见组织/工作区/成员/角色过滤、净化字段与脱敏、分页，不把原始 audit payload 发给前端 |
