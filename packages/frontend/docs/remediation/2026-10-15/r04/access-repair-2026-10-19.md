# 本地页面访问修复

日期：2026-10-19。环境：当前运行的 `dev.local`、浏览器中现有 `admin` 会话。

## 实际原因

上轮超级管理员实现解决了授权检查，但没有更新当前数据库的业务结构。
因此库存权限上下文已经返回 200，材料、库存和设施列表仍返回 500。
前端根据真实响应中的 capabilities 开放按钮；数据读取失败时仍禁用相关操作，
不存在另一个需要手动开启的前端超级管理员开关。

数据库差异覆盖 P07 材料分支、P08 设施/存储结构、P09 日期/库存操作及 P10 上传会话。
另外，部分管理页面仍是没有生产数据源的骨架，后端也没有对应公开接口。
超级管理员不会使这些接口自动出现。

## 本次执行

- 使用 Prisma 对当前数据库与当前 schema 做只读差异检查。
- 确认受影响的材料、库存、设施及附件业务表均为空。
- 普通 `db:push` 因新增唯一约束的通用警告停止；未使用 `--accept-data-loss` 或重置数据库。
- 审阅生成 SQL，在同一事务中锁定并再次检查相关旧业务表为空后更新结构。
  SQL 保存于本机 `output/remediation/access-repair-2026-10-19/schema.sql`，不作为通用生产迁移。
- 安装既有 identity、storage-node、inventory 原生约束；最终 Prisma schema diff 为空。
- 更新前后数量一致：账户 1、组织 2、工作区 2、角色 6、角色权限 36、
  组织角色绑定 4、工作区角色绑定 2、审计记录 8；admin 超级管理员标记保留。
- 本轮没有修改业务源码、注册 mock 来源、向真实组织创建业务记录或保存业务表单。
