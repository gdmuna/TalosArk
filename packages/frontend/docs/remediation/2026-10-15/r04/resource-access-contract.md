# R04-C 资源授权与共享契约交接

日期：2026-10-18。范围：F-03、F-04、F-05 的前端消费需求。**这是读模型提案，不是已实现的后端 HTTP 契约，也不批准新增授权规则。**

## 当前事实与缺口

已核对 `backend/prisma/model/permission.prisma`、`core/permission/permission.contract.ts`、权限上下文设计及现有公开团队接口：

- 现有持久事实是 Permission、Role、RolePermission、OrganizationRoleBinding、WorkspaceRoleBinding；绑定只有创建时间，没有资源直接授权、到期或撤销历史模型。
- 当前权限是精确动作、精确组织/工作区 scope、allow-only。没有显式 Deny、组织到工作区自动继承、节点继承或通用资源共享策略。
- Authorization 可以根据业务 Provider 解析真实归属并判定动作；ResourceIdentity 表达跨模块稳定资源身份。两者都不自动提供授权治理列表、完整授权解释或策略设置。
- P06 的角色绑定及 P07 的材料可读性不等于 F-03/F-04 的资源授权管理。邀请的 expiresAt/revokedAt 不能复用于资源授权状态。
- 未发现满足以下消费需求的公开读接口。本轮不猜 HTTP 路径，不修改 `packages/contract`、Prisma、权限目录或后端。

这里的“公开契约”是前后端明确约定的已授权业务 API、请求/响应类型和异常语义，不是必须增加 `.well-known` 的接口发现机制。发现文档不能代替业务实现和授权。

## 前端边界

`module/resource-access/data/source.ts` 定义两个独立可选来源：

| 来源方法 | 消费语义 | 待确认条件 |
| --- | --- | --- |
| `ResourceAccessDataSource.list` | 组织内可选工作区范围，服务器搜索/类型/来源/状态筛选和分页；返回授权记录与筛选目录 | 管理查看能力、实际支持的主体/来源、稳定排序、授权过滤先于分页与 total |
| `grant` | 按稳定授权记录 ID 独立读取 Inspector，不把列表摘要当完整详情 | 记录的稳定身份、历史/失效记录是否保留、当前不可见来源的安全投影 |
| `resource` | 按 Resource ID 深链，返回资源身份、授权依据、完整性、事实和关联实体 | 元数据管理权与内容读权分别判定；完整列表还是部分集合必须明确 |
| `SharingPolicyDataSource.read` | 组织内共享范围、资源类型规则矩阵、默认值和适用说明，只读字符串投影 | 是否存在组织策略、由谁读取、缺省值来源及与现有权限的关系 |

两类来源分别注入，不要求同时就绪，不在启动阶段加载。生产未注册它们；缺来源显示准确的未开放状态和已有管理入口，不生成空统计或回退 fixture。未来 HTTP adapter 应归该 owner 的 `data/`，用正式 wire schema 解码并映射；页面不直接请求 transport。

### 标识与授权投影

- Resource ID、Material ID、授权记录 ID、OrganizationMember/WorkspaceMember ID 和 User ID 不互换。
- `content` 是来源单独确认当前可读的业务对象引用；只有材料类型且与当前全局组织/工作区一致时出现内容详情链接。不以可查看治理元数据推导可读业务内容，也不在点击时静默切换全局工作区。
- `AccessReference` 仅用于来源已确认可读的成员、角色或工作区管理目标。未知/不可见来源可显示获准公开的名称和解释，但 reference 为 null，不拼猜测链接。
- permissions 是服务器解释后的动作 code/label，不由页面、角色名或某一行绑定计算用户最终有效权限；每次真实操作仍由后端授权。
- basis 的身份、名称和说明由来源提供。页面不把范围绑定称为节点继承，也不生成“所有者自动放行”规则。
- status 由来源投影为 active/expired/revoked/unavailable；没有状态时不是有效。该展示联合并不声称当前持久模型支持过期或撤销历史。
- expiresAt 缺失表示未知，null 表示来源明确没有到期限制，字符串表示时间。不能从缺失值推导永久有效。
- resource.complete=false 时计数只描述本批依据，并提示不是完整授权集合；related=null 表示未提供，[] 表示已知空集合。
- facts/settings 只接收明确的 label/value 字符串，不暴露原始策略 tuple、Prisma 对象或任意审计 details。

### 请求和恢复

- 页面的组织目录只是本地范围选择边界，不是服务器授权证明；每次 list/grant/resource/policy 仍须服务端重新授权。
- URL 保存 organization/workspace/q/type/basis/status/page/pageSize，详情用 view；列表条件修改清页码，保留无关 query/hash。列表面包屑恢复同范围最近 URL，快速返回保留导航来源。
- 账户、范围、资源或查询 key 改变同步清旧数据，取消旧请求；即使 adapter 忽略取消，旧结果也不能发布。卸载后同样失效。
- 同范围临时故障保留明确标注的旧结果；认证变化、401/403/404 和协议/范围不一致清结果。重试只重读。
- 响应组织/工作区、请求授权记录/资源身份及分页范围须匹配。空列表也校验响应 scope，不因没有行而跳过隔离检查。

## 真正接入前必须确认

1. **读权限**：组织治理查看、工作区范围查看、单资源管理元数据、业务内容读取分别由什么能力控制；未知对象/无权对象是否统一 404。
2. **授权语义**：首发是现有角色依据的只读解释，还是需要新的直接资源授权；支持的主体、动作与可委派上限。不能用当前提案反向批准任意主体/通配符/继承。
3. **列表与身份**：授权行的稳定 ID、一个资源的多来源记录、生命周期/历史保留、total 与过滤口径及分页一致性。必要时用游标替换页码，但不得对当前批次冒充全局搜索。
4. **到期/撤销**：若获批，明确时间边界、撤销记录保留、授权竞争与审计；否则来源返回未知，前端不模拟倒计时或撤销成功。
5. **共享策略**：是否属于软件 MVP；只影响未来默认值还是追溯已有授权、冲突/并发版本、影响预览。跨组织共享、公链、自动审批仍未获批。
6. **写入**：新增/撤销/保存需要正式命令、可授予候选、版本冲突、影响确认、事务审计和写后仅重读恢复。本轮接口无写方法，页面无假保存按钮。
7. **审计**：资源活动复用独立 audit 来源；真实公开契约与权限仍归 R04-A2。不将授权详情中的临时记录拼成组织审计。

后端若决定只交付角色依据解释而不支持直接授权，应按该真实能力收敛消费类型和页面，而不是实现一套仅为满足此提案的授权引擎。
