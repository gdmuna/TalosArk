# 审计读契约交接

日期：2026-10-18。状态：前端暂定消费模型，不是已批准的公开 HTTP 契约，不新增后端范围。

## 已核实的事实与缺口

- `core/audit` 有组织/工作区范围、动作/资源/时间过滤、时间与 ID 稳定游标；范围声明本身不是授权。
- R03 只有工作区/成员/角色对象活动，不能聚合它们冒充全组织日志。
- 尚无通用审计列表/单事件公开接口，也没有本页可据以判断的审计查看能力。组织成员身份、组织角色管理权、当前工作区可访问性都不自动等价于审计读权限。
- 原始事件没有通用结果、客户端、IP、事务编号或任意字段前后值。本轮不补采集模型。

## 前端消费边界

代码入口：`src/module/audit/data/source.ts`，由应用组合显式注入 `auditDataSourceKey`。当前生产未注册来源；隔离验收直接注入独立来源，不通过环境开关、URL 参数或 HTTP 失败触发 Mock。

| 查询 | 输入 | 输出 |
| --- | --- | --- |
| list | 明确组织、可选工作区；精确动作标识、资源 ID；ISO from（含）/until（不含）；limit 20/50/100；不透明 cursor | items、nextCursor；不假设 total 或随机访问页码 |
| event | 同样的组织/可选工作区范围、事件 ID | 单事件事实及受控业务说明；不能只在前端现有 items 中查找 |

摘要包含事件 ID、组织身份、工作区身份或 null、操作者安全显示身份或 null、动作标识/显示名、时间、可选请求 ID、事件时的资源 ID/名称。详情追加可选 description 和白名单解释的 `facts: {label,value}[]`，value 只能为展示字符串，不包含任意对象或 HTML。null 操作者表示资料不可用，不推断为系统。

未来 HTTP 适配器须从正式 contracts 导入 schema、验证响应并映射到这里；不要把当前 TypeScript 消费模型当成服务端校验。前端已额外检查返回组织/工作区与请求范围一致，但它不能代替服务端授权。

## 后端需要确认的行为

1. 明确组织与工作区审计查看能力、授权主体与目录。先授权，再查列表/详情，所有数据投影遵守同一范围；无权、跨组织或不可见事件不得返回可识别事实。
2. 所有分页筛选均在服务端应用；cursor 与作用域/筛选绑定，稳定排序、过期或失效的错误码需明确。当前 UI 不提供操作者筛选，因为内核尚无受控的对应过滤契约；不从当前页拼一个不完整的“全部操作者”目录。
3. 操作者和资源时点名称有明确安全投影；动作显示名、description、facts 由各业务动作白名单生成，不返回原始 details、凭据、请求、完整实体或原始异常。
4. 单事件详情允许在页面刷新时独立读取；身份撤销、事件不可访问时返回一致的 401/403/404 语义，读响应不缓存敏感内容。
5. 关联资源导航需要其当前可读性与定位信息，不能将事件时引用视为授权。删除/归档/离开组织后仍可查看的历史事实与当前可访问资源分别表达；这部分未在 A1 猜测协议或开启跳转。
6. 导出独立交给 P18，沿用同一授权与筛选，不在只读列表中暗中引入任务系统。

## A2 的接线验收

后端契约确认后再创建真实 HTTP 适配器并在应用组合处注册，不改页面取数规则。验收正确/错误组织、组织与工作区授权、撤权清理、游标与过滤一致、不可见资源、深链刷新及列表返回。类型检查和隔离来源通过均不能证明这些生产权限已经成立。
