## P10 接线

后端 P10 已交付；此前材料详情的文件视图仍使用 `ResourceFile` 占位。本轮用材料模块的附件视图替换，复用已有材料读权限、更新 capability 和归档状态。后端继续逐操作鉴权，前端按钮不充当授权边界。

| 用户操作 | 实现 |
| --- | --- |
| 查看附件 | 按材料与当前工作区读取有效引用；游标上一批/下一批，显示名称、声明类型、大小与添加时间 |
| 附件资料 | 只展示公开引用资料和下载入口；不提供文件内容内联预览、版本或在线编辑 |
| 上传 | 文件白名单和 100 MiB 提前检查，完整 SHA-256；当前 UI 使用契约允许的 single 模式，不提供分片模式切换 |
| 进度与恢复 | 原 begin 幂等键、sessionId、assetId 和绑定回执在材料模块持有；同标签页 sessionStorage 按账户隔离，刷新后重新选择原文件并校验名称/大小/哈希 |
| 完成与绑定 | 先完成并验证，再用原 assetId 绑定；完成或绑定响应丢失时查询/重放原会话，不另建上传 |
| 下载 | 每次取得短期签名；不持久化签名 URL，不通过业务 API 客户端传输文件 |
| 移除 | 显式确认，重试同 referenceId；确认写入后若列表失败，仅重新加载 |
| 归档 | 保留列表/下载，禁止上传及移除 |

`module/material/data/attachment-api.ts` 实现公开 HTTP 契约，作为已有 MaterialDataSource 的附件能力；`model/attachment.ts` 维护上传流程，`ui/MaterialAttachmentList.vue` 组合列表与交互。`platform/file-transfer` 只负责文件哈希和签名 GET/PUT，不依赖材料业务，不附加应用 Cookie 或 Bearer token。未新增依赖或修改后端。

上传恢复信息不含文件二进制、签名 URL 或认证凭据。内存文件在成功绑定、取消或账户变化时释放，失败时可继续使用原文件；存储恢复只覆盖当前标签页会话，关闭标签页、退出登录后不承诺恢复。单次 PUT 重试可能重新发送整个文件，不宣传为字节级断点续传。大文件哈希与下载 Blob 需要文件大小量级的临时内存。最终格式、大小和完整性仍由服务端验证。

## P09 自查项的纠正

1. 恢复原 Cell Bank 与专业 Batch 骨架及其路由，专业 Batch 和来源批次使用不同页面，不忽略 bankId 冒充来源批次。
2. 库存列表恢复 `data` 居中容器（1440px 上限），并消费一次性 `resource` 预览指令。
3. 入库的原 scope/body/idempotencyKey 和回执移入库存 Pinia owner，在当前标签页刷新、路由往返后仍可核对并重试原请求；账户切换清理旧内存/存储。
4. 恢复状态不由当前表单重新生成；无确定回执时不能建立同工作区第二次登记。确认写入但刷新失败，只重读。
5. 位置搜索/游标/设施查询提取到页面私有 InventoryPositionPicker；入库组件专注材料/批次表单组合，写入不再依附弹窗生命周期。
6. 批次冲突/不确定结果锁定重提，提供“读取最新资料”；新建结果不确定时按原批号核对，编辑则按 ID 读取最新修订。
7. Material reader 的显式刷新复用同范围未完成读取，避免 mutation revision 自动刷新后回调立即取消并重复发送同一请求。
8. 移除没有调用方的搬迁/回执查询适配器与读函数未使用配置参数；搬迁前端仍按后续切片实施。
