# Dev Portal 资源与数据源设计

> 状态：设计基线 v0.1，2026-10-10。本文定义待实现的索引与来源规则，代码位置仅表示现有来源或格式示例。

页面职责见 [业务设计](./business-design.md)，资源详情路径见 [导航矩阵](./navigation-route-matrix.md)，术语见 [CONTEXT.md](../../CONTEXT.md)。

## 1. 资源目录与身份

| `kind`              | 对象                  | 默认身份依据                  | 浏览入口                      |
| ------------------- | --------------------- | ----------------------------- | ----------------------------- |
| `feature`           | 功能                  | `.scratch` 内功能目录相对路径 | 功能详情                      |
| `issue`             | Issue                 | Issue 文件相对路径            | Issue 详情                    |
| `document`          | 文档                  | 文档文件相对路径              | 文档详情                      |
| `package`           | workspace 包          | workspace 中的包根相对路径    | 包详情                        |
| `module`            | 代码模块              | 所属包与已确认所有者入口      | 模块详情                      |
| `file`              | 仓库文件              | 文件相对路径                  | 文件详情                      |
| `design-component`  | UI 基元或通用功能组件 | 所属包与组件公开入口          | 组件详情                      |
| `design-foundation` | 设计基础              | 来源包与基础文档 / CSS 身份   | 设计基础；token 用 query 定位 |
| `schema-model`      | Prisma 模型           | schema 来源集合与模型名       | 模型详情                      |
| `schema-enum`       | Prisma 枚举           | schema 来源集合与枚举名       | 枚举详情                      |
| `schema-ddl`        | 原生 SQL 脚本         | 文件相对路径                  | DDL 详情                      |
| `api-operation`     | OpenAPI 操作          | 文档来源与规范化 method、path | 操作详情                      |
| `api-contract`      | 公开 wire schema      | 公开导出路径与符号名          | 契约详情                      |

每个资源记录至少包含 `id`、`kind`、`title`、`locator`、`sourceId`、`snapshotId`、解析状态与可用来源位置；关联与页内能力按实际内容附加，不强制所有类型拥有相同详情字段。

`id` 是根据类型与 locator 确定的稳定 URL 安全身份，同一资源刷新后保持一致，不能使用数组下标、标题、扫描顺序或临时 UUID。编码由实现确定，需保证不同 locator 不冲突。资源定位采用仓库相对路径和符号，不把机器绝对路径写进浏览地址。

文件路径规范化为 `/` 分隔并保留来源大小写；身份解析遵守实际文件系统的大小写语义，不能把 Linux 下不同的文件合并。文件移动后属于新的 locator，首版不建立全仓库重命名追踪。

不同资源类型可指向同一文件，例如文档与文件；它们保持类型身份并共享来源定位。资源详情 URL 由路由定义生成，索引不持有随意拼接的页面地址。

## 2. 首版数据源矩阵

| 来源       | 当前仓库依据                                                                                       | 首版读取方式                                         | 能力与限制                                                     |
| ---------- | -------------------------------------------------------------------------------------------------- | ---------------------------------------------------- | -------------------------------------------------------------- |
| tracker    | `.scratch/<feature>/PRD.md`、`issues/<NN>-<slug>.md`                                               | 按既有目录和 `Status:` 约定解析                      | 提取功能与 Issue；目录为空不产生演示记录                       |
| 文档       | 根级说明、`docs/`、各包 `CONTEXT.md` 与 `docs/`、tracker 文档                                      | 读取被纳入范围的 Markdown，生成正文与搜索索引        | VitePress 预览仅作为可选入口；不执行 Markdown 中脚本           |
| 包与结构   | `pnpm-workspace.yaml`、包清单、源目录和已确认入口                                                  | 解析清单、目录及直接导入关系                         | 不把每个目录都登记为模块；动态或未解析引用保持未确认           |
| 设计基础   | `packages/frontend/docs/design/design-foundation.md`、`src/style.css`、`color-system-preview.html` | 读取规范与 CSS，接入已有预览                         | CSS 是 token 数值真相源；HTML 样张是派生结果                   |
| 组件       | `packages/frontend/src/ui`、`src/component` 的公开入口及后续示例声明                               | 有限源码解析、显式示例登记和真实预览连接             | 自动发现文件不等于完整组件文档或可用预览                       |
| Prisma     | `packages/backend/prisma/schema.prisma`、`prisma/model/*.prisma`                                   | 读取当前多文件定义，解析模型、字段、枚举、关系和索引 | 排除 `deprecated-schema.prisma`、生成客户端等旧 / 派生内容     |
| 原生 DDL   | `packages/backend/prisma/ddl/init`、`schema`、`upgrade`                                            | 读取 SQL、注释与显式关联，保留阶段分类               | 首版不执行脚本或承诺完整 SQL 语义解析                          |
| 公开契约   | `packages/contract/src` 的公开导出                                                                 | 读取源码及可支持的 schema 结构，记录导出来源         | 排除 backend-only 内部目录和内部策略；不执行源码来自动发现类型 |
| OpenAPI    | 后端 `/api-doc-json` 或明确配置的已生成文档                                                        | 可选读取实时 JSON / 快照                             | 记录来源版本和取得时间；缺少版本证明时标记时效未知             |
| 验证证据   | 显式声明的报告或证据记录                                                                           | 读取受支持的结构化摘要与原始报告位置                 | 无通用报告格式时先显示原文；不通过任意日志文本猜测成功         |
| Git 元信息 | 当前工作区 Git 状态                                                                                | 只读获取 HEAD、分支和修改摘要                        | Git 失败不阻断文档和 schema；首版不执行写操作                  |

公开契约不能简单递归展示 `packages/contract/src/backend`；该目录含 backend-only 错误目录与内部策略。已知公开导出可以结构化显示，无法解析的内容提供源码入口和能力说明，不宣称完整解析。

默认正文索引只读取约定的文本类型和明确来源。`node_modules`、`dist`、构建缓存、生成客户端、Tauri 生成目录、`.git` 对象、`secrets`、`.env*`、密钥和凭据文件不进入文件浏览与全文索引；`.git` 元信息经只读 Git 操作获取。忽略项可以显示为已排除目录说明，不展示其文件内容。

生成报告可通过明确声明的路径单独纳入，即使所在 `output` / `coverage` 被默认排除；这不授权全量索引该目录。实际文本大小上限、忽略 glob 和允许来源在实施时集中定义，页面不自行扩展读取范围。

路径读取限制在选定仓库根内，并校验规范化真实路径；不借软链接、`..` 或绝对路径读取其他目录。图片、字体等资源只按已声明预览需要接入，不进入全文解析。

## 3. 资源关联规则

关联有两个来源：明确可解析的结构事实，或维护者的显式声明。名称相似、关键词命中和目录相邻只能帮助搜索，不能成为已确认关联。

首版关系限定为：功能包含 Issue、功能关联文档 / 实现资源、包拥有模块、模块拥有入口、文档说明资源、Prisma 模型引用模型 / 枚举、API 操作关联公开契约、设计资产引用规范 / 源码。

直接导入可以构成已确认代码依赖；未能静态解析的动态导入不生成猜测连线。OpenAPI schema 与 Zod 导出同名不能自动认定为同一契约，需要明确映射或可验证生成关系。

### 功能补充声明

保留现有 tracker 格式，建议在有需要的功能目录增加可选 `.scratch/<feature>/portal.yaml`，承载看板专用关联与程度声明。Portal 首版只读该文件，已有 PRD 和 Issue 无须迁移。

以下为格式示例，不代表已存在的功能、当前归属或验证结果；这些字段也是待实施的解析约定。

```yaml
version: 1
resources:
    - key: design
      kind: document
      path: packages/frontend/docs/design/design-foundation.md
      role: design
maturity:
    frontend:
        level: specified
        resourceRefs: [design]
        coverageConfirmed: false
        reason: 尚未确认全部必需的前端实现资源
    database:
        level: not-applicable
        reason: 本功能不持有业务数据
```

`key` 是该文件内的关联别名；实际资源 ID 仍由 locator 生成。`resourceRefs` 引用同文件已声明资源。`kind`、`level` 和维度使用文档规定的词汇；`path` 定位文件，需要符号时另加 `symbol`，禁止在 path 中混入行号或 URL。

`coverageConfirmed` 表示维护者已列明本维度全部必需资源。未确认覆盖范围时可以显示声明及依据，并附“局部”或“覆盖范围未确认”说明，但不能汇总为 `verified`。声明不存在时各维度为 `unknown`；声明的资源失效时显示无效依据，不能继续用旧声明背书。程度是显式声明，不根据被引用文件的存在或大小自动推算。

首版不要求为每个资源写登记文件。只有自动解析不足的功能关联、模块职责和真实预览示例需要补充声明；其他资源按已知来源读取。

### 验证证据

证据记录需要 `id`、`checkName`、`resourceRefs`、`covers`、`observedAt`、`result`、`revision` 和 `reportPath`，并可附检查范围的文件内容摘要。`covers` 描述实际检查能力，例如类型检查、组件交互或数据库定义校验，不笼统写“功能验证”。

证据格式可以附在功能补充声明的 `evidence` 集合，或由显式接入的报告来源提供；首版无证据时保持空集合。

版本比较先判断资源范围是否明确，再比较 Git 版本与被检查资源的内容依据。仅有 HEAD 不能证明未提交工作区已验证；无法确认检查范围或内容一致时，时效为 `unknown`，不得支持 `verified`。无关文件变化不必自动使有明确内容依据的证据失效。

## 4. 来源状态、快照与刷新

每个数据源具有独立状态：`ready`、`partial`、`unavailable`、`not-configured`。`ready` 表示读取成功，内容可以为空；`partial` 表示仅部分范围成功。另行记录是否正在刷新、是否过期及上次成功时间。

快照包含 `snapshotId`、生成时间、仓库身份、Git HEAD / 分支 / dirty 状态（可用时）、源文件内容依据、各来源状态和诊断。接口返回记录与搜索结果携带 `snapshotId`。

刷新规则：

1. 首次读取按来源建立索引，来源失败形成诊断，其他来源继续；关联只在已读取资源间解析。
2. 文件监听合并短时间内的变更，按受影响来源重新解析；支持显式刷新。监听只是提醒重新读取，不直接把事件内容当作索引。
3. 新候选快照的资源、关联、搜索和诊断准备好后统一发布。刷新期间用户继续读取上次发布快照。
4. 刷新某来源失败时保留其旧内容并标记过期，候选快照明确记录该来源的旧版本；不能把它标成当前成功结果。
5. 同一页面和关联查询使用同一已发布快照。跨请求发现版本变化时重新读取当前视图，避免新模型搭配旧关系；旧来源在快照中仍须保留自己的过期说明。
6. 文件在扫描期间再次变化时丢弃不一致候选结果并安排重读，不发布一半新内容。
7. 首版保留当前与刷新期间需要的上一快照，不建立永久历史数据库。

通知可通过 SSE 或短轮询告知“有新快照”；最终内容重新经读取接口获取。首版无需为浏览交互引入双向 WebSocket。

## 5. 搜索与跨资源定位

搜索索引覆盖标题、路径、已解析符号名、文档正文与适合展示的模型 / 契约说明。结果包含资源类型、命中片段、来源位置、快照和时效。

默认优先匹配明确身份、标题和符号，其次路径与正文。搜索只按类型与来源过滤已有索引，不执行代码或调用数据库。没有名称精确匹配时仍可提供文本命中，但不能把命中自动转为资源关联。

结果跳转使用资源类型对应的规范详情路径；源码命中携带 `line`，文档标题命中携带 hash，模型与组件进入其专属详情。

## 6. 前端数据能力与降级

| 能力            | 完整可用时                   | 暂不可用时                                          |
| --------------- | ---------------------------- | --------------------------------------------------- |
| 文档渲染        | 预览、目录与链接定位         | 提供安全原文和解析诊断                              |
| 组件元数据      | 已解析参数、事件与已登记示例 | 展示已收录部分及源码，说明缺失范围                  |
| 真实组件预览    | 显示来自前端预览入口的效果   | 展示预览不可用，不伪造组件效果                      |
| Prisma 解析     | 模型、枚举与关系图           | 成功范围可浏览，失败文件提供诊断，不宣称完整 schema |
| 原生 DDL        | 原文、阶段和显式关联         | 单个文件读取失败不清空 Prisma 模型                  |
| OpenAPI         | 操作与请求响应结构           | 无快照时操作目录不可用，契约目录独立可用            |
| 契约解析        | 可支持的 schema 结构与来源   | 提供源码，不执行任意导出代码                        |
| 实现矩阵        | 显式程度、有效依据与当前证据 | 标记未知、未确认覆盖范围或历史证据                  |
| 文件 / Git 读取 | 当前目录与版本信息           | 保留成功部分，各自说明来源状态                      |

读取到的文档、源码、示例与诊断均作为数据处理。Markdown HTML 与 Mermaid 采用安全渲染策略；源码只显示文本。真实组件预览连接只使用明确声明的本地入口，是否允许嵌入由提供方决定，不假定任意站点都能 iframe 显示。
