日期：2026-10-18。状态：后端公共能力和材料用途贡献已交付；数据库未同步，P10 HTTP/公开契约/前端尚未接入。

没有新增上传供应商、环境变量、缓存、自动任务、真实类型检测或病毒扫描。

## 1. 职责怎么分

`core/file` 管上传意图、用途准入、引用生命周期、并发排他、分页和签名。
它不读取请求 ALS，不知道 `material.read/update`，也不自己决定材料是否可管理。

材料模块通过 `@FilePurposeExtension(materialAttachmentPurpose)` 贡献静态定义和一个单例 Provider：

- 定义：用途 key、资源种类、大小上限、扩展名与声明 MIME 对照表。
- `authorize`：按真实材料事实检查当前 read/update；管理操作先取得组织、材料锁，与 P06 治理和 P07 归档串行。
- `recordChange`：首个有效绑定/解绑在同一事务内追加材料审计，失败整体回滚。

FilePurposeRegistry 在 `onApplicationBootstrap` 用现有 ExtensionDiscovery 收集并冻结定义。
重复 key、非法格式/大小、缺方法、request/transient 依赖树使启动失败；不在启动时写数据库。
没有用途的部署可以只使用通用上传；请求未注册用途明确失败。

这里复用 ResourceIdentity 和公开 ResourceDescriptor 类型/校验，不把 Resource 的 read-only describe 当作更新权限证明。
用途 Provider 只依赖材料公开事实、Authorization 和 Audit，不与 Resource Provider 相互调用。

## 2. 第一种用途

`material.attachment` 最多 104,857,600 字节，一个资产最多绑定一个材料，不提供已有附件复用。

| 扩展名 | 允许的声明 MIME |
| --- | --- |
| pdf | application/pdf |
| docx | application/vnd.openxmlformats-officedocument.wordprocessingml.document |
| xlsx | application/vnd.openxmlformats-officedocument.spreadsheetml.sheet |
| pptx | application/vnd.openxmlformats-officedocument.presentationml.presentation |
| txt | text/plain |
| md | text/markdown、text/plain |
| csv | text/csv、application/csv |
| jpg、jpeg | image/jpeg |
| png | image/png |
| webp | image/webp |
| gif | image/gif |
| tif、tiff | image/tiff |

扩展名不区分大小写；上传输入规范化声明 MIME，拒绝通配类型和无条件的 application/octet-stream 回退。
未列出的格式，包括 SVG、旧 Office、宏、压缩包、可执行文件和音视频均不准入。
声明匹配不是内容安全证明；I08-A 的实际大小和完整 SHA-256 核验继续保留。

## 3. 调用方式

应用编排者显式导入 FileModule，从已验证身份及材料事实构造 actor、真实 resourceId 和固定用途。
不能把客户端填写的 userId、组织或用途当成可信输入。P10 仍需完成这个映射。

```ts
const target = { ...actor, purposeKey: 'material.attachment', resourceId };
const upload = await files.beginUpload({
    ...actor,
    purpose: { purposeKey: target.purposeKey, resourceId },
    idempotencyKey,
    filename: 'report.pdf', contentType: 'application/pdf', sizeBytes, sha256,
    mode: 'single',
});
// signUpload / inspectUpload / completeUpload 沿用 I08-A；分片也支持。
const asset = await files.completeUpload({ ...actor, sessionId: upload.id });
const reference = await files.bind({ ...target, assetId: asset.id });
const page = await files.listReferences({ ...target, limit: 30 });
const download = await files.downloadReference({ ...target, referenceId: reference.id });
await files.unbind({ ...target, referenceId: reference.id });
```

`readReference` 返回明确的引用/资产快照；列表使用 `(sortOrder ASC, id ASC)` 游标，默认 30，最多 100。
游标绑定组织、资源与用途，不能作为授权证明，也不承诺跨页快照。
内部快照仍使用 Date 和十进制大小字符串；P10 必须另做 wire schema、输出白名单和公共错误映射。
不返回 bucket/key/lease/uploadId；签名地址仍是短期凭据，不进日志、不当成永久 URL 保存。

## 4. 上传和生命周期约束

FileUploadSession 新增可空 `purposeKey/resourceId`，以组织一致的外键关联 ResourceIdentity。
两者都是上传幂等意图的一部分，重放不能换目标。旧通用会话仍可保持两者为空。
材料用途上传开始、签名和后续使用、最终发布都会重新检查用途和当前权限；取消仍允许有效成员取消自己的会话，以便权限变化后停止上传。
签名生成后还会复查会话 OPEN、未过期、未进入完成清单状态，防止并发取消/完成后仍返回新上传签名。

上传完成仅产生未绑定资产。首次绑定需要同组织、当前上传者、未过期且未绑定的已验证资产；
有用途意图的资产还必须匹配原目标。通用上传资产绑定时也检查格式/大小，不能绕过材料准入。

绑定后清除未绑定期限，旧上传者 readAsset/downloadAsset 入口拒绝任何有引用历史的资产。
完成上传的合法重放可返回同一已绑定资产，但必须检查该引用的当前资源读取权限，不以会话所有权绕过授权。
其他有材料读取权限的用户不需要是上传者。

解绑同事务设置 `removedAt` 和资产 `deletedAt`；无其他有效资产时把对象标为待清理状态。
保留引用历史，不恢复引用，不重新开放未绑定下载。重新添加必须重新上传。
合法重复绑定/解绑返回原结果，不重复审计；重复请求仍检查当前权限和材料未归档。
归档材料可读/下载，但禁止绑定和解绑；恢复材料不会复活已解绑附件。

## 5. 事务、锁和签名

绑定/解绑使用 ReadCommitted 短事务；加入已有事务时使用 mandatory，且要求外层明确为 ReadCommitted。
不允许加入旧 RepeatableRead/Serializable 或未声明隔离级别的外层事务，避免在组织锁之后仍从旧快照读取已撤销权限。
与现有事务管理器一致，不兼容选项在执行写入前返回 options-conflict。
授权、引用写入、生命周期更新、审计同事务；已加入操作失败会把外层标为 rollback-only。

材料写入的锁顺序为 `Organization → Material → FileObject → FileAsset`。
核心生命周期锁与 I08-A 清理共用 Object → Asset；取得锁后重新读取对象、资产、期限和引用。
同资产绑定不同目标不能只依靠现有三列唯一索引；共享对象锁和资产锁串行化排他检查。
清理不得删除有效引用；重复解绑也不会直接执行对象存储删除。

上传、下载签名、存储传输、哈希和清理入口仍拒绝外层数据库事务。
引用列表/读取独立时使用 RepeatableRead；加入已有事务时沿用调用者快照。
下载先检查当前引用/授权，在事务外签名，返回前用新的读取事务再次检查。
下载固定 attachment 和 application/octet-stream，不开启内联预览。

下载签名默认 60 秒。解绑或撤权能阻止后续签发，不能撤回已发地址、已开始的传输或已下载副本。
本轮没有自动清理调度器；维护入口和暂存桶生命周期要求继续见 I08-A。
