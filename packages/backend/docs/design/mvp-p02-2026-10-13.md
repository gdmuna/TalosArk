# P02：邮箱找回密码

日期：2026-10-13。用户已授权 P02，并确认本轮有效期、发送限制、有限异步发送及仅本地合成 SMTP 验证。
本轮交付恢复申请/确认接口、真实恢复页面和邮件模板，不把 P03 的完整登录/启动恢复/当前账户接入记为完成。
任务状态见 [MVP 工作安排](../../../../docs/product/mvp-work-plan.md)。

## 用户现在能做什么

从登录页的“忘记密码？”进入 `/auth/recovery`，填写账户邮箱。符合条件时，由邮件中的 `/auth/reset-password#token=...` 链接设置新密码。
恢复完成撤销原有会话，用户自行返回登录，不自动签发新会话。
OIDC-only、尚未激活及不存在的账户得到相同申请受理结果，不用找回流程首次创建本地密码。

链接凭据由前端立即从地址栏移除，只保存在当前页面内存；不写 localStorage/sessionStorage、query、日志或埋点。重复、过期、撤销或邮箱变化的链接统一显示无效。
刷新该页面后不会从存储恢复秘密，需要重新打开邮件里的链接；重复打开同一有效链接不会在提交前消耗凭据。
提交失败若无法确认服务端是否已提交，页面不声称一定未修改：可重试，或尝试新密码登录/重新申请。

## 接口和分工

路径前缀 `/api/v1`。请求均为匿名入口，仍要求获信任的 Origin 与 `X-TalosArk-Client: browser`，不需要 AT。

| 接口 | 输入 | 成功 |
| --- | --- | --- |
| `POST /auth/password/recovery/request` | `{ email }` | 202，`{ status: 'accepted', retryAfterSeconds }` |
| `POST /auth/password/recovery/confirm` | `{ token, password }` | 200，`{ status: 'completed' }`；清除当前浏览器的 RT Cookie |

202 只表示受理，不证明存在账户、发送成功或进入收件箱。`retryAfterSeconds` 是客户端最小重申间隔，不承诺下次一定获准发信。
公开响应没有邮箱、userId、token、hash 或内部 metadata。确认失败统一使用 `AUTH_PASSWORD_RECOVERY_INVALID` 等声明过的错误，成功和申请响应 no-store。
使用 200 作为确认结果，复用已有包络解码器；没有为了本任务提前改造 P03 的通用 204/logout 接入。

## 凭据与事务

- 凭据为 32-byte 密码学随机值，使用 base64url；仅在独立 PasswordResetToken 表保存 SHA-256 digest、邮箱快照、有效期及消费/撤销状态。
- 邮箱去首尾空格并转小写，不合并点/+ 后缀。凭据签发取得 User 锁后再次检查当前邮箱及已存在本地密码，不能给 OIDC-only 或无密码账户创建恢复凭据。
- 签发在 ReadCommitted 事务中撤销旧恢复链接并创建新链接；事务提交成功后才发信。URL 只来自已验证配置，不从 Host/Origin 拼接。
- 确认前用现有 Argon2id/准入策略预计算密码，计算不占数据库事务或行锁。
- Auth 事务内依次执行：锁 User、再次检查凭据/时限/邮箱/本地密码、消费凭据、写新密码、撤销其他恢复/激活凭据、Access 撤销旧会话。任何一步失败整体回滚。
- 凭据撤销也使用同一 User 锁，避免并发邮件失败清理与重设产生“已经撤销却被继续消费”的结果。
- 申请本身不修改密码、不撤销会话、不锁定账户。确认不自动登录，旧 AT/RT 都因 Session 撤销而失效。

本轮直接使用现有模型及 P01 的受管事务/密码准备引用，没有 Schema/DDL、迁移或 db:push。
安全取舍参考 [OWASP Forgot Password](https://cheatsheetseries.owasp.org/cheatsheets/Forgot_Password_Cheat_Sheet.html)，不声称实现了完整恢复合规体系。

## 限制和发送失败

用户确认默认：链接 30 分钟；同一邮箱至少间隔 60 秒、每小时最多 5 次申请；同一 IP 每小时最多 20 次。
所有格式有效的邮箱，包括未知账户，先执行同样的计数/冷却流程；首次请求起算固定窗口，不是自然小时或滚动时间序列。
邮箱的冷却/配额不足时不投递，仍返回相同 202，避免通过目标活动暴露内部情况；IP 超额统一 429/Retry-After，KVS 不可用 fail closed。
确认使用已有 Auth attempt limiter/KDF 上限，不重做 Nest Throttler 或新的通用限流基础设施。

HTTP 路径只做输入、来源、限制和队列受理，不查询账户或等待 SMTP。发送延后到 event-loop 的后续任务，避免响应等待随账户是否存在而变化。
队列含在途最多 64 项，并发沿用 SMTP 配置（缺省 3）。容量不足或关闭时在查询账户前统一返回 unavailable；不是无限缓存或隐藏队列。
邮件成功是 SMTP 接收结果，不是收件箱送达。SMTP 拒绝、超时/取消或未知发送结果时，尽力撤销本次凭据，记录不含收件人/正文/URL/秘密的有限错误摘要；撤销失败也记录标志，凭据仍有自然过期边界。

**明确限制：** 这是进程内 best-effort 发送，不是 Outbox/可靠任务。进程意外退出会丢未处理申请；邮件已被接收但结果未知时，用户也可能收到已失效链接。没有自动重试、可靠送达承诺或投递状态查询；用户可重新申请。
关闭停止入队、丢弃未处理申请、取消在途发送并至多等待 2 秒；不另装进程信号或扩大 W03 的全局关闭预算。

## 配置和部署

下列六项已明确写入 development、development.local、test、test.local、production、example，逐份加载校验，不只更新 example。

| 配置 | 默认 |
| --- | --- |
| `AUTH_RECOVERY_URL` | dev/test/example：`http://localhost:4444/auth/reset-password`；production：HTTPS 占位 |
| `AUTH_RECOVERY_TTL_SECONDS` | `1800` |
| `AUTH_RECOVERY_COOLDOWN_SECONDS` | `60` |
| `AUTH_RECOVERY_WINDOW_SECONDS` | `3600` |
| `AUTH_RECOVERY_EMAIL_LIMIT` | `5` |
| `AUTH_RECOVERY_IP_LIMIT` | `20` |

URL 必须 HTTP(S)，不得带凭据/query/fragment；production 要求 HTTPS。冷却不得长于计数窗口。
Web 启动现会显式激活 MailModule，校验发件配置并验证 SMTP 连接/TLS/认证；配置或验证失败阻止 Web 启动，不假装恢复服务可用。
部署前须替换 production 的来源/恢复 URL/发件身份等占位配置。修改前端端口也需同步恢复 URL；浏览器 Origin 回环放通不自动更改邮件链接。
CLI 没有新增 SMTP 依赖。原有加密凭据和其他任务的 SMTP 配置未被改写。

CD 的 `export-openapi.sh` 同步增加固定版本 Mailpit 接收器与显式合成 SMTP 配置，避免新增邮件初始化破坏既有文档导出。接收器无外发 relay/公开端口，随其他一次性容器清理；同时将供应商验证 fixture 改为独立 RSA 公钥，满足当前 IAM 校验而不复用 Access 的 EC 密钥。依据 [Mailpit 官方镜像](https://mailpit.axllent.org/docs/install/docker/)，本轮只作 Bash 语法/静态核查，未执行完整 Docker/CD 导出。
