## 实际接口

以下路径前缀为 `/api/v1`。

| 接口                             | 输入/认证                                 | 成功                                           |
| -------------------------------- | ----------------------------------------- | ---------------------------------------------- |
| `POST /auth/password/login`      | identifier、原样 password                 | 200，session/AT，RT Cookie                     |
| `POST /auth/account/activate`    | 专用 token、新密码                        | 204，激活，不自动登录                          |
| `POST /auth/password/set`        | Bearer AT、新密码、近期会话和外部身份绑定 | 200，首次设密、撤销旧会话、签发新会话/Cookie   |
| `GET /user/me`                   | 验证过的 Bearer AT                        | 200，仅自己的身份/资料，主体不取自 body/query  |
| `POST /auth/oidc/start`          | 原 OIDC 业务                              | 201，URL 和事务 Cookie                         |
| `POST /auth/oidc/login-callback` | 原 code/state/事务 Cookie                 | 201，保留 success/block；成功用 Cookie 交付 RT |
| `POST /auth/session/refresh`     | RT Cookie，无 AT，无 body 或 `{}`         | 200，原子轮转并写 Cookie，JSON 无 RT           |
| `POST /auth/session/logout`      | RT Cookie，无 AT，无 body 或 `{}`         | 204，撤销并清 Cookie；缺失/无效时幂等成功      |

Auth 写入口要求 Origin 在 `AUTH_ALLOWED_ORIGINS` 中，并有 `X-TalosArk-Client: browser`。
ApiRoute 同时校验/文档化 headers；合并声明字段，保留 Authorization/Cookie 等原始头。
刷新/退出 Cookie 的 OpenAPI security 独立于 Bearer；security 只描述文档，不改变实际 guard/领域验证。
body RT/sessionId 被拒绝。不存在、错误密码、OIDC-only、标识歧义都用同一 credentials-invalid 错误并执行相同 KDF。

## 规则与事务

- 标识去首尾空格；用户名区分大小写，邮箱忽略大小写。不合并点/+ 后缀，不折叠 OIDC issuer/subject。邮箱保存规范化小写；2026-10-14 改由 identity.sql 的 `email = lower(btrim(email))` CHECK 拒绝非规范化写入，普通 email 唯一索引负责唯一性。CHECK 失败保留为技术错误，不转换成账户冲突。
- 输入同时匹配两个账户时拒绝，不任选/合并。Identity 只返回内部 hash 的单向指纹用于立即事务复核，不把原始 hash 交给 Auth。
- 新密码为 15-128 个 Unicode code point，允许空格、不 trim/改大小写、不强制字符组合；拒绝全空白和小组已知可预测密码。该小表不是完整泄露密码库或 NIST 合规认证。
- Node 内置 scrypt：`N=131072,r=8,p=1`，16-byte 随机 salt、64-byte key，格式 `scrypt-v1:<salt>:<key>`；单进程最多两次并发 KDF，超出有限重试拒绝，不无限排队。
- 不猜测兼容未知旧 hash，不自动改旧密码。安全依据：[OWASP Password Storage](https://cheatsheetseries.owasp.org/cheatsheets/Password_Storage_Cheat_Sheet.html)、[NIST SP 800-63B-4](https://pages.nist.gov/800-63-4/sp800-63b.html)；参数是本轮技术选择，不伪称用户逐项批准。
- 独立 UserActivationToken：256-bit 随机 token，仅存 SHA-256 hash、邮箱快照、时限与消费/撤销状态，不复用 PasswordResetToken。链接用 fragment，显式受控终端交付，不写应用日志。
- 开户/首张激活凭据同一嵌套写入。激活取得 User 锁后重新读取时间/状态/邮箱；消费、改密、撤销其他激活/恢复凭据和旧会话在一次 ReadCommitted 事务内，竞争只能成功一次。
- 重发仅针对已有激活记录、未设密码、用户名/邮箱匹配的受控账户；撤销旧链接与新签发同事务。不能用于恢复已有密码或替代 OIDC-only 首次设置。
- OIDC-only 首次设密要求 Session 在最近 10 分钟内创建，刷新 AT 不让登录变新。超出窗口仅拒绝本次首次设密请求，不自动撤销会话或强制账户补密码。Auth 以 User -> Session 顺序锁定；改密、撤销、签发新会话失败整体回滚。
- OIDC 回调通过 KVS 的条件 Hash 消费在同一次 Lua 执行中读取、严格比较 state 并删除事务。不匹配时保留内容和原有 TTL；匹配后仍一次性消费，提供商换码失败不自动恢复事务。公开错误不变，内部诊断区分记录缺失、字段缺失和 state 不匹配。
- 登录先验证，再在签发事务中锁 User/复核指纹，不能在并发改密后用旧验证结果签发。凭据复核与近期会话校验都要求 ambient transaction。
- Cookie 为 HttpOnly、host-only、SameSite=Lax。Secure 时用 `__Host-talosark_rt`、Path=/；本地 HTTP 用 talosark_rt，清除属性一致。Max-Age 不超过 RT/Session 期限，服务器仍验证到期/撤销。
- 来源白名单加非简单 header 防护 Cookie 写入口，不靠 HttpOnly/SameSite 单独声称 CSRF 已解决。生产拒绝非 Secure、非 HTTPS 来源/激活 URL。
- 已消费但未到期、所属 pair/Session 仍有效的 RT 可用于撤销，不能再次刷新。失败时不声称退出完成、不主动清 Cookie；刷新败者不清 Cookie。保持 W05 的 RT 重用只拒绝当前请求、旧有效 AT 正常保留。
- 默认 5 分钟内每入口标识桶 5 次、IP 桶 30 次，成功也计数，返回 Retry-After。桶保守合并标识大小写，但不改变匹配规则；不是跨别名统一用户桶。KDF 另有全局上限。
- Valkey 原子计数/过期，使用既有 app/env namespace、输入 digest 入键；失败 fail closed，未知错误不冒充错误密码。IP 取自 Fastify，不信任任意转发头。

Cookie/CSRF 依据：[OWASP Session Management](https://cheatsheetseries.owasp.org/cheatsheets/Session_Management_Cheat_Sheet.html)、[OWASP CSRF Prevention](https://cheatsheetseries.owasp.org/cheatsheets/Cross-Site_Request_Forgery_Prevention_Cheat_Sheet.html)。
