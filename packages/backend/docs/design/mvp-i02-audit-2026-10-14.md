# I02：关键业务与审计一起提交

实施日期：2026-10-14。范围依据：`mvp-foundation-work-plan.md` 的 I02，以及本会话确认的事务、操作者和直接输入设计。

## 本次交付

`AuditKernel` 只有两个公开方法：

```ts
record(input: AuditRecordInput): Promise<AuditReceipt>;
list(input: AuditListInput): Promise<AuditPage>;
```

业务明确选出需要审计的事实、动作名和安全字段。审计不是请求日志、领域事件总线，也不自动收集请求体或整个业务对象。
保留现有 `AuditEvent` 与 `AuditResourceReference` 表；新增查询索引，没有新增历史事实表。

```text
src/core/audit/

  audit.kernel.ts
  audit.contract.ts
  audit.error.ts
  internal/
    audit.input.ts

```

`AuditModule` 导入 `DatabaseModule`，只向 Nest 调用方导出 `AuditKernel`。内部 repository 是当前 Prisma 实现，不是公共 Port，
也没有另建 `infra/audit`。原有三个 TODO 骨架由实际接口和实现替换；没有调用方需要兼容旧接口。
业务模块在需要时显式导入 `AuditModule`，本次没有为了挂载审计而激活组织/工作区路由。

## 写入怎么保证一致

1. application 层打开业务事务，执行业务写入，然后 `await audit.record(input)`。
2. `record` 用 `propagation: 'mandatory'` 加入该事务，输入校验和数据库追加都在这个范围内。
3. 没有事务时拒绝，不偷偷开一个独立事务。校验或落库失败时，现有 transaction manager 把外层标成 rollback-only。
4. 即使 application 捕获审计异常，外层仍不能提交。业务后续失败时，审计也跟着回滚。

不使用 `requiresNew`、`afterCommit` 或后台队列写这种成功必须伴随的审计。
返回的 `AuditReceipt` 只说明当前事务中产生了该记录；只有外层 `transaction.run` 成功返回，才得到确认提交的结果。
提交断连仍可能是不确定结果，本次不承诺严格 exactly-once，也不自动重试事务或审计。
调用方必须等待 `record`，不能用 fire-and-forget。

写入检查组织存在、工作区属于该组织、操作者存在，以及所有引用资源均存在于事件组织中。
已有组合外键在实际写入时再次保证组织一致性，避免把预查询当成唯一防线。
操作者是全局 User，不要求永久保留当前成员资格；行动时是否有权操作，由调用方判断。
工作区是操作上下文，不强迫组织级设施等所有引用资源都属于同一个工作区。

`labelSnapshot` 由调用方提供行动时有权读取的显示名，写入后不会随资源改名刷新。
组织、工作区、成员不必仅为审计而成为 Resource，可以通过明确的安全详情保存目标 ID 和名称。
库存流水仍保存数量和位置事实；审计只保存所需引用和摘要，不复制一套库存账本。

## 操作者怎么取得

请求中间件建立每请求 ALS 范围，`AuthGuard` 在 Access 验证成功后调用 `bindAuthenticatedUser(userId)`。
同一范围不能换绑为另一用户，`requireActor()` 返回冻结的 `{ userId }`；缺少认证用户时明确失败。
metadata 内的同名字段不能提供身份。`get()` 仍返回副本，修改副本不会改变上下文。

`request.authentication` 仍只有冻结的 `userId/sessionId`。JWT claims 和供应商凭据不重新挂回 request。
Core Audit 本身不读 ALS；application 读取身份和关联请求 ID，再通过普通输入传入。
已认证响应会填入协议原本就允许的 `context.userId`，不新增响应字段或输出 sessionId。
公开及未认证的 optional 请求不绑定用户。本次没有引入 system/anonymous actor 或租户授权上下文。

## P04 接入示例

这是未来 application 内的直接调用形态，不是已启用的 P04 服务。模块须导入 `AuditModule`、`DatabaseModule` 和 `PlatformContextModule`。
创建资格、初始成员及权限仍需主线完成；这段示例不代表只创建一行 Organization 就完成团队闭环。

```ts
const actor = this.context.requireActor();
const requestId = this.context.get()?.requestId;

return this.database.transaction.run(async () => {
    const organization = await this.database.queryClient.organization.create({
        data: { name: command.name, ownerUserId: actor.userId },
        select: { id: true, name: true },
    });
    // Complete the approved initial membership/permission writes in this transaction.
    await this.audit.record({
        organizationId: organization.id,
        actorUserId: actor.userId,
        requestId,
        action: 'organization.created',
        occurredAt: new Date(),
        details: { organizationName: organization.name },
    } satisfies AuditRecordInput);
    return organization;
});
```

没有 `organizationCreated(...)` 一类纯字段拼装函数，也没有每个 action 对应一个注册器。
调用方从已授权上下文取 scope/actor，不允许 HTTP body 自报操作者和组织范围。
`action` 是稳定、点分隔的小写标识，首个真实用例确定具体名称与详情白名单。

## 输入与隐私边界

| 项目          | 当前约束                                                                                             |
| ------------- | ---------------------------------------------------------------------------------------------------- |
| ID            | UUID；校验后统一小写                                                                                 |
| action        | 最多 100 字符，至少两个点分隔片段，如 `organization.created`；片段支持小写字母、数字、下划线和连字符 |
| occurredAt    | 必填有效 Date，UTC 年 0001 至 9999；本层克隆时间，不替调用方决定事件时点                             |
| requestId     | 可选，1-128 字符，无控制字符；应使用内部关联 ID，不能拿凭据充当 ID                                   |
| resources     | 可省略，最多 32 项，同一资源不能重复                                                                 |
| labelSnapshot | 1-200 字符，无控制字符；不从整份对象自动富化                                                         |
| details       | 可省略；顶层为纯对象，内部为纯 JSON；编码后最多 16384 UTF-8 字节                                     |
| details 结构  | 根深度 0，最大深度 8，最多 2000 个值，键最多 128 字符                                                |

详情拒绝循环、稀疏数组、额外数组属性、getter、symbol、非枚举属性、类实例、undefined、函数、bigint、非有限数字、
不完整 Unicode 和 PostgreSQL JSON 不支持的 NUL。按校验结果复制数据，在第一次数据库等待前固定快照，防止调用方修改原对象影响落库。
不静默截断，不把非法值变成一个“看似成功”的事件。

另外拒绝明确的 credential 键，如 `password`、`access_token`、`authorization`、`cookie`、`privateKey`。
这只是防误用护栏，不能判断普通 `name`、`text` 字段中是否夹带密码或隐私。
**真正的隐私保证来自业务显式字段白名单，不能依靠一个敏感键黑名单。**

`AuditError` 只描述审计自身规则；数据库和事务错误保留所属模块的类型，未知编程错误保留原实例。
输入错误提供安全的 field/code/expected/received 诊断，不附原始输入或原始 Zod cause，不回显非法值。
没有 request/body/用户完整数据的日志或审计自动捕获。

## 查询与授权

```ts
const page = await this.audit.list({
    scope: { kind: 'workspace', organizationId, workspaceId },
    resourceId,
    from,
    until,
    limit: 50,
    cursor,
});
```

每次查询必须显式选择 `organization` 或 `workspace` scope。组织范围包含该组织所有工作区及组织级事件；工作区范围精确匹配一个工作区。
不能省略 workspace 后悄悄扩大权限。application 必须先验证读取该范围的权限，本层不是授权策略引擎。
跨组织 workspace 不会扩大读取范围；不存在的已声明范围返回空页。

可选资源和时间筛选；时间范围是 `[from, until)`，两者同时提供时必须 `from < until`。
默认 50 条，上限 100，查询多取一条判断下一页，按 `(occurredAt DESC, id DESC)` 做 keyset 分页。
不做总数扫描、不用 offset。读取只选择审计字段和资源名称快照，不联查完整 User 或业务实体。

cursor 是有版本的 base64url JSON，包含边界时间、ID 及 scope/资源/时间筛选的指纹。
换 scope 或筛选后重用 cursor 会拒绝；允许下一页换 page size。
指纹防止误用，不是签名：cursor 可以被客户端构造，它不证明授权，查询的组织/工作区条件始终独立强制应用。
没有跨页一致性快照；并发新记录可能影响后续页面，occurredAt 也不是事务提交顺序。

## Schema 与部署

把已有组织/工作区时间索引扩展为 `(organizationId, workspaceId, occurredAt, id)`，
并补 `(organizationId, occurredAt, id)`，支持两种查询范围和相同时间的稳定边界。
没有业务字段的破坏性更新，没有修改现有部署数据库，也没有创建迁移历史。
后续按已批准的数据库同步流程应用索引；大表建索引的锁和上线方式另行安排。

append-only 是公开能力约束，**不等于数据库防篡改**。拥有原生 client/SQL 权限仍能修改记录。
本次没有部署不可变触发器、独立数据库角色、保留周期、归档或审计日志外送。
