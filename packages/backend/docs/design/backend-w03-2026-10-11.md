# W03: 有限关闭与进程健康契约

实施日期：2026-10-11。接续 W01/W02；不包含 RT 竞争策略、S3 修复、Casdoor 可选配置或日志集成层替换。

## 已确认口径

用户确认默认预算为：Node 应用关闭总计 10 秒，HTTP 排空最多 5 秒，KVS 收尾 2 秒，最后预留 500 毫秒刷日志。
健康接口只报告 HTTP 进程存活和初始化/停止状态，不声称数据库、KVS 或外部提供商实时健康。
不新增或维护测试文件；本轮验证使用不落盘的隔离探针。

## 关闭路径

`bootstrap/lifecycle/shutdown.ts` 是进程入口的支持模块，不是通用 Lifecycle Kernel。

1. Bootstrap 创建应用后安装唯一一套 SIGTERM/SIGINT 处理器，不同时启用 Nest 的信号处理器。
2. 第一个信号同步将 HealthState 置为 stopping。重复信号复用同一个关闭 Promise，不重复清理或重置预算。
3. 先关闭 Fastify，停止接收新请求，排空正在执行的 HTTP 请求；空闲 keep-alive 连接直接关闭。
4. HTTP 排空超时则销毁剩余 HTTP/1 连接。关闭 socket 不等于取消业务函数或已发送到数据库的语句。
5. 调用 Nest 的 `close(signal)`，仍由 Nest 分派资源所属模块的生命周期 hooks。Nest 的公开接口类型没有 signal 参数，
   这里仅按其实际 NestApplicationContext.close 签名调用，不手工遍历 provider。
6. outbound HTTP factory 在 onModuleDestroy 取消在途/排队请求及凭据等待，销毁自己的 agents；KVS 在同一 hook 中限时排空。
   两者不依赖彼此的顺序。Prisma 改在 onApplicationShutdown 断开，使其晚于上述模块清理；查询和事务行为不变。
7. 在 Node 总预算内等待 Prisma 和其余 hooks。Prisma 没有伪造的强制取消 API：挂起 disconnect 会触发总预算失败，
   此时不能声称数据库清理已完成，最终由退出释放本进程资源。
8. 清理阶段最多使用总预算减去日志预留时间。之后刷新 Nest 日志缓冲和 Pino 的 request/out-of-context roots，
   刷新本身也有限时。正常停止退出 0；清理错误、预算耗尽或日志刷新失败退出 1。
   总预算 watchdog 为仍可调度的事件循环提供硬停止兜底；CPU 阻塞仍需外部进程管理器处置。

注册插件、初始化或监听失败时也使用同一关闭路径，再将原始启动错误交给入口处理。
没有给 WS/worker 添加假实现；将来真实接入时，需要在相应所属模块补充 drain。

### KVS

- 配置同时约束原生 socket connectTimeout 和整个连接/握手等待预算。
- 连接超时会 destroy，禁止继续重连并清除 pending commands；拒绝为类型化 `kvs.connect-timeout`。
- graceful close 超时会 destroy，拒绝 pending commands，记录 `kvs.close-timeout` 后允许其他 hooks 继续执行。
- 非预期关闭错误仍向上抛出。被主动销毁的命令错误 DisconnectsClientError 归为 KVS unavailable。
- destroy 可能同步使 Redis close Promise resolve；deadline 支持明确的过期标记，避免将强制清理误报为 graceful success。

### 容器信号

隔离 Linux 容器实测发现，原来的 runuser 在收到 SIGTERM 后约 2 秒就强杀子进程；2.5 秒 HTTP 排空尚未完成就被截断，退出 143。
入口改用镜像内现有的 setpriv，降权后直接 exec，node 用户、卷目录准备和 dotenvx 配置加载均保留。
替换后，相同排空过程、资源 hooks 和日志刷新均执行，退出 0；重复真实 SIGTERM 也仅执行一次清理。

Compose 的 stop_grace_period 为 15 秒，为 Node 的 10 秒预算及 dotenvx 包装程序退出留出余量。
独立 docker run/其他部署环境也应设置至少 15 秒的外部停止宽限时间；修改 Node 预算后应同步调整它。
没有停止、重启或修改用户正在使用的容器。

## 配置

| 环境变量               | 默认毫秒 | 所属配置  |
| ---------------------- | -------: | --------- |
| SHUTDOWN_TIMEOUT_MS    |    10000 | lifecycle |
| HTTP_DRAIN_TIMEOUT_MS  |     5000 | lifecycle |
| LOG_FLUSH_TIMEOUT_MS   |      500 | lifecycle |
| KVS_CONNECT_TIMEOUT_MS |     3000 | kvs       |
| KVS_CLOSE_TIMEOUT_MS   |     2000 | kvs       |

上述值必须是正整数。关闭总预算范围为 1000 至 120000 毫秒，两个 KVS 预算不超过 60000 毫秒。
HTTP 排空加日志预留必须严格小于总预算，给资源清理留下时间。KVS/Prisma 的实际剩余时间仍受进程总预算约束。
示例文件及开发、测试、生产运行环境文件（含现有 .local 文件）均已显式填写默认值，没有改变现有 env 打包策略或密钥挂载方式。

## 健康契约

通过 HealthModule 显式接入 composition。公开 schema 位于 `@talos-ark/contracts/system`，503 定义位于 backend SystemErrorDefinition。

| 路径                     | HTTP 状态 | 含义                                                                          |
| ------------------------ | --------- | ----------------------------------------------------------------------------- |
| GET /api/v1/health/live  | 200       | HTTP handler 可执行；data 为 `{ status: 'alive' }`                            |
| GET /api/v1/health/ready | 200       | 初始化和监听完成且未开始关闭；data 为 `{ status: 'ready', scope: 'process' }` |
| GET /api/v1/health/ready | 503       | 尚未就绪或已进入停止；错误码 SYS_NOT_READY，details 为 null                   |

两个接口均公开且跳过限流，使用现有 ApiRoute 的 OpenAPI、响应包络和运行时 schema 校验，不公开 ALS metadata。
停止状态不可再 markReady。启动失败通常不会留下可访问的监听端口；停止期间连接拒绝/断开也表示不能继续接收请求。
Dockerfile 与 Full Compose 都探测 ready；live 供只需要存活语义的部署使用。旧的 `/api/v1/health` 从未实现，不增加兼容别名。
这里没有 DB/KVS ping、Casdoor/SMTP/S3 远端探测；后续依赖健康应作为独立、有限时的契约设计。
