## 交付范围

P10 将 I08-A/B 的文件核心能力接入材料模块。材料模块只暴露 `material.attachment` 用途，服务端从材料事实解析真实 `resourceId`，客户端不能提交用途键或资源身份。每次上传会话操作、绑定、列表、下载和解绑都会重新经过材料资源的当前授权检查。

公共 HTTP 路由位于 `organization/:organizationId/workspace/:workspaceId/material`：

| 方法 | 路径 | 作用 |
| --- | --- | --- |
| POST | `:materialId/attachment/upload` | 创建单次或分片上传会话 |
| POST | `:materialId/attachment/upload/:sessionId/sign` | 获取单次或分片签名请求 |
| GET | `:materialId/attachment/upload/:sessionId` | 查询上传进度和已确认分片 |
| POST | `:materialId/attachment/upload/:sessionId/complete` | 完成并验证上传 |
| POST | `:materialId/attachment/upload/:sessionId/cancel` | 取消上传 |
| GET | `:materialId/attachment` | 分页读取有效附件 |
| POST | `:materialId/attachment` | 将已验证资产绑定到材料 |
| GET | `:materialId/attachment/:referenceId/download` | 创建短期下载请求 |
| POST | `:materialId/attachment/:referenceId/unbind` | 逻辑解绑附件 |

上传完成和材料绑定是两个独立操作。完成只产生上传者可用的未绑定资产，绑定成功后才成为材料附件。完成响应丢失时客户端应按原 `sessionId` 查询或重放；绑定使用原 `assetId`，不会因为网络不确定而自动新建上传。

## 契约与投影

公开 schema 位于 `packages/contract/src/material/attachment.ts`，错误定义位于 `attachment.error.ts` 与 `packages/contract/src/backend/material-attachment.error.ts`。公共投影只包含文件名、声明 MIME、字节数、创建时间、引用 ID、上传状态和签名请求；不返回 bucket、key、供应商 upload ID、租约、Prisma 行或内部错误详情。

文件用途白名单和 100 MiB 限制继续由 `MaterialFilePurposeProvider` 维护。当前白名单不包含 SVG、音视频、压缩包和可执行文件；真实类型识别和病毒扫描延期。

`FileUploadSnapshot` 增加文件名、声明类型、预期字节数及用途快照，支持前端恢复界面显示。材料服务在每个 session 路由中将会话用途资源与当前 URL 材料精确比较，防止跨材料复用上传会话。

## 错误边界

材料附件服务使用本地 `defineErrorMapper` 将文件核心的已知失败转换为 `material-attachment.*`：输入/分片/状态错误、不可用、冲突、过期、忙、未就绪、格式/大小限制、归档只读和资产已占用分别投影到公开错误。未知程序错误、存储异常和数据库 CHECK 错误保持技术错误，由 HTTP 边界按内部错误处理，不被润色成业务成功或可重试结果。

## 模块接入

`MaterialModule` 显式导入 `FileModule`，注册 `MaterialAttachmentService` 和 `MaterialAttachmentController`。组合根注册 `MaterialAttachmentErrorDefinition`，使 ApiRoute 能为成功响应与错误响应生成 OpenAPI 契约并执行响应校验。

绑定和解绑沿用 I08-B 的 `FileBindingService`：使用材料的当前读/更新授权，归档材料只读，单资产只允许一个有效材料引用，解绑保留历史引用并逻辑删除资产，不恢复上传者入口访问权。清理仍由受控维护入口执行，不在 P10 增加调度器。

## 收尾复查

补充回归验证覆盖：材料 URL 与上传会话用途/资源不一致时，在用途授权和文件准入前拒绝；进度查询将 URL 材料解析出的资源身份传入文件核心；取消操作重新授权后才锁定并重读会话，若锁等待期间已完成则不取消；技术性的 `transaction-active`、`unknown-purpose` 和 `purpose-not-ready` 保持原错误，不伪装为用户输入错误。返回短期签名 URL 的 `sign` 与 `download` HTTP 响应设置 `Cache-Control: no-store`，避免临时凭据进入缓存。
