## 执行边界

- 保留 runtime env，包括 `.env.development.local`、`.env.test.local`。这些明文开发配置仍可被镜像持有者读取，是用户明确接受的分发边界，不将其描述成无敏感信息。
- 排除解密密钥和整个 crypto 目录；公钥/证书也改为随该目录运行时挂载，保持配置中的路径不变。
- 暂缓删除或全面优化 formatter、env/schema、operation 和其他 crypto 工具；只迁移已用支持、移除无消费者总入口及重复空骨架。
- 不更改正常 HTTP 契约、认证策略、读取失败语义、KVS timeout 行为或中间件顺序。
- 不运行数据库同步/初始化、真实外部服务验收、凭据轮换或已有服务停止操作；不维护测试脚本。
- 执行中出现的用户前端改动及 `AppModule` Pino 展示配置改动原样保留，不作为本轮整改内容。

## W01：密钥打包与 CLI 脱敏

### 镜像与运行配置

- 根 `.dockerignore` 将 `.env.keys` 规则扩大到 `.env.keys*`，并排除 `packages/backend/secrets/crypto/`。
- Dockerfile 删除 crypto 的复制；保留原有 env 通配复制和合成 Prisma 构建 URL。
- Full Compose 保留 `/talos-ark/.env.keys` 只读挂载，新增 `/talos-ark/secrets/crypto` 只读挂载。
  两者均设 `create_host_path: false`，缺失宿主文件/目录时不自动创建错误的占位目录。
- entrypoint 无需改动：继续通过现有 dotenvx 命令和 `node` 用户启动；没有增加另一套密钥加载器。
- 运行要求已写入 [Docker 说明](../../ops/docker/README.md)：宿主路径存在、容器用户可读，非 Compose 启动者提供等价挂载。

运维变化：镜像不再独立携带 crypto 文件，运行者需要挂载。此项已在实施前告知。
现有镜像、凭据及运行中的容器没有被删除、轮换或重启。

### URL 脱敏

`tooling/database/environment.ts` 的 `redactDatabaseUrl` 只显示协议、经过密码脱敏的凭据、host 和 pathname。
query、fragment 不再进入日志；无效 URL 仍使用固定占位字符串，不返回原输入。
Prisma 实际收到的连接字符串没有改动。

## W02：实际依赖与职责清理

### 支持函数

| 原位置 | 当前归属 | 保留行为 |
| --- | --- | --- |
| `common/utils/helpers/file.helper.ts` | `config/internal/config-file.reader.ts` | cwd 相对读取、trim、失败返回空字符串 |
| `common/utils/helpers/auth-service.helper.ts` | `platform/http/credential.ts` | 原 Bearer 匹配和 Cookie 默认/自定义提取 |
| `crypto.helper.ts` 中的安全随机和 SHA-256 | `common/utils/crypto.ts` | 随机字节数校验、base64url、十六进制 SHA-256 |
| `async.operation.ts` 中的 timeout | `infra/kvs/kvs.timeout.ts` | 原超时计时、message、race 和 timer 清理 |

Access、Identity、HttpClient 直接导入轻量 crypto；AuthGuard 和 KVS 导入自己的支持文件。
保留的 crypto 工具复用同一 SHA-256 实现，原工具文件仍导出共享随机/hash，不复制实现。
`Simplify` 保留；其余工具实现不变，但不再通过 `common/utils/index.ts` 总桶进入运行路径。
KVS 超时仍不取消底层连接，此缺陷留在 W03，不以改路径伪装成已经解决。
Casdoor 必配/可选策略也没有改变。

### HTTP 与装配

- 三个 Middleware 拆成 `request-preprocessing.middleware.ts`、`request-scope.middleware.ts`、`cors.middleware.ts`。
- 两个 Interceptor 拆成 `performance.interceptor.ts`、`timeout.interceptor.ts`。
- 类名、日志上下文、方法体及装配顺序保留。ALS 仍在 Guard 之前由 Middleware 建立。
- AccessKernel 删除仅注入未使用的 KvsClient；AccessModule 只导入 PrismaModule。Identity 真实的 IAM/KVS 依赖没有删。

内部接口变化：AccessKernel 构造函数由三个参数变为两个，现有源码没有手动实例化调用方需要调整。
现有分页测试通过 prototype 构造模拟对象，也不使用该构造函数。

### 删除范围

- 无消费者的 `common/utils/index.ts` 总桶，以及迁移后的旧文件/函数实现。
- Common 的 `errors`、`result`、`assertions` 三个空入口。
- Platform 的 root、HTTP root、`http.types.ts`、Realtime root 四个空入口。
- `AuthenticationGuard`、`RequestContextInterceptor`、`TelemetryInterceptor` 三个重复空类。
- KVS `key/key.ts` 中无消费者的整份示例定义及顶层执行；实际 key-family 实现和业务 key 不变。

工作区、权限、幂等、扩展、WS/SSE 等其余规划骨架及已有 WS error adapter 保留。
没有用“暂时未使用”作为删除大部分 utils 的依据。

### Docker 验证与限制

- 使用与 Compose 相同的本地目录上下文方式，复制当前 `.dockerignore`，仅放置合成 env、密钥和 crypto 文件。
  构建产物的三个层逐层检查：五份获准 env 在上下文复制和 runtime 复制中均存在；密钥、备份和 crypto 文件均不存在。
- Compose 使用合成凭据解析通过；挂载位置、read-only 与禁止创建占位路径的设置符合预期。
- 借用本机已有镜像中的 Node/dotenvx，显式设置新 Dockerfile 的 `/talos-ark` 工作目录，验证合成文件的只读挂载、node 用户可读及现有 dotenvx 明文 profile 加载。此项不是完整新镜像构建或真实加密凭据启动验收。
- 实测预制 tar 直接作为 stdin 上下文时，本次目录过滤规则未生效，因此没有用该方式得出安全通过结论。
  目录过滤发生在客户端发送上下文前，参见 [Docker build context](https://docs.docker.com/build/concepts/context/#dockerignore-files)。手工分发 archive 的流程需要自行确保过滤，不应假定归档内的 `.dockerignore` 会替其删除文件。
- 本机两个既有 backend 镜像只读查看最终文件系统，未发现所检查位置的 `.env.keys` 或 PEM/key 私钥标头；其中一个仍含 PEM 文件。
  未审计这些历史镜像的所有层，也未核实远端分发范围，不能据此认定历史镜像从未包含秘密。
- 临时合成文件、探针镜像和临时容器在验证后清除；临时空目录的递归移除被执行策略拒绝，因此没有继续尝试删除。
