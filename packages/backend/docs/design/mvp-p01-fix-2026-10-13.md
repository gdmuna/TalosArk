# P01 Fix：来源策略、密码实现与事务边界

本文是 [P01 初次交付](mvp-p01-2026-10-13.md) 的后续修订；接口业务范围不扩大，最新实现以本文和源码为准。

## 本轮完成什么

1. HTTP CORS 与 Auth 共用一套显式浏览器来源策略，消除重复配置和空列表的相反语义。
2. 用 `argon2` 的 Argon2id/PHC 实现替换手写 scrypt 格式，分离密码准入与密码计算。
3. 将 Identity 私有凭据实现移入 `internal/`，由 Auth 编排 Identity 密码写入和 Access 会话处理。
4. 把首次设密的近期会话窗口改为自描述名称，不改变它的业务含义。
5. 保留并复验 OIDC state 严格匹配后才消费事务的修复。

不实现找回密码、邮件发送、前端页面或新的限流基础设施；Auth attempt limiter 与 Nest Throttler 的整合按用户要求留待后续讨论。

## 来源配置不再依赖空列表猜测

`http.browserOriginPolicy` 是判别联合，CORS 与 Auth 使用相同的纯判定函数。

| 模式 | 规则 | 环境限制 |
| --- | --- | --- |
| `deny` | 不信任任何浏览器 Origin | 所有环境；缺省值 |
| `allowlist` | 只接受非空列表中的精确 Origin，包括端口 | 生产列表必须 HTTPS |
| `development-loopback` | HTTP(S) 的 `localhost`、`127.0.0.1`、`[::1]`，不限端口 | 仅 `NODE_ENV=development` |
| `development-any` | 接受所有合法 HTTP(S) Origin，启动时警告 | 仅 `NODE_ENV=development` |

不支持任意字符串通配符；回环模式通过 URL 结构检查主机，不接受 `localhost.evil.test`、带凭据/路径的 URL 或 `Origin: null`。列表要求浏览器实际发送的规范 Origin，不带尾部 `/`。
开发宽松模式不能在 test/production 启动。所有来源均不允许 opaque/null Origin；Tauri 等载体的独立方案仍属 P03。

`CORS_ENABLED=false` 仅关闭 CORS 协议处理，**不会关闭 Auth 的 Origin 和 `X-TalosArk-Client: browser` 检查**。
无 Origin 的服务端普通请求可以继续通过 CORS middleware，但不会得到 `Access-Control-Allow-Origin: *` 或凭据授权；Auth 写入口仍拒绝无 Origin。
允许来源时回显具体 Origin 并允许 credentials。`Vary: Origin` 与既有 Vary 合并，不覆盖其他缓存维度；拒绝响应也设置 Vary/no-store。

本地任意端口是开发便利，并不表示回环地址上的其他应用永远可信。需要更严格隔离时改用 allowlist；development-any 更宽松，只适合受控开发。
此策略只决定浏览器请求信任，不修改 Casdoor 的已登记 redirect URI、前端 OIDC redirect 配置或激活链接 URL；改变端口时仍需分别核对它们。

## 密码计算与准入分开

依赖固定为 `argon2@0.45.1`、`@phc/format@1.0.0`；显式批准 argon2 的 pnpm 构建。直接声明 PHC parser，避免隐含依赖其传递安装。
[node-argon2](https://github.com/ranisalt/node-argon2) 提供参考实现的绑定、随机 salt、PHC 编码和验证，本项目不手写 KDF 或编码比较。
参数：Argon2id/version 19，memory 65536 KiB、time 3、parallelism 1、salt 16 byte、hash 32 byte。选择遵循 [OWASP 的 Argon2id 方向](https://cheatsheetseries.owasp.org/cheatsheets/Password_Storage_Cheat_Sheet.html)，不把参数或本轮验证声称为合规认证。

- 输入仍为 15-128 Unicode code point；允许空格，不 trim、不改大小写。HTTP 与 Core 使用同一中立长度 schema。
- policy 保留全空白及原有五项明显可预测密码的拒绝；这不是完善的泄露密码库。补充大型泄露名单应另行设计，不在本轮隐式接入外部服务。
- hasher 只负责计算，不把新密码策略套到登录验证。PHC 先经结构化 parser 检查算法、版本、参数和长度，避免损坏数据库记录触发任意高成本计算。
- 目前只接受上面这一套 PHC profile；旧 scrypt、未知 profile、损坏 hash、无密码账户都执行同参数 dummy Argon2 验证并失败，不猜测兼容。未来调参需显式定义可接受的历史 profile，不能只改生成参数。
- dummy hash 在 Nest 初始化时等待生成；生成失败阻止初始化。默认最多两个并发 KDF，超限返回有限重试的 login-unavailable，不无限排队；原生计算异常保留 cause，由现有错误体系处理。
- 两个并发任务的 Argon2 工作内存约 128 MiB，另有运行时开销；该容量为单进程限制，不是集群总配额。需在部署资源下再作压力验证。

## 事务边界

Auth 在进入事务前调用 `IdentityKernel.preparePassword`。返回空对象形态的 opaque 引用；hash 存于 Identity 私有 WeakMap，不作为公开属性、日志、序列化结果或 HTTP 字段传递。伪造或来自其他运行实例的引用被拒绝。

激活：预计算 -> Auth ReadCommitted 事务 -> Identity 锁 User、校验并消费激活凭据、写密码/撤销其他激活和恢复凭据 -> Access 撤销未撤销会话 -> 提交。

OIDC-only 首次设密：预计算 -> Auth ReadCommitted 事务 -> User 锁 -> Access 校验并锁近期 Session -> Identity 校验绑定/无密码并写凭据 -> Access 撤销旧会话 -> Access 签发新会话 -> 提交。

Identity 的密码写入口要求 mandatory ambient transaction；不自行提交半个业务流程。Identity 不再直接操作 Session 表；Access 不重写已经撤销的会话时间。任一步失败整体回滚。昂贵 KDF 不占用这段数据库事务或行锁。
登录仍是先验证密码，再在签发事务中复核密码指纹，避免并发改密后使用旧验证结果签发；W05 轮转与旧 AT 生命周期规则未改。

## OIDC state 修复状态

KVS Lua 用 `HGET(key, field)` 检查明确指定的 `state` 字段，然后读取整个 Hash；只有严格等于 expectedValue 才删除 key。不是遍历所有字段去猜匹配。
不匹配时保持 Hash 和字段 TTL；有效 state 的并发消费者只有一个成功。匹配后仍先消费，再调用提供商；换码失败不恢复旧事务。
内部诊断只记录缺失/不完整/格式异常/不匹配的有限 operation，不输出 code、完整 state、Cookie 或其他凭据。
先前正常工况下的偶发提供商失败尚未真实复现，不能把条件消费修复等同于已证明编码问题的根因。
