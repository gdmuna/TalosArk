# W04: 部署与文档工具链对齐

实施日期：2026-10-11。接续 W01/W02/W03，不包含认证生命周期、S3 协议、业务 Schema 初始化或 Casdoor 可选配置。

## 交付路径

```text
同一源码构建的 backend 镜像 digest
    -> 一次性 PostgreSQL / Valkey + 合成运行配置
    -> 正常初始化后的 /api-doc-json
    -> packages/backend/scripts/generate-openapi.ts
    -> packages/docsite/api-reference/openapi.json
    -> GitHub artifact / 本地规范源文件
    -> docsite/script/prepare-api-reference.mjs
    -> docsite/docs/public/api-reference/
    -> VitePress dist/api-reference/
    -> nginx /api-reference/ + /api-reference/openapi.json
```

导出器接受 BACKEND_URL，使用 30 秒请求期限，检查最小 OpenAPI 3 结构后原子替换源文件。
网络、HTTP、JSON 或结构检查失败时不覆盖上一份规范；终端错误不打印 URL 凭据或 query。
docs:gen-openapi 不再依赖后端运行环境的 dotenvx 解密。docs:dev 调用实际 docsite 包。

docsite 默认在 dev/build 前准备 Scalar 页面和规范。规范源及生成公开目录不进 Git，
缺少或无效的规范阻止本地参考文档构建。外部 API 文档模式只移除自己生成的两个文件，避免缓存残留被发布。
Scalar 使用相对路径 ./openapi.json；nginx 对缺失规范返回 404，不回退成首页 HTML。
/api-reference 重定向到带尾斜杠路径，不泄露 nginx 容器端口。

## 镜像与 CD

- backend 与 docsite Dockerfile 均使用根 packageManager 指定的 pnpm 和 frozen lockfile。
  修正旧 backend/docsite 路径、包名和构建产物路径，不新增另一套构建系统。
- backend runner 接收现有 CD 的 APP_VERSION/GIT_COMMIT 构建参数；生产版本和 commit 取自实际 checkout。
- 开发与生产 CD 都从刚构建镜像的 digest 导出规范，不读取移动中的 latest tag。
  上传、下载 artifact 均使用 docsite/api-reference/openapi.json。
- ops/docker/ci/export-openapi.sh 是实际交付脚本，不是持久化测试脚本。
  使用独立 Docker network、一次性依赖和合成密钥；不发布端口，不调用真实身份提供商、不执行业务 DDL。
  导出时直接启动编译入口，不使用镜像中的运行 profile，也不需要真实 DOTENV_PRIVATE_KEY。
  成功、失败和停止信号均清理自己创建的容器、依赖匿名卷、网络和临时密钥文件。
- 生产文档镜像必须先取得规范。开发镜像保留原先的外部 Apifox 地址默认值；
  可将 VITE_API_REFERENCE_URL 构建参数设置为 /api-reference/ 使用本地规范。
- docsite Docker 构建只复制其自身源码、包清单和工作区安装元数据，不复制 backend/env/crypto/.git。
  不含 Git 元数据的构建不生成页面提交时间，避免 lastUpdated 导致缺少 git 的构建失败。

现有 registry 推送、Watchtower 通知和 Apifox 同步流程保留，本轮没有实际触发这些远端操作。

## 部署契约

Full Compose 中 Casdoor 的 target 为 8000，与 app.conf 和探针一致；宿主端口仍由 CASDOOR_PORT 控制。
该端口修正已包含在工作树中，本轮基于其现值完成验收。
backend 显式设置 PORT=3000，使监听端口、Docker/Compose 探针和发布 target 保持一致。

W01 的密钥/crypto 构建排除、运行时只读挂载和获准 env 打包策略保留。
W03 的进程级 ready 探针、entrypoint 信号转发、10 秒 Node 关闭预算与 15 秒 Compose 宽限保留。
Full Compose 验收另行使用正常 dotenvx CMD 与合成运行 profile，并不以导出器绕过 profile 的成功替代部署验收。

Casdoor 当前仍为启动必配；F9 的必配/可选策略没有在本轮静默改变。
容器间 URL、宿主 URL 和浏览器 OIDC 回跳 URL 的用途已在运行说明中区分。

## 文档校正

更新 backend README/CONTEXT、Docker 运行说明及 docsite 的中英文项目状态/运行与交付页。
导航只指向实际存在的页面，编辑链接使用 docsite/docs 路径。
说明现有 Auth/OIDC、健康、契约与 Adapter 的实现边界，公开 refresh/logout 仍为未实现，
不能从业务目录、模型或接口占位推断软件 MVP 已完成。
CONTEXT 区分真实路径、计划归属与尚未实现的 observability/queue 等能力。

VITE_BASE_PATH 默认 /，当前 nginx 镜像服务根目录；子路径部署需要代理剥离前缀。
完整子路径代理部署没有在本轮验收，不能只凭 Scalar 使用相对 URL 就声称已验证。
