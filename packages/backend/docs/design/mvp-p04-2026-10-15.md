# P04：真实组织与工作区

实施日期：2026-10-14 至 2026-10-15。P04 已实现并完成隔离验证；不代表 P05/P06 或整个团队阶段已验收。

## 本轮确定的范围

- 所有已登录的有效账户可以创建组织；账户仍由邀请/受控运维产生，不开放注册。
- 用户填写组织名和首个工作区名，组织、初始成员、初始角色绑定、工作区和两条审计一起提交。
- P04 仅允许组织创建者创建工作区，且必须仍是有效组织成员并拥有实际创建授权。
- 进入工作区必须同时满足组织/工作区未归档、两个成员关系有效、组织读授权及工作区读授权。
- 邀请、成员管理、角色管理、所有者交接、Discovery 和 Casbin 装配仍分别留给 P05/P06；没有临时匿名管理入口。

沿用现有模型：名称是展示标签，不是唯一身份，允许同名；关联和隔离使用 UUID。名称去首尾空格、限制 1–40 个 UTF-16 单元，并拒绝控制字符/不完整代理字符。HTTP 路径 UUID 统一转为小写，避免数据库匹配正确但应用字符串比较失败。

## 模块分工

| 所有者 | 本轮职责 |
| --- | --- |
| `contract/src/team` | 组织/工作区请求、公开列表与创建结果、公开拒绝契约；没有 ORM/Nest 类型 |
| `core/tenant` | 核对真实账户、有效组织成员，返回只读租户成员快照 |
| `core/permission` | 从有效成员、未归档角色和正确 scope 的数据库绑定查询 allow-only 授权；不根据角色名字自动放行 |
| `core/workspace` | 校验工作区属于指定组织、有效成员和目标权限，返回只读操作上下文 |
| `modules/organization/application` | 编排原子建组织、初始组织角色/成员、工作区公开能力及审计；组合当前可访问快照 |
| `modules/workspace/application` | 创建工作区、初始工作区成员/绑定、审计，以及验证当前上下文 |
| `bootstrap/composition` | 显式导入组织模块并注册错误定义；不扫描文件或启动时写业务目录 |
| 前端 `module/workspace` | HTTP 适配、真实列表、创建、已提交写入的同步恢复、可取消的切换 |

首批实际权限为 `organization.read`、`workspace.create`、`workspace.read`。组织创建流程显式建立前两个权限和组织初始角色；首次工作区创建建立工作区读权限及工作区初始角色。权限目录不是 Discovery 机制，也不是整个 P06 的可配置角色体系。

组织初始角色与工作区初始角色分别使用 `ORGANIZATION`、`WORKSPACE` scope。组织所有者也必须具有目标工作区的有效成员关系和授权；组织管理角色不会隐式授予所有工作区的进入权。错误 scope、角色归档、授权撤销、成员失效均不能借旧 AT 绕过。

当前执行方式是最小的数据库授权查询。P05 的定义收集/冻结、P06 的权限执行方式及 Casdoor/Casbin 整合尚未完成；本轮不宣称已实现通用权限引擎或远程策略同步。

## HTTP 接口

共同前缀：`/api/v1`。全部要求验证过的 AT，业务演员来自服务端请求上下文，不接受 body 中的 userId。

| 方法与路径 | 结果 |
| --- | --- |
| `POST /organization` | 201，原子创建组织和首个工作区 |
| `GET /organization` | 200，当前有效成员可读取的组织 |
| `GET /organization/context` | 200，当前可读取的组织与工作区快照 |
| `POST /organization/:organizationId/workspace` | 201，新增工作区和创建者的初始成员关系 |
| `GET /organization/:organizationId/workspace/:workspaceId/context` | 200，校验目标上下文后返回工作区公开投影 |

响应设置 `Cache-Control: no-store`。`ApiRoute` 统一验证输入及成功/失败包络；非法输入返回 400，无认证返回 401，未知/不匹配/无权进入的上下文统一返回 403 `TEAM_ACCESS_DENIED`，不借不同错误暴露其他租户的对象。

读快照/上下文使用 RepeatableRead 事务。管理写入使用现有 DatabaseRuntime 的 required 事务与 `queryClient`；组织创建复用工作区公开能力并加入同一个物理事务。AuditKernel 使用 mandatory 加入，审计失败不能留下部分成员、角色或工作区。数据库/编程错误不润色成业务拒绝。

审计动作只有 `organization.create`、`workspace.create`。字段白名单为对应对象的 ID/name，另带验证过的 actor、组织/工作区、发生时间和 requestId；不记录密码、凭据、整个请求或内部角色实体。管理对象没有为审计强行变成 Resource。审计读取页面没有在本轮启用。

## 前端行为

- 主入口显式选择真实 account/workspace HTTP 数据源，不回退 mock。
- 无工作区账户可直接新建组织；切换器和管理工作区页面复用模块内创建弹窗。真实数据源不提供邀请码加入，保留的 mock 适配器仍可使用原功能。
- 切换先由服务端验证目标，再更新活动工作区。仅本地选择不是授权；后续业务请求仍须独立验证上下文。
- 活动工作区变化使旧工作区/工作台操作作用域失效；旧读取、切换或写入返回不能污染新上下文。退出/换账户沿用 P03 的全量业务状态清理。
- 创建提交成功但列表重读失败，保留待同步提示并暂停进一步写入。重新同步只 GET，不重放 POST。显式选择旧工作区可以改变恢复后的选择意图，但不能清除待同步状态。
- 关闭、重开或切换创建表单类型会更新表单代次，旧提交结果不能关闭新表单或写入新表单的错误。提交中输入禁用。
- 刷新/重开从服务端重新取得授权列表，当前版本选择首个可访问工作区；没有持久化工作区偏好，也没有服务端“全局当前工作区”。
- 只显示实际已接入字段；工作区列表不伪造负责人、成员数、资源数。工作台业务尚无真实数据源时显示暂不可用，不把未加载空数组的 0 当真实统计。mock 工作台在显式加载后仍可使用。
