# P09 真实入库与带存量搬迁交付记录

日期：2026-10-19。范围依据：[业务对齐](../../../../docs/product/mvp-p09-alignment-2026-10-19.md)、[实施方案](../../../../docs/product/mvp-p09-plan-2026-10-19.md)。

后端批次维护、单件入库、库存和流水读取、实物资料更正、同组织带存量容器搬迁已实现。test.local 的真实数据库及合成 HTTP 验证通过；前端页面、真实登录 Web 闭环和 Tauri 尚未验收。P09 不能标记为四页面闭环全部完成。

## 1. 这次实际交付

Material 增加 `quantityScale`，0～6、默认 6；有实例后，数量精度、单位和业务分支均冻结。数量使用精确十进制字符串，不经 JS number、不舍入；公开响应固定六位小数。尾随零不导致合法输入被误拒绝。

批次属于一种材料，不是一次入库。同材料批号唯一，支持资料维护、revision 冲突检查、归档和恢复；不存在按批号自动覆盖。入库可不选批次、选择已有批次或明确新建。批次的生产/有效期只作为表单默认值，后端保存本件实物提交确认的最终日期，不动态继承。

一次提交登记一件实物，必须选实际存在、可使用且空闲的 POSITION。系统生成 `INS-` 前缀随机编号，也允许事先指定；编号工作区内唯一，创建后不可改。零量合法，生成 `DEPLETED` 库存和真实 RECEIPT 流水，仍保留位置占用。过期不是持久化 StockStatus；过期登记须明确确认。

资料更正采用完整资料输入，不是局部 PATCH：省略可选字段会应用契约默认值。必须携带当前 `expectedRevision` 和原因；仅改标签、备注、生产/有效期、到货日和开封时间，不接受数量、位置、材料/批次归属或编号字段。初始量、已提交流水不重写。

Material/批次归档禁止新入库，不删除已有实物、库存和占位。归档材料、零量及过期实物仍参与合法的整容器搬迁。单件领用、归还、转移、调整、释放位置和错误入库撤销留到 P11；多件入库留到 P13。

## 2. 日期与配置

`manufacturedOn`、`receivedOn` 和有效期为真实日历日期 `YYYY-MM-DD`；`openedAt` 为带时区 ISO 时刻。有效期为严格判别联合：

```json
{ "kind": "UNKNOWN" }
```

```json
{ "kind": "NONE" }
```

```json
{ "kind": "DATED", "date": "2030-01-01" }
```

UNKNOWN 不等于永久有效。DATED 的到期当天仍有效；按服务端业务时区次日才过期。非法日历、生产日期晚于有效期、实例生产/到货/开封时间在未来等输入拒绝。不推导开封后有效期，也不假设历史实物必然先到货再开封。

`INVENTORY_BUSINESS_TIME_ZONE` 是可选字符串配置，默认 `Asia/Shanghai`，由 `inventory.config.ts` 在启动时通过 Intl 校验，typed config 注入 `InventoryCalendar`。它只控制业务日期/风险判断，不改变历史日期或数据库时刻。已将默认值写入 example 及五份实际应用 env；Prisma-only env 不增加无消费者配置。读取 `inventory/context` 可获得 `businessDate` 和 `timeZone`，客户端不要另用本地时区推翻服务端风险结论。

## 3. 依赖、权限与旧组织初始化

依赖方向为 `Inventory -> Material(public) + Facility(public) + Core`，没有反向模块循环。MaterialReceiptSource 是显式的跨模块读取/事务内批次创建入口；FacilityRelocation 承载设施授权、结构准备与原生树移动。结构坐标规则收敛在 Facility 内部，普通结构移动与带存量搬迁共享它，但保留不同的占用和生命周期规则。

| 权限 | Scope | 实际用途 |
| --- | --- | --- |
| material.read | WORKSPACE | 批次读取；库存操作的附加前提 |
| material.batch.manage | WORKSPACE | 批次新建、维护和归档；入库内联新建亦需此权 |
| inventory.read | WORKSPACE | 库存、实物、流水和操作回执 |
| inventory.receive | WORKSPACE | 单件入库 |
| inventory.instance.update | WORKSPACE | 描述资料更正 |
| inventory.transfer | WORKSPACE | 本轮带存量容器搬迁，不代表已开放 P11 单件转移 |

组织/工作区有效成员资格仍由现有授权内核验证；库存变更还须 inventory.read 和 material.read。入库位置须真实设施关系及 facility.use，搬迁另需来源/目标结构管理资格和全部受影响工作区授权。

新组织的 workspace-manager 默认定义包含上述能力。**已有组织不会在启动、查询或登录时自动加权**：组织所有者显式调用 `POST /organization/:organizationId/inventory/initialize`，仅为有效的已有 workspace-manager 角色补齐本轮权限并留审计；重复调用返回 `updated=false`。其他自定义角色通过 P06 显式授予，不能把角色名字当授权依据。

库存读取不等于设施读取。无 facility.read 或现有设施关系不可见时，仍可读取已授权的本工作区库存，返回 `location=null`、`locationRestricted=true`，不能显示为“未存放”。StockItem/MaterialInstance/MaterialBatch 的 Resource Provider 根据真实归属和当前权限返回描述，不信任调用方随意携带的 workspaceId。

## 4. 单件入库与幂等

OrganizationWriteKernel 先取得组织写锁，再重新授权；实例、资源身份、StockItem、Placement、流水、审计和幂等完成均参加同一物理事务。FacilityPositionReader 是观察而非预留，提交时重新校验生命周期和位置；唯一约束保底处理位置竞争。

InventoryOperation 是 Inventory 私有的业务幂等适配，不是新的全局任务表。复用 I07：入库采用 workspace 作用域，整容器搬迁采用 organization-user 作用域。operation 参与规范化请求指纹，不形成另一个键命名空间。执行人来自受信 ALS；自动编号及服务端时间在首次 claim 后确定。

同键同内容返回同一小型操作回执，同键不同内容冲突；失败全部回滚，不占住键。资源、审计、幂等完成或结构更新后置失败均不能提交半次成功。成功但响应丢失时以同键重试或查 operation 确认，不能换键盲目再登记。重放重新鉴权，但不重新要求旧位置为空、旧批次仍活动。已完成而回执缺失/损坏时返回 `INVENTORY_RESULT_UNAVAILABLE`，不重新执行。

入库示例，所有 UUID 均应替换为当前有权资源：

```json
{
  "materialId": "00000000-0000-4000-8000-000000000001",
  "quantity": "200.125",
  "batch": { "kind": "none" },
  "manufacturedOn": "2026-01-01",
  "expiry": { "kind": "DATED", "date": "2030-01-01" },
  "receivedOn": "2026-10-01",
  "openedAt": null,
  "label": "实验室现有存量",
  "notes": "按首次登记时实存量记录",
  "position": {
    "facilityId": "00000000-0000-4000-8000-000000000002",
    "topologyId": "00000000-0000-4000-8000-000000000003",
    "nodeId": "00000000-0000-4000-8000-000000000004"
  },
  "confirmExpired": false,
  "idempotencyKey": "p09-receipt-example-1"
}
```

已有批次输入为 `{kind:'existing', id, expectedRevision}`；新建为 `{kind:'create', value: BatchWrite}`。实例日期必须发送最终确认值，不能只传批次 ID 然后期待服务端动态继承。资料编辑表单须保留材料的 quantityScale，不能省略后把既有非默认精度误写为 6。

## 5. 同组织带存量容器搬迁

先调用 preview，只有全部授权通过才返回影响集合、来源/目标路径、治理工作区和共享工作区。执行提交相同结构输入、`expectedFingerprint`、`confirmGovernanceChange=true`、原因和幂等键。

执行在组织锁内按稳定顺序锁来源/目标拓扑，重查当前来源/目标管理权、每个实际库存工作区的有效成员和 inventory.read/transfer/material.read，以及目标设施对这些工作区的准入关系。组织所有者不豁免。预览不是授权令牌；结构、设施关系、实物修订或库存版本变化会使旧确认失效。

迁移保持节点及资源 ID、实例/库存身份、数量、状态、保管人和库存工作区归属不变；Placement 继续指向同一个孔位。改变的是节点拓扑、路径及设施治理上下文；StockItem.version 推进。按真实工作区分别生成 CONTAINER_RELOCATION 流水，历史路径保存当时设施/节点名称和编号，不按现位置重解释历史。所有工作区流水、结构和审计一起提交或回滚。

普通 P08 结构移动仍拒绝任何带占用子树；空容器使用原 P08 接口。本轮同步搬迁上限为 10,000 个结构节点、1,000 件已占位实物，超出明确拒绝，不悄悄拆批。这是防护上限，不是已完成千件或万节点性能基准。

## 6. 前端接口交接

公开契约来自 `@talos-ark/contracts/material`、`@talos-ark/contracts/inventory`，错误协议来自 `@talos-ark/contracts/backend`。沿用 ApiRoute + HTTP Method；输入、成功包络按 Zod 校验，读响应 no-store。应用层显式投影公开字段，不直接返回 Prisma 行。

工作区前缀 `W = /organization/:organizationId/workspace/:workspaceId`：

| Method / 路径 | 输入 | 成功状态 / data |
| --- | --- | --- |
| GET W/material/:materialId/batch | BatchQuerySchema | 200 / BatchPageSchema |
| GET W/material/:materialId/batch/:batchId | 路径参数 | 200 / BatchSchema |
| POST W/material/:materialId/batch | BatchWriteSchema | 201 / BatchSchema |
| PATCH W/material/:materialId/batch/:batchId | BatchUpdateSchema | 200 / BatchSchema |
| POST W/material/:materialId/batch/:batchId/archive | BatchArchiveSchema | 201 / BatchSchema |
| GET W/inventory/context | 路径参数 | 200 / InventoryContextSchema |
| GET W/inventory | InventoryQuerySchema | 200 / StockPageSchema |
| POST W/inventory/receipt | ReceiptSchema | 201 / OperationReceiptSchema |
| GET W/inventory/:stockItemId | 路径参数 | 200 / StockSchema |
| PATCH W/inventory/:stockItemId/facts | InstanceCorrectionSchema | 200 / StockSchema |
| GET W/inventory/transaction | InventoryQuerySchema | 200 / TransactionPageSchema |
| GET W/inventory/transaction/:transactionId | 路径参数 | 200 / TransactionSchema |

组织前缀 `O = /organization/:organizationId/inventory`：

| Method / 路径 | 输入 | 成功状态 / data |
| --- | --- | --- |
| POST O/initialize | 组织参数 | 200 / {updated:boolean} |
| POST O/container-relocation/preview | RelocationSchema | 200 / RelocationPreviewSchema |
| POST O/container-relocation | RelocationExecuteSchema | 201 / OperationReceiptSchema |
| GET O/operation/:operationId | 路径参数 | 200 / OperationReceiptSchema |

Stock 列表每行是一件实物，包含材料/批次、初始量/当前量、库存状态、资料 revision、库存 version、expiryRisk、当前可见位置和 capability。page 默认 1、pageSize 默认 10、最大 100。支持 q/materialId/batchId/nodeId/stockItemId/operationId/status/expiryRisk；库存与流水均稳定排序。流水不接受 status/expiryRisk 当前状态过滤，q 在流水中匹配实例编号。nodeId 在流水中匹配事件的来源或目标位置，历史路径与当前位置区分。

回执只含 operationId、kind 和可选实体 ID，不塞入整个库存或全部流水。入库后可凭 stockItemId 查实物，凭 operationId 过滤本工作区流水；搬迁后刷新设施树、相关库存和流水。搬迁前必须展示治理范围变化，不能只显示“修改父节点”。

错误明确区分：不可见/无权、revision 或幂等冲突、编号/批号冲突、位置占用、生命周期不允许、过期未确认和超限。Material/Facility 原有错误仍沿各自契约返回。未知数据库、CHECK 或程序错误不包装为用户填错表单，交给现有内部错误边界；不公开 metadata、数据库详情或堆栈。

审计只记录白名单事实。批次和实物的自由备注保存 SHA-256 摘要，不把全文或完整实体塞入有体积上限的 Audit；因此审计能确认备注变化，不能还原备注旧全文。位置完整路径由库存流水保存，审计保留必要 ID。

## 7. 数据库实际变更

Prisma 模型已增加 Material.quantityScale、MaterialExpiryKind、批次/实例日历日期和 revision、InventoryOperation、流水 operationId 和历史设施/拓扑 ID，以及 CONTAINER_RELOCATION 类型。批次旧 manufacturedAt/expiresAt、实例旧 expiresAt、流水头旧 idempotencyKey/requestHash 已移除；这是已批准的快速迭代破坏性模型调整，不提供旧时间戳含义猜测或自动回填。

执行前确认目标是 `talos-ark_backend_test`，Material、MaterialBatch、MaterialInstance、StockItem、Placement、InventoryTransaction 六张受影响表均为空。随后仅应用 P09 定向差异与 `prisma/ddl/schema/inventory.sql`，没有全仓 db push，没有同步并行 I08 文件结构，没有操作 dev/prod。

inventory.sql 提供数量精度、非负数量、日期三态一致性及 operation 作用域 CHECK；它不是业务表创建或旧数据迁移脚本。新建/可重建数据库按照 DDL README 的 init → Schema 同步 → schema DDL 顺序准备，并执行新增命令：

```powershell
pnpm --filter @talos-ark/backend db:apply-inventory-ddl --env test.local
```

其他已有环境尚未同步。对有历史存量的数据库，必须另行审查数据处理，不能直接把本地空表操作当成生产升级方案。
