# I06 存储拓扑、分页与数量技术支撑

实施日期：2026-10-18。支持 P08/P09，不代表这两个业务切片已经完成。

## 交付边界

本轮实现三项能力：受管事务中的节点创建/移动、参数化树查询与游标分页、库存数量的精确表示。
物理存储拓扑仍属于 Facility；`infra/storage` 是对象存储，二者不合并，也不新增 `core/storage`。

- Facility 私有 persistence 拥有 SQL、游标与输入校验。DatabaseRuntime 不认识设施业务。
- `FacilityModule` 对外导出 `FacilityStorageTopologyReader` 和 `FacilityStorageTopologyWriter` 两个 DI 端口，使用 `useExisting` 指向私有实现，不增加转发服务。
- AppModule 注册 FacilityModule，但没有新增 Controller、启动查询或业务写入。
- 其他业务模块显式导入 FacilityModule，消费公开端口；不得导入私有 SQL。
- 通用后台任务基础设施不依赖 Facility。设施任务由业务所有者注册 Handler，再由 Handler 使用这些能力。
- 没有新增权限表、节点继承规则、自动位置分配、库存执行或后台调度。

## 公开接口

入口为 `src/modules/facility/index.ts`，主要方法如下：

| 端口 | 方法 | 结果 |
| --- | --- | --- |
| Reader | `findNode` | 当前范围内的单节点事实，不可见或不存在时返回 null |
| Reader | `listChildren` | 直接子节点，parentId 为 null 时读取根节点 |
| Reader | `listDescendants` | 指定根节点的后代，不包含根节点本身 |
| Reader | `listAncestors` | 祖先从浅到深，不包含目标本身，只返回当前范围内的祖先 |
| Writer | `create` | 在当前事务创建节点，路径由数据库触发器产生 |
| Writer | `move` | 在当前事务移动节点及整个子树 |

Reader 的每次调用都是一条参数化 SQL，没有 N+1 查询。返回事实包含 path 文本，但不直接作为 HTTP 响应契约。
本轮使用 `Prisma.sql`、绑定参数与显式结果类型，没有引入 TypedSQL 生成流程，也不要求构建时连接数据库。

### 调用示例

下面是已获授权的业务编排片段，不是新的公开 HTTP 接口：

```ts
await this.database.transaction.run(async () => {
    // 此前已在本事务解析实际归属、检查权限并创建关联的 ResourceIdentity。
    await this.topologyWriter.create({
        id: nodeId,
        organizationId,
        topologyId,
        resourceId,
        parentId,
        code: 'BOX-01',
        name: 'Box 01',
        kind: 'CONTAINER',
    });
    // 业务审计也在本事务内记录；失败时节点和身份一起回滚。
});

const page = await this.topologyReader.listChildren({
    organizationId,
    topologyId,
    parentId,
    scope: authorizedReadScope,
    limit: 50,
});
```

Writer 只接受已有的活动受管事务，使用 `mandatory`，不自行开启根事务或独立事务。
输入校验也在 mandatory 回调中执行，因此调用方捕获写入失败后不能继续提交一个部分成功的业务事务。
原生错误交给现有 managed query 统一处理，不在 Facility 再造一层 normalize/execute 包装。
已有 DDL 的拓扑锁、禁止循环/跨拓扑、POSITION 不能作为父节点、延迟路径约束全部保留。
移动不重写库存历史路径快照；死锁/序列化失败由业务决定是否整体重试，Writer 不自动重试。

## 查询范围不是授权凭证

每次读取都必须传 `StorageNodeScope`，没有“省略则全量”的默认值：

- `none`：SQL 恒假，不能退化为不限制。
- `topology`：指定组织和拓扑的读取上限。
- `subtree`：同一组织/拓扑内，最多 200 个根节点的子树并集；空集合为空范围。

该类型是调用方已确定的 SQL 读取上限，不表示“传了这个对象就完成鉴权”。
客户端不能直接决定 scope。P08 的编排层仍需读取当前成员关系、设施使用关系和权限，再构造它。
读取限制在 WHERE 中与请求组织、拓扑、节点未归档、拓扑未归档、设施未归档取交集，随后才分页。
跨组织/跨拓扑的请求和范围不会互相扩权。

子树根保存 ID 而不是缓存的路径；每次 SQL 解析根节点的当前路径，移动后不沿用旧路径字符串。
子树查询不包含根节点本身；若根已归档或不存在，就不产生可见范围。
查询锚点本身不必可见：后代和直接子节点仍逐行取范围交集；祖先查询则先要求目标可见，再逐个过滤祖先，避免泄露不可见名称。

这不是权限继承实现。没有停止继承、显式 Deny、节点授权关系表，也没有从工作区权限猜测设施权限。
日后若支持停止继承及更深层直接授权，需要 I04 产出同口径的有限范围计划，再扩展此 SQL；不能把当前子树并集误称为完整 ReBAC。
要求权限与数据使用同一快照时，由业务把授权和 Reader 放进同一个合适隔离级别的受管事务；Reader 不悄悄开启独立事务。

## 分页与索引

- 页大小默认 50，最大 100；读取 limit + 1 项决定 hasNextPage，不使用 OFFSET。
- 子节点按 `(sortOrder ASC, id ASC)` 排序，游标保存这两个键。
- 后代按原生 `(path ASC, id ASC)` 排序，不按路径文本的数据库排序规则排序。
- 后代游标只保存节点 ID，在同一 SQL 中解析该节点当前路径；游标长度不随树深度增长。
- 游标携带版本、查询类型和查询指纹。组织、拓扑、规范化范围、parentId/rootNodeId 不匹配时拒绝复用；长度最多 512 字符。
- 游标是未签名的分页位置，不是授权 token；即使被重编码，每次查询仍执行完整的范围条件。
- 稳定数据下使用唯一 ID 兜底。并发移动、调整 sortOrder 或授权变化时不承诺跨页一致快照，应刷新列表；后代游标锚点被硬删除时返回空页，客户端重新读取首页。

Schema 将子节点索引补为 `(organizationId, topologyId, parentId, sortOrder, id)`，名称为 `StorageNode_children_page_idx`。
继续使用 `StorageNode_path_gist` 支持树范围；不新增可能被长路径撑爆的全路径 B-tree。
后代范围查询仍可能需要排序，游标分页不等于排序天然无成本。万级节点的真实执行计划和耗时必须实测，不能仅凭索引存在宣称已达标。
本轮未将索引变更同步到任何现有数据库。

## 数量表示

`modules/inventory` 公开 `parseInventoryQuantity`、`formatInventoryQuantity` 与 `InventoryQuantityError`。
实现放在 Inventory 的 value-objects，不新增全局数字工具模块。

- 输入只接受普通十进制字符串，不接受 number、指数、空白或超过六位小数的文本。
- 与现有 `Decimal(20,6)` 一致：最多十四位整数、六位小数，绝对值小于 10^14；超限拒绝，不静默舍入。
- 解析返回独立精度配置的 Prisma Decimal，后续计算不经过 JavaScript 浮点数，也不修改全局 Decimal 设置。
- 输出为固定六位小数的字符串；负零规范为 `0.000000`，非有限值和超限结果拒绝。
- 支持有符号数值表示；库存余额非负、流水方向、单位及除法舍入规则仍由 P09/P11 决定。
- P09 的共享 wire 契约采用字符串，并在响应投影中显式调用格式化函数，不直接返回 Prisma 实体。
- 其他 BigInt 字段同样在所属响应投影中转十进制字符串；本轮没有新增 BigInt 业务接口或泛用 JSON replacer。

例：`parseInventoryQuantity('90071992547409.123456')` 不丢精度；
`formatInventoryQuantity(parseInventoryQuantity('1.2'))` 返回 `'1.200000'`。

## 验证与交接

本轮未执行 db push、DDL、迁移、seed 或已有环境的数据写入，也未新增长期维护的测试脚本。
Backend build、Facility/Inventory 定向 ESLint、`git diff --check`、Prisma format 与
Prisma validate（`dev.local` 配置，仅加载 schema，不执行数据库写入）均通过。
隔离 PostgreSQL 的受管事务回滚、原生错误、并发移动、稳定翻页和万级节点执行计划仍待获准后验收，不能沿用早先原生 writer 的测试结果冒充本轮验证。

P08 仍需完成设施使用与节点授权规则、归档/占用业务校验、Resource Provider、审计、HTTP 契约和前端浏览。
P09 仍需完成数量正负/单位规则、入库事务、竞争控制与幂等；本轮只是准备其技术支撑。
