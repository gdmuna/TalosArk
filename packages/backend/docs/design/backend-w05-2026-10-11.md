# W05: Session / TokenPair 生命周期和原子推进

实施日期：2026-10-11。范围仅限 `core/access/access.kernel.ts` 的刷新与 AT 校验及相关设计记录。
未修改公开响应、错误 catalog、Access 类型、Schema、配置、凭据寿命或 Auth 路由。
W05 验收时公开 refresh/logout 尚未实现，不将该次 Kernel 验收等同于认证 HTTP 闭环已完成。
后续公开接口接入及其独立验收见 [会话接口实施记录](auth-session-http-2026-10-11.md)。

## 已确认策略

- RT 重用只拒绝当前刷新，不自动撤销 Session 或 Token family。
- 正常轮转后，旧 AT 在自身未到期且 Session/TokenPair 仍有效时继续可用。
- Session 或 TokenPair 已撤销、Session 空闲到期时，后续 AT 校验和 RT 刷新均拒绝。
- RT 还必须未到期、未消费，且所属 pair 的 generation 等于 Session 当前 version。
- 不存在或已到期 RT 返回 `session-inactive`；未到期但已消费 RT 返回 `refresh-token-reused`。
  此检查顺序保留原有语义；已消费且随后撤销的凭据不会被重新解释为可刷新。
- AT 的 `sv` 校验所属 pair 的 generation，而不是 Session 当前 version；后者会误伤正常轮转前的 AT。
  其余 JWT 签名、claims、存储凭据与身份一致性校验保持不变。
- AT 保留现有配置寿命，RT 保留 7 天，刷新后 Session 空闲期限仍为 30 天。

共同的 pair/Session 活性判断收为文件内纯函数 `isTokenPairActive`，没有新增跨模块生命周期抽象。

## 原子推进

`rotateTokenPair` 使用显式 `ReadCommitted` interactive transaction，整个成功结果在提交完成后才返回：

1. 在事务外计算 RT 的 SHA-256 hash；事务内使用参数化查询，通过该 hash 找到所属 Session 并 `FOR UPDATE OF s`。
2. 获得锁后重新读取 RT、pair 和 Session，并在这时取得当前时间。不能使用锁等待前的状态或时间。
3. 校验 RT 到期/消费、pair 撤销、Session 撤销/空闲到期及 generation。
4. 条件消费旧 RT，要求 `consumedAt = null` 且仍未到期；影响行数必须为 1。
5. 签发下一代凭据；按旧 version、未撤销、未空闲到期条件更新 Session，version 原子加一。
6. 同一 nested write 创建下一代 TokenPair、AT 和仅含 hash 的 RT；提交成功后返回新凭据。

签发、条件更新或持久化的确定失败会回滚事务内的 RT 消费和新凭据。
同 RT 的等待者取得 Session 锁后会读到已消费状态，得到明确的重用错误，不再产生并行代际。
不把所有 unique constraint 都解释成 RT 重用，不自动重试整个签发事务。

行锁查询显式限定 `public.Session/TokenPair/RefreshToken`，与当前 Prisma 表映射保持一致，
避免 `search_path` 中同名表改变锁目标。以后若变更数据库 schema 或模型映射，必须同步此查询。
原始 RT 从未拼入 SQL；这里只锁 Session，不扩大到 User 或全部 TokenPair。

## 撤销顺序与边界

现有单会话/全部会话撤销使用 Session UPDATE，其行锁与刷新锁互斥：

- 撤销先提交：等待中的刷新重新读取撤销状态，拒绝且不消费 RT。
- 刷新先提交：撤销随后生效；后续校验会拒绝新旧 AT，新 RT 也不能继续刷新。
- 不取消已经完成认证的在途业务请求，不把撤销解释成回滚历史操作。
- 全部会话撤销保持现有的匹配行更新语义，不保证阻止并发登录新建 Session。

当前没有 TokenPair 撤销命令；校验会识别存储中的 pair 撤销状态。
未来若添加 pair 撤销写入且需要与刷新互斥，也必须先锁所属 Session，遵守相同的内部写入协议。
不能只更新 pair 后声称已拥有与 Session 撤销相同的竞争保证。

现有 `execute` / error mapper 继续只重解释已识别的数据库原因。
无关 unique failure 仍为 DatabaseError；未知错误保留原实例，交由现有终端错误边界安全兜底。
实际 deferred commit failure 在当前 PrismaPg 中表现为原始 DriverAdapterError，而不是现有 normalizer
支持的 Prisma 已知请求错误。本轮没有为迎合探针断言扩张 Infra 错误规则或公开它的数据库细节。

如果 COMMIT 已生效但响应丢失，客户端可能无法确定提交结果；不能宣称所有 rejected promise 都代表回滚。
本轮验证的是数据库明确拒绝提交的回滚，不是网络中断下的提交结果恢复。
未增加自动重试、刷新幂等回放或明文新凭据缓存；这些需要独立协议设计。

## 实际验收

遵循快速迭代政策，没有新增、回填或维护测试文件。以下均为不落盘的一次性探针：

| 检查 | 结果 |
| --- | --- |
| 修改前真实编译 Kernel + mock | 复现已撤销 pair、空闲到期 Session 仍能刷新 |
| 修改后真实编译 Kernel + mock | 无效生命周期均拒绝；锁、重新读取、条件消费和推进顺序正确；无关错误不吞掉 |
| 正常轮转，真实 PostgreSQL | version/generation 从 1 到 2 到 3；正常轮转后旧 AT 和新 AT 均有效 |
| 无效状态，真实 PostgreSQL | pair/Session 撤销、Session/RT 到期、RT 消费和旧 generation 拒绝；没有额外推进 |
| 同 RT 并发，真实 PostgreSQL | 16 轮，每轮 8 请求；恰好 1 次成功、7 次重用拒绝；仅有两代 pair，无自动撤销 |
| 刷新与撤销竞争，真实 PostgreSQL | 分别控制撤销先、刷新先；等待与最终状态符合上述顺序 |
| 等待期间到期，真实 PostgreSQL | 分别让 Session 空闲期限、RT 期限在锁等待中到期；重新取时后拒绝，无消费或新 pair |
| 事务失败，真实 PostgreSQL | 签名失败、version 条件失配、无关 generation 唯一冲突均完整回滚 |
| 真正提交失败，真实 PostgreSQL | DEFERRABLE constraint trigger 在 COMMIT 拒绝；未返回成功，事务前后快照一致 |
| 全部 Session 撤销，真实 PostgreSQL | 后续 AT 与 RT 均拒绝 |
| `search_path` 影子表，真实 PostgreSQL | 同名影子 Session 不影响刷新；行锁和 Prisma 仍操作同一个 public 表 |
| 静态交付 | backend build、定向 ESLint、Prettier 和 diff whitespace 检查通过 |
