# P07 材料登记、查询与资源引用

日期：2026-10-18。P07 是第一个真实业务材料切片，建立在 P06、I04 授权目标解析、I05 ResourceIdentity 与审计内核之上。

## 范围

- 每个材料定义只属于一个工作区；工作区分类是扁平分类。
- 三个首发业务分支：`consumable` 普通耗材、`chemical` 化学材料、`biological` 生物材料。
- 共享字段：编号、名称、描述、厂家、货号、计量单位、别名、外部标识。
- 分支字段全部选填：耗材规格/包装说明/材质；化学材料分子式/纯度或浓度/形态；生物材料来源/物种/保存条件。
- CAS、RRID 等统一存入外部标识；同一材料内别名及标识去重。
- 编号在工作区内唯一；同名、同外部标识可因厂家或规格不同而并存。
- 材料与分类只归档/恢复，不提供硬删除；存在实例后禁止改变材料分支或计量单位。

P07 不实现批次、物理实例入库、库存数量/位置、文件上传、QC、培养、谱系、专业子类型或自定义 Schema；这些分别留给 P09、P10 及后续领域切片。

## 后端模块

`modules/material` 暴露 `MaterialModule`、`MaterialService` 和材料事实读取器。服务负责严格输入投影、列表查询、分类与材料写入、归档恢复、资源身份创建和审计记录。材料目标 Provider 只解析真实组织/工作区归属；最终授权仍由 `AuthorizationKernel` 判定。

写操作在一个受管数据库事务中完成：先锁定组织，再完整检查材料读取权限与本次写动作权限，适用时按组织 → 材料顺序锁定材料，随后执行业务写入、ResourceIdentity 创建和审计追加。审计失败会回滚材料与资源身份。数据库唯一约束只映射材料/分类编号冲突，其余未知数据库错误保持原始技术错误。

HTTP 根路径为 `/organization/:organizationId/workspace/:workspaceId/material`，提供：

- `GET /` 列表、搜索、分支/分类/状态过滤、排序与服务端分页；
- `GET /overview` 概览摘要与最近材料；
- `GET /type`、`POST /type`、`PATCH /type/:typeId`、`POST /type/:typeId/archive` 分类管理；
- `POST /`、`GET /:materialId`、`PATCH /:materialId`、`POST /:materialId/archive` 材料定义读写。

查询先应用授权范围，再执行搜索、统计和分页。空授权范围显式生成无匹配条件，不退化为无限查询。详情及 Resource 描述都重新解析实际目标，不能伪造 URL scope 绕过授权。

## 前端交付

材料模块使用真实 HTTP data source，不回退 mock 成功。概览提供总数/有效/归档摘要、最近材料、三分支分布和真实边界内的快捷动作；列表使用 DataTable 的服务端搜索、过滤、排序、分页、Sheet 预览及编辑/归档操作；详情支持深链刷新、基础事实、分支属性和实例数量占位。材料编辑和分类管理使用 Sheet，空数据、加载失败和权限失败分开呈现。

`?create=1` 是一次性命令，进入列表后消费并打开新建 Sheet。详情编辑使用当前材料快照，避免刷新读模型时把编辑入口误判为新建。

## 已知边界

组合根提供新建 `workspace-manager` 角色的初始材料权限；创建工作区时如果该组织已有此角色，会复用其原有权限，不自动扩权。因此旧工作区，以及复用旧角色的新工作区，都可能需要通过 P06 创建材料自定义角色并显式绑定。读取和启动不会自动修复业务授权。

材料实例、库存、文件和活动数据尚未接入，页面显示明确的未接入状态，不以零值冒充真实查询。实际开发环境使用前仍需由操作者同步当前材料 Schema，并按当前角色授权；本轮未代为改写开发库。

## 2026-10-19：锁后完整授权修复

材料及分类写入先取得现有组织锁，再检查 `material.read` 与本次动作权限，避免把锁前读权限和锁后写权限拼成完整授权。
材料实体锁、业务校验、资源身份和审计仍由原有业务事务拥有；本轮不改变锁粒度或实现 Lock Core。
用户接受该粒度仅用于 MVP；1.0 前必须完成细化并发控制，见[基础设施计划的前置约束](mvp-foundation-work-plan.md#10-前置约束细化并发控制与-lock-core待设计)。

- 后端完整构建、定向 ESLint、四个修改文件的 Prettier 检查通过。
- 一次性公共入口对照探针覆盖创建/更新/归档材料及创建/更新/归档分类，共 6 个入口 × 10 个场景，60 组修复前后对照、120 次调用。
- “只有读取 → 只有动作”和“撤销读取、保留动作”的 12 组旧实现放行结果均改为拒绝，且拒绝前没有业务写入、资源创建或审计调用。
