# P06：成员、邀请和角色管理

状态：2026-10-15 完成本文限定的 Web 团队管理闭环。资源、设施及其节点授权不在本轮验收内。

## 用户确认的规则

- 组织所有者管理组织成员、自定义角色和邀请。工作区管理员仅管理本区成员并分配已有工作区角色，不能授予自己没有的权限。
- 组织所有者不可被移除或自行离开，本轮不提供所有权交接。
- 邀请仅面向已有平台账户，绑定规范化邮箱、有效期默认 7 天。未开户者沿用运维开户和专用激活流程。
- 邮件有限异步发送，不自动重试；重发替换凭据使旧链接失效。本轮只使用本地合成 SMTP 验证。
- 接受邀请只授予基础组织读取，以及可选目标工作区读取；管理权限通过明确的角色分配产生。

## 边界与实现

沿用已实现的内部 Casbin Permission / Authorization，不调用远程 Casdoor 管理接口，不增加另一份策略事实表。
使用现有 OrganizationMember、WorkspaceMember、OrganizationInvitation 和 Role 模型；没有 Schema/DDL 变更。

组织所有者通过显式初始化入口一次性建立组织治理角色，并为现存、有效且保留读取权限的初始工作区管理角色增加成员管理动作。
读取不写库；已有治理角色不会被初始化入口修复，归档或撤销授权也不会因读取或初始化重跑而自动恢复。
内置所有者、治理和基础成员角色不允许在自定义角色入口修改或归档。

当前七个动作是组织读取、创建工作区、工作区读取、组织成员管理、组织角色管理、组织邀请管理、工作区成员管理。
代码定义由已有 Discovery/显式贡献装配并冻结；创建或修改角色时由 Permission 显式物化用到的权限目录项，不在启动阶段写目录。
工作区管理员添加成员时也检查基础读取权限；绑定已有角色时检查新增绑定所携带的全部权限，保留现有绑定不等于重新授予。
角色归档立即停止参与授权；成员视图也不再把归档角色当作可编辑的有效绑定。

管理变更在 ReadCommitted 事务内持有组织行锁，在锁内重新验证权限；邀请接受使用同一锁。
组织移除同时使其工作区成员失效并清除绑定，保留成员历史行，撤销相应未接受邀请。
LEFT 通过新邀请或显式添加重新加入时清除旧绑定；SUSPENDED 不通过邀请恢复。
所有成功管理写入与字段白名单审计同事务提交；提交后才将无明文持久化的邀请凭据送入有限邮件队列。
邮件失败不改变已提交的成员事实，也不承诺自动重试或进程重启后可靠恢复。

管理查询先限定组织、工作区和管理资格，再搜索、分页和计数。非管理员只读取自身成员行，不获取组织成员邮箱目录。
角色定义只由组织所有者编辑，避免共享工作区角色的修改影响其他工作区。授权撤销对下一次新授权快照生效，不承诺取消已在执行的事务。

前端成员页和角色页接真实管理接口，提供组织/工作区范围、搜索、分页、邀请、撤销/重发、角色编辑与绑定、离开/移除以及加载/错误/待同步状态。
邀请链接使用 fragment；页面先移除 URL 中的凭据，仅在内存中保留明确的邀请意图以跨越 SPA 登录，必须登录并人工确认接受。
同页更换邀请或登录身份时清空预览并取消旧请求，接受操作只消费已成功预览的凭据。
此内存意图不跨页面刷新或企业 SSO 的整页跳转保存；遇到这些情况，登录后重新打开邮件原链接，不把凭据塞入查询参数或浏览器持久化存储。
旧工作区/账户/表单的晚到结果不能更新新的操作上下文。已提交写入的同步失败只重读，不重放写入。

`TEAM_INVITATION_URL` 和 `TEAM_INVITATION_TTL_SECONDS` 已加入所有六份 env 文件，默认有效期 604800 秒，可配置为 60-604800 秒。
URL 不允许用户信息、查询或 fragment；生产环境必须 HTTPS。生产 env 沿用现有激活地址的 HTTPS localhost 占位，部署前必须改成真实客户端地址。
队列总容量 64，并发复用 SMTP 并发配置；排队成功不代表收件箱送达。队列关闭或已满时明确返回 unavailable，管理员可以重发。

本轮不做资源/设施节点继承、显式 Deny、任意 ABAC、所有权交接、自动开户、真实邮件发送验收或 Tauri 实机验收。

R03 真实管理详情在 P06 能力之上复用成员、角色、邀请和审计授权；详情读取、关系分页、角色绑定计数和并发修订检查见前端 R03 记录及对应 TeamDetail/WorkspaceManagement 服务。P06 的管理命令仍是唯一写入入口，R03 没有新增一套管理权限或绕过现有授权。

## 验证记录

- 后端构建、前端类型检查与生产构建、本轮源码 ESLint/Prettier 和 diff 空白检查通过。前端仍有现有的单包体积提示，未以此为由改动既定静态路由策略。
- 一次性真实后端检查完成 52 个断言，覆盖两个组织、所有者/普通成员/工作区管理者、scope 不匹配、禁止所有者离开、邀请重发/失效/过期/重放、成员历史保留、旧 AT 的上下文拒绝及审计失败回滚。此数量是断言总数，不是 52 个独立业务场景。
- PostgreSQL 实际并发检查：同一邀请并发接受只成功一次；同一角色并发替换后的权限不被合并；邀请审计抛错时事务回滚且不会入邮件队列。
- 使用项目正式开户、密码准备和激活能力创建合成账户。Edge/Playwright 实际验证启用团队管理、成员页、角色创建、界面发邀请、SPA 登录返回邀请页、移除 fragment、更换链接清除旧预览、退出后取消旧预览并重新登录、人工接受以及普通成员只看自身。代表截图保存在忽略的 `output/p06/`。
- 一次性前端状态检查验证：离开已提交但工作区读取失败时返回写入成功、清空旧成员视图并暂停写入；恢复只重读，离开请求总计一次。
- 数据库仅使用 `talos-ark_backend_test`，每次均先核对库名，合成记录按本轮 ID 清理。没有同步 Schema、执行 DDL、清空库、向真实地址发信或调用 Casdoor 管理接口。
- 邮件仅使用本进程的合成 SMTP；主后端检查实际接收 6 封，另有浏览器及并发流程的合成邮件。没有新增或维护测试脚本，按当前迭代约定使用一次性探针。
- 两份只读代码审查发现并修复委派、离开后同步及邀请上下文问题；浏览器另发现并修复 Select 空选项导致的渲染失败。

未验证真实 SMTP 收件箱送达、多进程持久化邮件队列、Tauri、生产部署、节点继承或完整业务资源授权，不据此宣称这些能力已完成。
