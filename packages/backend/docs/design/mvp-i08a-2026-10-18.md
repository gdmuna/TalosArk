## 1. 这轮完成什么

用户确认首批同时支持单次上传与分片上传；可用前核验实际字节数与完整 SHA-256。
真实类型识别、病毒扫描留到后续，不把客户端声明的 MIME 当作安全证明。

本轮实现 `core/file`，复用 `infra/storage`，没有另建 S3 client、任务系统或通用幂等框架。
提供持久上传会话、签名、进度、完成验证、取消，以及未绑定资产的读取、下载、移除和显式清理。
不提供公共 HTTP 路由，不操作真实数据库，不创建迁移或自动执行桶生命周期配置。

I08-B 再实现用途贡献、`FileReference` 绑定/解绑和按当前资源权限下载；
I05 管 `ResourceIdentity`，不是文件系统。P10 还需要业务契约、用途规则和附件界面。

## 2. 调用方式与边界

业务模块显式导入 `FileModule`，注入公开的 `FileKernel`。
Bootstrap 使用 `FileConfigurationModule.forRootAsync` 注册配置；只有配置 token 全局可见。
当前组合入口从已有 `storage.bucketStaging/bucketPrivate` 取桶名，没有增加环境变量。

```ts
const actor = { organizationId, userId }; // 来自已认证、可信的应用上下文，不直接接受请求体身份
const upload = await files.beginUpload({
    ...actor,
    idempotencyKey, // UUID；同一组织、上传者内标识一次不可变上传意图
    filename: 'report.pdf',
    contentType: 'application/pdf', // 仅声明
    sizeBytes,
    sha256, // 整个文件的十六进制 SHA-256
    mode: 'single',
});
const request = await files.signUpload({ ...actor, sessionId: upload.id });
// 客户端按 request.method/url/headers 上传；这些地址是短期凭据，不记录到日志。
const asset = await files.completeUpload({ ...actor, sessionId: upload.id });
const download = await files.downloadAsset({ ...actor, assetId: asset.id });
```

| 方法 | 输入/结果与行为 |
| --- | --- |
| `beginUpload` | 固定文件名、声明类型、大小、完整 SHA-256 和模式；同 key 同输入返回原会话，不同输入冲突 |
| `signUpload` | 单次 PUT，或指定 `partNumber` 的分片 PUT；签名 TTL 不超过会话余下时间 |
| `inspectUpload` | 返回会话与供应商已确认分片；完成中返回已保存的完成清单 |
| `completeUpload` | 分片模式要求完整 `parts: [{ partNumber, etag }]`；成功返回同一个资产，不重复创建 |
| `cancelUpload` | 持久取消并使当前工作者不能发布；物理删除由清理完成 |
| `readAsset` / `downloadAsset` | 只支持当前上传者的有效、未绑定且已验证资产 |
| `removeAsset` | 逻辑移除；拒绝仍有业务引用的资产，共享对象不会因此被误删 |
| `cleanup(limit = 50)` | 可信维护入口，范围为 1..200；分阶段有界处理，不是用户可自由调用的接口 |

分片由服务端计划 `partSizeBytes/partCount`。客户端保存每片返回的 ETag，提交连续完整清单；
服务端将其与实际分片编号、ETag、大小逐项比对。ETag 不是完整文件 SHA-256。
零字节文件只支持单次上传。文件名最多 255 个字符，拒绝路径字符、控制字符和非法 Unicode。
资产大小使用十进制字符串，日期仍为 `Date`；这些是内部契约，不是已发布的 wire schema。

Core 不读请求 ALS。每次按显式 actor 校验当前组织成员关系、组织与上传者，
未授权/不存在统一返回 `file.unavailable`。当前不提供组织管理员旁路。
发现已有有效 `FileReference` 时，未绑定资产入口拒绝操作，不能绕过将来的资源授权。

所有入口要求**不在现有数据库事务内**，否则抛 `file.transaction-active`。
S3 I/O、流式哈希不占用长数据库事务；内部持久写入使用自己的短事务。
不要在材料写入事务中上传文件或偷偷使用 `requiresNew` 绕过这个边界。

## 3. 为什么不能上传成功就变为可用

签名 PUT 在到期前可反复使用，原 key 可能被覆盖，不能把“暂存文件验证后原地发布”当作不可变承诺。
该行为见 [S3 签名地址文档](https://docs.aws.amazon.com/AmazonS3/latest/userguide/using-presigned-url.html)。

实际流程是：

1. 保存会话，上传只签发到 `uploads/<organizationId>/...` 暂存 key。
2. 完成时认领有期限的 lease；分片先保存规范化清单，再请求供应商完成。
3. 核对暂存对象大小，在数据库登记唯一的 PENDING 候选对象，然后复制到 `objects/<organizationId>/<token>`。
4. 流式读取这个候选对象，累计实际字节数并计算完整 SHA-256，不把整个文件载入内存。
5. 短事务重新校验成员、会话、到期与 lease，原子发布 AVAILABLE 对象、FileAsset 和完成会话。

旧上传地址只能改暂存 key，不能改已发布候选。失败候选有持久记录，后续可回收。
lease token 只约束数据库发布，不会取消供应商已经接受的写入；取消、到期后迟到的复制不会发布资产。
下载强制 `attachment` 与 `application/octet-stream`，保留 UTF-8 文件名，不提供内联预览安全承诺。
SHA-256 证明上传内容符合声明，不证明文件无害，也不证明声明类型真实。

当前单次复制路径最多支持 5,000,000,000 字节，配置也禁止超过该上限。
更大的文件将来需要 multipart copy，不是假装现有 multipart upload 已解决全部大文件路径。
参见 [CopyObject 限制](https://docs.aws.amazon.com/AmazonS3/latest/API/API_CopyObject.html)。

## 4. 恢复、竞争与超时

- 会话保存 uploadId、预期内容、完成清单、完成资产和 lease，重启后可继续查询、签名与完成。
- 分片完成响应丢失时，重试先检查已保存清单和暂存对象；对象已存在则重新验证，不盲目创建第二次上传。
- 同一会话同时完成/签名时用条件 lease 拒绝竞争；发布前锁会话并重新检查，旧工作者不能发布。
- 完成后的重放仍检查当前资产是否可访问；取消/到期不会自动生成新会话。
- 达到进程容量直接返回 `file.busy`，没有无限排队或默认自动重试。
- 操作超时向调用方失败并取消 SDK/流，但容量直到实际工作结束才释放。SQL 或远端已受理的操作可能继续完成，不能声称超时等于回滚。
- 关闭时拒绝新操作、发送取消并等待有限预算；仍未结束明确报 `file.close-timeout`，不报告虚假的排空成功。
- 已知 StorageError 清理失败按项返回并记英文日志；未知程序错误继续抛出，不伪装成可恢复的供应商故障。

下载签名后再次校验当前资产状态，但已签发地址在 TTL 内仍有使用窗口。
签名地址可能在到期前开始一个随后继续的传输；数据库取消/撤权不是即时撤销已经发出的地址。
调用方应按错误原因和不可变会话 ID 决定是否重试，不能给整个流程套无条件重试。

## 5. 配置与生命周期

以下是 `FileOptions` 的程序化配置，不是新增 env 开关；当前 Bootstrap 仅映射两个桶名，其余采用默认值。
桶可以相同，隔离依靠不同 key 前缀；桶应为私有，浏览器上传所需 CORS/IAM 仍由部署方配置。

| 配置 | 默认值 | 限制/作用 |
| --- | --- | --- |
| `stagingBucket` / `privateBucket` | 无，必填 | 沿用 `S3_BUCKET_STAGING` / `S3_BUCKET_PRIVATE` 的配置装配 |
| `maxFileSizeBytes` | 104857600，100 MiB | 1..5,000,000,000 |
| `partSizeBytes` | 8388608，8 MiB | 5..256 MiB；最后一片可小于 5 MiB |
| `uploadTtlSeconds` | 3600 | 会话接受操作的期限 |
| `unboundTtlSeconds` | 86400 | 发布后未绑定资产的可用期限 |
| `presignTtlSeconds` | 600 | 上传签名 TTL，并受会话余下时间限制 |
| `downloadTtlSeconds` | 60 | 下载地址 TTL，并受资产余下时间限制 |
| `operationTimeoutMs` | 120000 | 100..600000；包含复制、读取与哈希，不仅是单次 SDK 请求 |
| `maxConcurrentOperations` | 4 | 1..32；进程内全部 File 操作共用容量 |
| `closeTimeoutMs` | 5000 | 1..30000；应与进程总退出预算匹配 |

全部秒数配置为 1..604800。大文件、慢存储需要调大验证预算，否则文件可能始终无法在期限内完成。
Storage 原有 SDK 重试继续保留，不再叠加一层隐藏重试。

## 6. 清理与部署前提

`cleanup` 显式执行：过期会话、过期未绑定资产、终态暂存对象、无有效资产/引用的候选与删除对象。
不同阶段各有批次上限，不是每次总共只执行 limit 条 SQL/对象请求。
会话和对象保留清理时间及删除墓碑，重复删除用于处理迟到写入；本轮不自动清空历史记录。
清理与未来绑定必须共同使用 **FileObject -> FileAsset** 的锁顺序，并在锁内复查状态、到期和引用。
I08-B 必须遵循它，不能直接插入 FileReference 后宣称与清理并发安全。

当前**没有自动调度器**。维护调用方应重复运行有界批次、观察失败结果，不能因存在 cleanup 方法就认为已经自动清理。
另外，创建 multipart 已在供应商成功、但响应完全丢失时，应用不知道 uploadId，数据库无法定位它。
必须给暂存前缀配置 `AbortIncompleteMultipartUpload` 生命周期作为兜底；
[S3 multipart 文档](https://docs.aws.amazon.com/AmazonS3/latest/userguide/mpuoverview.html)也建议处理未完成分片。

下面仅是**未启用版本控制的桶**的规则示例，不自动执行；部署方先合并现有规则，并核对兼容存储的实现。
8 天大于当前允许的最长 7 天会话，避免主动删除有效会话；规则只针对 `uploads/`，不能覆盖 `objects/`。

```json
{
    "Rules": [
        {
            "ID": "talosark-staging-retention",
            "Status": "Enabled",
            "Filter": { "Prefix": "uploads/" },
            "Expiration": { "Days": 8 },
            "AbortIncompleteMultipartUpload": { "DaysAfterInitiation": 8 }
        }
    ]
}
```

启用版本控制时普通删除可能只产生删除标记，旧版本与费用不会由本轮清理彻底消除；
需要另外决定非当前版本保留策略。未知 uploadId、延迟中止以及旧版本的物理回收不能仅靠 SQL 事务保证。

## 7. Schema 与接入交接

`file.prisma` 新增 `FileUploadSession`、上传模式/状态枚举；`FileObject` 增加可空上传会话关联与清理时间，
`FileAsset` 增加可空未绑定期限。Organization/User 只有反向关系；FileReference 的定义没有变化。
原有资产不自动补期限，不批量删除；没有恢复历史迁移或 seed。

仅完成离线 schema 格式、校验和 client 生成，**未执行 db push、DDL 或任何现有环境的表结构更新**。
使用 File API 前需要另行审查并同步选定数据库；现有数据库未更新时不能认为模块已可落地运行。
本轮没有业务 HTTP 入口，因此也没有新增公共错误契约或 OpenAPI 路由。

主线接下来仍需：

1. 按已确认的 D10 实现 `material.attachment` 白名单和 100 MiB 业务上限；真实类型识别/病毒扫描仍延期，不能把声明 MIME 当作真实检测结果。
2. I05 提供资源身份入口；I08-B 接上用途、资源权限、绑定/解绑、当前授权下载和清理锁协议。
3. P10 提供真实身份到 FileActor 的映射、HTTP 错误/响应投影、客户端哈希与 ETag 收集、上传/恢复界面。
4. 部署审查私有桶、CORS/IAM、生命周期与维护调用，再验证真实 PostgreSQL 和兼容对象存储。
