P1 生产镜像打包本地环境凭据与密钥

触发： 从当前工作区按 Dockerfile 构建。 secrets/env/* 和 secrets/crypto/* 被无差别 COPY； .dockerignore 未排除本地配置和密钥。当前本地环境文件确有非空明文敏感赋值，报告不显示其值。

影响： 开发 / 测试凭据及本地密钥进入生产镜像；Git ignore 不会限制 Docker 构建上下文。优先改为按生产用途选择配置并在运行时注入密钥，评估已发布镜像是否需要清理和轮换凭据。

P2 正常停止进程没有调用 Nest 资源清理 hooks

module 有 interface 和 implementation；depth 产生 leverage 与 locality。实线盒表示 module，虚线表示内部 seam，红色表示泄漏。这里只给概念方向，不提前规定新 interface。

问题： 获取一个文件读取 helper 会加载配置、格式化、HTTP / 环境支持，独立入口失去 locality。

  • locality：初始化知识归 owner
  • leverage：不同入口一致运行
  • 纯 helper 可独立验证

Deletion test： 去掉 common → config 的绕行会消除循环，而不会把配置知识转嫁给各业务调用方。不是单纯“禁止 barrel”。
