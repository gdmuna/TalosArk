# P08 设施与存储位置实施方案

日期：2026-10-19。状态：方案已获批准，P08 后端已实施，前端正式接入及隔离读写验收完成；真实环境联合 Web 验收未签收。分别见 [后端实施记录](../../packages/backend/docs/design/mvp-p08-2026-10-19.md) 和 [前端验收](../../packages/frontend/docs/remediation/2026-10-15/r04/facility-p08-acceptance-2026-10-19.md)，P09 联动仍待完成。

本方案承接 [MVP 工作计划](mvp-work-plan.md)、[I06 技术支撑](../../packages/backend/docs/design/mvp-i06-2026-10-18.md) 和本轮业务讨论。已确认的业务边界与本文建议的实施细则分开记录；文档不代表对应代码或数据库约束已经改变。

## 1. 交付目标与边界

P08 完成后，用户可以登记一处存储场所，指定管理工作区，向同组织其他工作区开放整处设施，建立冰箱、液氮罐、层架、盒子和孔位，并通过真实接口浏览、维护、定位和选择位置。空容器及其内部结构可以在同组织不同设施间整体搬迁。

本轮讨论已确认：Facility 作为组织拥有的存储场所；容器使用任意深度父子树；首版只做整个设施共享；支持同组织跨设施子树搬迁的设计方向。公共存放区暂不增加，沿用当前每个 POSITION 同时最多放一个实物实例的模型。这里的“独占”只描述占用数量，与访问权限无关。

首版不提供节点级授权或停止继承、跨组织搬迁、公共存放区、跨位置逻辑集合、自动位置分配、模板市场或硬件联动。节点授权的长期方向保留，未因此实现。

P08 交付结构维护和位置事实。P09 交付材料实例、库存、Placement 和入库；带存量的容器搬迁作为 P09 的联动收尾，需要库存编排后才能开放。P08 不能用“树已移动”冒充“带库存搬迁已完成”。

## 2. 用户能够表达什么

```text
Organization
└─ Facility：301 实验室
   └─ StorageTopology：当前存储布局
      ├─ CONTAINER：超低温冰箱 A
      │  └─ CONTAINER：第一层
      │     └─ CONTAINER：冻存盒 01
      │        ├─ POSITION：A1
      │        └─ POSITION：A2
      └─ CONTAINER：液氮罐 B
         └─ CONTAINER：提篮 01
```

Facility 可以表示房间、库房或有独立管理边界的存储区，不建立固定的楼栋、楼层、房间业务树。地址说明先用位置文本表达。

StorageTopology 是设施的一套存储结构。建议首版每个设施只有一套活动布局，创建设施时一起创建；用户不必先理解或手工建立拓扑。它不是布局草稿、历史版本或可切换的库存副本。

CONTAINER 可以包含容器或位置，POSITION 是最终存放点且不能有子节点。人为划分的上区、下区或虚拟层架也可以作为容器，只要它们为下级提供唯一位置路径。跨多台冰箱收集“常用样本”的集合不进入这棵树。

冰箱和液氮罐无需先登记 Equipment。现有 Equipment.facilityId 仍表示设备所在地；具体设备与存储节点的关联留给设备台账切片，不在 P08 增加未接通的设备绑定接口。涉及已登记设备的整机跨设施搬迁，在关联语义落实前不宣称能够自动同步设备台账。

## 3. 数据模型与规则

下面的新增字段、编号口径和生命周期细则是本方案建议的实现默认值，不是此前已经落地的事实。

| 对象 | 首版字段及变化 | 关键规则 |
| --- | --- | --- |
| Facility | 沿用组织、编号、名称、描述、管理工作区；补位置文本、停用时间和 revision | 编号在组织内唯一；管理工作区必须属于同组织；所有权不随管理关系改变 |
| FacilityWorkspaceAccess | 沿用 USE / MANAGE 关系 | 仅同组织有效工作区；USE 允许使用，MANAGE 允许结构维护；共享授权管理另行鉴权 |
| StorageTopology | 沿用模型，补结构 revision，约束每个设施最多一套活动布局 | 不创建公开拓扑切换、克隆或历史回滚功能 |
| StorageNode | 保留 kind、父节点、path、编号、名称、坐标和排序；补容器分类、描述、停用时间及必要网格规格 | 组织与节点 ID 不可变；拓扑归属允许通过合法迁移改变；POSITION 不能变为非叶节点 |
| Placement | 本轮不改变占用模型 | 一个位置同时最多一个实物；已有占用会限制结构改造、归档和 P08 的结构移动 |

容器分类采用有限集合：冰箱、液氮罐、柜体、层架、提篮、抽屉、盒、逻辑分区、其他。分类负责表达用途和展示，不预建专业属性系统，也不规定固定的父子级数。kind 与分类不能混成一个枚举。

建议将节点编号从“拓扑内唯一”改为“同一父节点下唯一”，根节点编号则在同一拓扑的根级唯一。这样不同盒子都可以有 A1，不同冰箱都可以有第一层。根节点 parentId 为 null 时必须用明确的数据库唯一规则处理，不能依赖普通可空复合唯一约束。

网格容器保存明确的行列规格，直接子节点可以有成对的行列坐标。公开坐标从 1 开始，同一父节点内不得重叠或越界。不存在的格子不算空位；可用位置数来自实际存在且可使用的 POSITION，不能直接用行数乘列数假定容量。

提供有数量上限的批量位置生成，用于创建盒子的孔位。一次提交整体成功或回滚，检查编号、坐标与资源身份。首版不开发模板版本或布局迁移工具。

停用禁止新增存放，保留已有内容查看和授权移出能力。目标位置是否允许入库同时检查设施、拓扑、全部祖先和位置本身的状态。归档不硬删除对象或历史引用；有占用时拒绝归档。首版不做隐式级联归档：先处理活动子节点，再归档父节点，恢复要求父级有效。

已使用过的位置保留身份与历史。kind 作为创建时结构身份，不通过普通编辑切换；需要改变结构时建立新节点，避免把既有孔位悄悄变成容器。

## 4. 共享和权限

设施属于组织，当前工作区是使用上下文，管理工作区是治理关系。这三者必须分别验证；共享设施不能套用“资源唯一归属于管理工作区”的材料授权算法。

建议组织角色提供 facility.create 和 facility.govern，分别控制创建、管理工作区及设施访问关系；工作区角色提供 facility.read、facility.use、facility.manage，分别控制浏览、使用和结构维护。具体 permission code 随契约实现校对，不新增角色名称判断。

对普通工作区入口，有效成员关系、当前工作区动作权限、管理工作区或共享关系三者取交集。USE 关系最多开放浏览和使用；MANAGE 可以开放结构维护，但不自动授予重新共享设施、变更管理工作区的权力。组织治理入口单独检查组织级治理权限，不自动获得其他工作区材料内容。

设施列表、搜索、统计和分页在 SQL 中先应用这些条件。节点详情、祖先、子节点、位置候选和资源描述使用同一设施准入规则。首版授权覆盖整套布局，不扩展 I06 的子树范围为节点继承系统。

P09 接入后，位置可见可以展示“已占用”，材料名、批次、数量和实例链接仍按材料及库存权限投影。设施管理权限不能代替库存变更权限。

收回使用关系后立即阻止新操作，不删除已有 Placement。仍有该工作区存量时，普通撤销入口先要求处理存量，或由具备相应权限的管理流程完成撤销和后续移出；不能靠保留一条隐藏授权让已撤销成员继续访问。

权限定义通过现有 Discovery 装配，角色授权通过显式业务写入。新组织或显式升级授权时写入首批权限，不在启动或读接口自动修复已有角色。

## 5. 跨设施搬迁

移动契约显式包含来源拓扑、目标拓扑、节点、目标父节点，以及目标根节点的新编号或坐标（需要调整时）。节点所属设施由数据库关系解析，不信任请求提供的所属关系。

同拓扑和跨拓扑移动共用结构校验：目标是活动容器或合法根级；不能移入自身子树；不得跨组织；目标同级编号、坐标不能冲突。目标冲突时拒绝或要求用户明确提供新值，不静默重编号。

一次迁移保持整棵子树所有节点及 ResourceIdentity 的 ID 不变，更新子树的 topologyId、移动根的 parentId 和完整路径。已归档的后代也随结构一起迁移，不能留下跨拓扑父子关系。子树内部的编号和坐标保持原值，移动根按目标布局重新校验。

数据库不再将 topologyId 一概判为不可变；组织和节点身份继续不可变。改写受约束的迁移函数和 guard，按稳定顺序取得来源、目标拓扑锁，检查最终父子关系和路径一致性。实现时核对父子复合外键的检查时机与 onUpdate 行为，采用能够原子更新整棵子树的语句；确有需要时只调整相关外键的延迟检查方式，不删除外键或关闭触发器绕过约束。

应用写入沿用 OrganizationWriteKernel 的 ReadCommitted 协议：组织锁后重新授权，之后按固定顺序取得拓扑锁，检查状态和占用，写结构、资源相关事实及审计，最后一起提交。Reader/Writer 继续使用 DatabaseRuntime.queryClient 和 mandatory 事务传播，不取得原生客户端绕开上下文。

P08 的用户入口只开放无 Placement 的子树移动，并在受管事务内重新检查。占用检查是 Facility 私有持久层读取 Placement 存在性的结构安全事实，不导入 Inventory 的私有服务，也不修改库存字段。P09 的所有占用写入必须参加同一并发协议。

P09 开放带存量搬迁前，新增库存拥有的编排入口：检查受影响实物及来源、目标权限，移动结构，记录各实物前后位置快照和容器搬迁审计，保证失败整体回滚。Placement 继续指向原孔位，数量、实物身份和所属工作区保持不变。涉及多个工作区的库存时，流水分别归属各自工作区，仍在同一个物理事务中提交；不能把所有实物记录到当前工作区的流水中。普通 Facility 结构接口不能绕开这条入口移动有存量子树。

## 6. 代码职责

保留 Facility 领域，不新增与 infra/storage 同名的 Core，也不恢复旧版固定四级模型。按真实职责增加文件，不填满现有 TODO 目录。

| 位置 | 实施内容 |
| --- | --- |
| packages/contract/src/facility/ | Facility、节点、位置候选、移动、生命周期的公开 Zod 契约与错误定义 |
| modules/facility/api/ | 控制器和 ApiRoute 声明，绑定受信用户身份与显式操作上下文 |
| modules/facility/application/ | FacilityService、StorageStructureService、FacilityAccessService；编排规则、授权、写入与审计 |
| modules/facility/contribution/ | 权限定义、真实组织归属的目标事实解析 |
| modules/facility/extensions/ | Facility、Topology、Node 的 Resource Provider，复用访问能力 |
| modules/facility/public/ | 现有树 Reader/Writer 和经授权的位置事实接口，供 P09 消费 |
| modules/facility/infrastructure/persistence/ | 有界事实读取、列表、结构使用检查、原生树 SQL 和游标 |
| prisma/model/facility.prisma 与 prisma/ddl/schema/storage-node.sql | 模型、活动布局唯一性、节点编号规则、迁移与路径一致性 |

FacilityAccessService 集中组合组织/工作区成员、角色动作和设施关系，供应用服务及 Resource Provider 复用。它不成为第二套 Casbin 或通用权限框架。基础事实 Reader 不递归鉴权，不从 HTTP 或请求 ALS 推断操作者。

ResourceDescriptor 的归属保持 organization，不伪装成管理工作区所有。现有 expectedScope 是归属限制，不能同时充当当前操作工作区。需要工作区上下文的设施描述入口，给内部 ResourceLookup 增加独立、可选的 accessContext，并由设施 Provider 验证；缺少所需上下文则不返回描述。材料 Provider 保持原有语义，未知或无权资源不泄露名称与链接。

内部树写契约和对应 DDL 会发生破坏性修改，公开新增接口没有旧版本迁移负担。资源身份不重建；不清库、不重建历史流水。具体 Schema/DDL 差异在实现时列出并对选定环境执行，本文不执行数据库操作。

## 7. 公开接口与调用方契约

管理入口使用组织上下文；工作区使用入口显式包含当前工作区。统一以数据中的组织和设施关系核对请求上下文，不能靠更换 URL 获得其他设施。

| 接口组 | 提供的能力 |
| --- | --- |
| 设施登记 | 创建设施及初始布局、列表、详情、编辑基本资料 |
| 设施治理 | 修改管理工作区、授予/调整/撤销设施访问关系、停用/启用、归档/恢复 |
| 存储结构 | 读取根节点和直接子节点、祖先路径、搜索与定位、节点详情 |
| 结构维护 | 创建容器或位置、编辑、同级排序、批量生成位置、同拓扑及跨设施移动 |
| 位置候选 | 返回当前上下文有权使用且状态允许的 POSITION、路径及占用事实；P09 提交时再次验证 |

请求和响应均使用公开 Zod Schema；不直接返回 Prisma 对象、原始 ltree 或底层策略。响应提供当前 capability 和受限原因，用于区分无权限、停用、占用冲突和版本冲突。capability 和位置候选都不是后续写入的授权凭证。

普通资料编辑及结构变更携带单调递增的 revision 条件，不依赖毫秒时间戳区分连续写入。跨设施移动同时校验来源和目标当前结构修订，避免旧页面把已移动节点再次搬走。节点编辑、停用、归档、创建和排序也推进所属拓扑的结构修订。同级重排不能用未加载的整套子节点 ID 覆盖分页之外的顺序；请求只表达本次移动项和合法相邻锚点。

## 8. 前端交付与交接

延续后端主线和其他 agent 负责前端的分工，本方案不自动派发或修改其他会话。后端交付公开契约、真实接口、能力投影、错误口径和验证记录；页面由前端实施方按 R04-D 及 C-03/C-04 的整改方案接入。

| 页面 | P08 应具备的内容 |
| --- | --- |
| F-06 设施列表 | 当前合法范围内的设施、管理工作区、位置及状态；创建和进入详情 |
| F-07 设施详情 | 基本信息、管理/使用关系、真实结构摘要、活动及浏览入口 |
| F-08 存储结构治理 | 树选择、节点表单、列表/网格预览、批量孔位生成、移动和生命周期操作 |
| C-03/C-04 存储浏览 | 设施与树定位、面包屑、盒/孔位网格、位置详情及授权候选选择 |
| 工作区详情的设施关系 | 接入真实管理/共享关系，替换未接入状态，不创建另一套设施数据源 |

前端不根据角色名自行算权限，不把尚未接入的库存、设备或容量指标显示为零。树和网格只读取需要的范围，刷新后保留合法节点定位；跨设施移动后刷新相关来源、目标和面包屑。规则、模板和设备控制继续按已批准范围显示，不因设计稿存在标签而增加虚假能力。

## 9. 按什么顺序实施

| 阶段 | 完成什么 | 可以交给调用方什么 |
| --- | --- | --- |
| P08-A 模型和契约 | 字段、编号命名空间、活动布局约束、公开 Schema、错误及权限清单 | 明确输入输出和破坏性内部变更清单 |
| P08-B 设施登记与共享 | 创建、查询、管理工作区、访问关系、生命周期、Resource 与审计 | 前端可以接真实设施列表和详情 |
| P08-C 存储结构维护 | 容器/位置创建编辑、网格生成、排序、状态检查、空子树跨设施搬迁 | 前端可以接真实治理与存储浏览 |
| P08-D 授权查询与交接 | 位置候选、搜索、分页、统计、资源描述、调用方能力投影 | P09 入库和前端位置选择的完整契约 |
| P08 收口 | 定向真实库验收、文档和实施记录；前端单独记录接入结果 | 分别说明后端完成、Web 验收与 P09 延后事项 |

阶段是同一项任务的交付顺序，不代表每阶段重新启动一轮架构改造。带存量搬迁在主计划中明确作为 P09 联动项跟踪，不以普通 P08 结构验收代替。

## 10. 验收和完成标准

按项目快速迭代规则，不新增或维护长期测试脚本。实施时执行构建、类型与定向 lint；有数据库变更时先只读核对目标，再在已授权的 test.local 环境验证关键实际行为，不操作 dev/prod。验证记录区分服务级、HTTP 和完整 Web 流程，前端另行交接。

| 场景 | 必须得到的结果 |
| --- | --- |
| 创建设施中资源或审计失败 | 设施、布局、资源身份和授权关系整体回滚 |
| 共享给第二工作区 | 合法成员可按动作权限浏览/使用；无关系工作区和跨组织请求均被拒绝 |
| 两个盒子都创建 A1 | 不同父节点成功；同一父节点重复失败；根级编号也有真实唯一保护 |
| 批量生成孔位中一项冲突 | 不留部分孔位或孤立 ResourceIdentity |
| 空冰箱或空盒跨设施移动 | 所有后代和身份保留，路径、拓扑、坐标与分页定位正确；来源目标更新原子提交 |
| 目标冲突、循环、无权或中途审计失败 | 无部分移动、无旧新路径混存；历史引用仍有效 |
| 对向移动或同时修改目标 | 按锁和修订规则产生明确成功或冲突，不产生断树或静默覆盖 |
| 有 Placement 的子树走普通移动/归档 | P08 明确拒绝，不改变库存或隐式移除占用 |
| 祖先停用或设施归档 | 不能通过直达 URL 或位置候选绕过状态；既有历史保持可解释 |
| 共享设施中的其他工作区存量 | 后续库存接入后仅返回允许的占用事实，不泄露未授权材料内容 |

P08 后端完成要求登记、共享、结构维护、合法空子树搬迁、授权查询与事务审计实际可用。完整页面验收另有真实前端记录；P09 的实物入库和带存量搬迁仍是后续独立完成项。
