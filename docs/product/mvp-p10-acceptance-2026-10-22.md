## 本轮补齐的 Web 场景

| 场景 | 实际结果 |
| --- | --- |
| 1. 缺桶的公开错误与进度 | 在未创建任何验收桶时发起真实分片上传；签名返回 `MATERIAL_ATTACHMENT_STORAGE_UNAVAILABLE / 503 / details=null`，不泄漏桶名。前端显示配置检查与取消提示，未初始化会话查询返回空分片 |
| 2. 缺桶时取消 | 页面直接取消原会话，没有先 GET 进度；数据库未产生 multipartUploadId |
| 3. 单次闭环回归 | 默认单次上传、服务端校验、绑定、列表、浏览器下载 SHA-256 比对和确认解绑通过 |
| 4. 显式分片上传 | 选择分片模式，上传 8,408,281 字节，按服务端计划完成两片；真实 ETag、合并、绑定及整文件下载哈希一致 |
| 5. 不完整分片恢复 | 第二片 PUT 被故意中断；服务端保留第一片 8 MiB。刷新后先拒绝同名同大小但内容不同的文件，重选原文件只上传缺失第二片，不另建 begin |
| 6. 业务完成响应丢失 | 后端完成验证并发布资产后，丢弃 complete 响应；页面刷新后无需原文件，通过同一会话完成绑定，没有新 begin 或额外 PUT |
| 7. 已初始化分片取消 | 原会话改为 CANCELLED，前端取消前不读进度，后续签名返回 400。物理分片回收不在取消接口内完成 |
| 8. 绑定后读取失败 | 真正绑定成功后令附件列表 GET 返回 503；页面提示已添加但未同步，恢复只读，不重复绑定 |
| 9. 解绑后读取失败 | 真正解绑成功后令列表 GET 返回 503；确认框切换为“只重新加载”，恢复没有再次发送 unbind |
| 10. 存储合并响应丢失 | RustFS 已合并两片，代理才断开返回链路。SQL 保留 OPEN/null assetId/两条 completionParts，公开状态为 finalizing。刷新后无需原文件，使用完全相同完成清单恢复；没有重传或新会话，只发布一个资产 |
| 11. 当前授权撤销 | 成员实际打开附件资料后撤销材料动作授权；刷新清除附件行和下载入口，列表/新下载签名/已有会话读取及签名均被真实接口拒绝 |
| 12. 授权恢复与收尾 | 恢复成员原角色，取消其未完成会话，解绑最后附件；后续不能取得已解绑引用的新下载签名 |

除明确列出的故障注入外，不拦截业务成功数据。浏览器保持真实 CORS 与签名地址，没有关闭安全策略；存储直传请求未携带应用 Authorization 或客户端认证标记。

第 10 项首个 complete 返回了真实 `500 / SYS_INTERNAL_ERROR`：合并已提交后的断链触发 SDK 重试，随后收到 NoSuchUpload。页面没有将其当作上传成功或新建任务，而是保留原会话，通过 finalizing 恢复；本轮不把首次 500 改称 503，也不声称已优化该技术错误的公开分类。

## 真实 HTTP 补验

| 场景 | 实际结果 |
| --- | --- |
| begin 幂等与材料隔离 | 同 key/同参数返回原会话；同 key 改文件名返回 409；另一材料读取该会话返回 404 |
| complete/bind 重放 | 同一会话返回原 assetId，同一资产绑定返回原 referenceId，有效引用不重复 |
| 下载协议 | sign/download API 响应为 `Cache-Control: no-store`；真实下载使用 attachment disposition，整文件 SHA-256 匹配 |
| 无成员资格账户 | 真实登录不能列出附件或取得下载签名 |
| 整文件校验失败 | 实际分片字节成功存储，但声明的完整 SHA-256 不同；complete 返回完整性错误、不发布资产，并可取消 |
| 材料归档只读 | 已绑定附件仍可读取/下载，新上传和解绑被拒绝；验证后恢复测试材料 |

另外重新验证了签名窗口：撤权后不能获取新签名，但此前已发签名在有效期内实际仍返回 200；自然到期后为 403。这是预签名地址的既定边界，不宣称撤权能立即收回地址或已下载字节。

## 数据库和对象存储收尾

最终只读 SQL 与独立 RustFS 核对得到 11 个会话：7 个 COMPLETED、4 个 CANCELLED，没有 OPEN 会话或残留租约。缺桶会话没有初始化分片 ID，错误哈希会话没有 assetId。

7 个成功资产均对应一个原会话；对其实际私有对象逐个读取，大小及完整 SHA-256 与数据库的已验证事实一致。7 条材料引用全部移除，资产已逻辑退役；`material.attachment.bind` 和 `material.attachment.unbind` 审计各 7 条。重放和故障恢复没有产生重复资产或引用。

**取消不等于同步物理 abort。**当前 cancel 只结束业务会话，分片 abort 和暂存对象删除由既有 FileCleanupService 负责。关闭后台任务的本轮环境中，仍有 1 个与 CANCELLED 数据库会话精确对应的分片上传等待清理；没有无数据库记录的分片上传。已解绑私有对象也仅逻辑退役，未在此时宣称完成物理回收。

为避免处理测试库其他组织的数据，本轮没有运行全库清理。验收后停止并移除独立临时 RustFS，连同本轮临时对象和分片一并销毁；这属于测试环境收尾，**不是**自动清理器或生产调度验收。数据库合成历史保留用于追溯，临时对象存储不是其持久部署环境。

## 验证、证据和限制

一次性产物位于忽略目录 `output/p10-acceptance-2026-10-22/`。九份 `browser-*.json` 保存 12 组场景、真实请求状态、存储 PUT/GET 和分片编号；`api.json` 保存 6 组 HTTP 检查；`database.json` 保存会话、对象字节核验、引用、审计、CORS 与 finalizing 中间状态。截图中 `expected-*` 明确代表故意触发的失败态，不能当作正常成功页面。

主要正常截图为 `single-bound.png`、`multipart-bound.png`、`partial-recovered.png`、`complete-response-recovered.png`、`finalizing-recovered.png`，已打开核对代表性页面。凭据与签名地址仅保存在本机忽略的私有运行状态，不纳入公开文档或版本控制。没有新增长期测试套件。

前端 `vue-tsc --noEmit` 通过。后端通过独立输出目录的可执行 TypeScript 编译和别名转换，使用 `--declaration false`，不覆盖共享 dist；因并行日志改动，运行时沿用验收专用控制台 JSON/采样配置。本轮没有重跑标准声明生成、全仓测试或生产构建，不用以前的构建通过代替本轮结果。

最终分组报告 pageerror 为空，**但并不代表无客户端告警**：Vite 实际报告过 13 条 ResizeObserver 通知循环错误，后端还有同一 pg client 并发 query 的弃用告警；两者不是故意注入，根因仍未定位。请求日志还包含切换到合成工作区前、以旧工作区范围读取新材料时被拒绝的 403，以及刻意注入的 503/断链；这些与上述告警分开记录，不能统称正常成功流。

单次上传另有既定协议探测：先尝试 complete，尚未传输时收到 `MATERIAL_ATTACHMENT_NOT_READY`，再签名 PUT 和完成原会话。该探测会在浏览器网络日志留下 409，不等于随机保存失败；本轮完整流程和最终字节已验证。

本轮关闭了临时 3119/4469、19012/19013 代理和 RustFS 容器，原 3000/4444 服务仍在监听。未修改 dev/prod、真实邮件配置、现有开发桶或业务权限规则。

本地分片 UI 与最新恢复逻辑的真实链路缺口已关闭。生产 HTTPS/CORS/反向代理、Tauri、其他 S3 供应商、100 MiB 上限及高并发性能、自动清理调度、全应用视觉和剩余运行告警仍各有验收边界；本轮不据此全部签收。
