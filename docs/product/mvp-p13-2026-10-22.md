# P13：入库与审批批量操作

日期：2026-10-22。状态：已完成本轮范围的本地真实 Web／HTTP／数据库验收。Tauri、生产部署另验。

## 1. 本轮范围

沿用已上线的单项命令，新增批量入库、跨申请单统一审批、同一申请内多明细执行三个入口。不重复开发已有的表格选择、申请多实物、单申请部分批准和设施位置批量生成。不新增直接批量消耗、转移、处置、普通任务或提醒写入。

用户确认 D09：逐件实物／逐申请单／逐获批明细独立提交，失败不回滚已成功项目；单申请内部审批仍为一次原子提交。跨单审批统一批准或拒绝，提交前加载所有选中申请的完整明细，部分批准保留原详情入口。单批最多 100 个执行单元，不限制 P12 单申请明细数量。

## 2. 使用入口

库存列表的“批量入库”维护待提交清单。添加、编辑、复制使用现有单件入库表单及真实材料、来源批次、空位置选择。复制清除实例编号和位置，必须另选位置。清单检查重复位置、手工实例编号和重复新建来源批次；同批实物应先创建来源批次，再选择已有批次。确认前不发库存写入请求，关闭未提交清单须确认放弃。

待审批表格选择本页申请后，可统一批准或拒绝。准备阶段逐单读取最新版本及所有明细页；任一申请不能完整加载或已不可审核，不提交整份批次计划。确认后每单保留自己的完整结论及幂等键，服务端逐单校验、逐单提交。

申请详情选择本页可执行明细后，可一次确认多个获批动作。每条仍调用 P12 的单明细执行接口，不改变获批量、目标位置、来源治理绑定或授权规则。失败不阻止后续确定可提交的项目；不支持跨工作区或跨申请详情拼凑执行。

## 3. 代码职责与恢复

`component/batch-operation` 只管理顺序执行、逐项状态、进度和账号所属的 tab-session 日志，不是业务 bulk engine。审批和库存原有 store 分别提供输入/回执校验、发送与回执核对；页面负责输入及同步列表。服务端继续使用既有版本、权限、幂等、事务、流水、审计，不增加批量路由或修改数据库结构。

冻结的原 scope、参数、幂等键在发送前写入 sessionStorage。已知业务拒绝记录失败并继续；结果不明暂停。用户明确恢复时复用原参数／键，已成功项目不再发送。明确失败可选择重试原请求，也可结束批次后另建修正计划。未发送项可跳过；结果未明项不能被跳过或清除。

成功回执只通过 GET 核对并重新加载页面，读失败不重放写入。批次内有成功项时，同步完成才允许结束批次。单件与同领域批次在一个工作区内互斥，避免静默覆盖恢复信息。切换工作区会取消在途请求，保留原工作区计划；账号切换／退出清除旧账号内存及 tab 日志，忽略旧完成结果。

100 是客户端每次操作的上限，不是新增的服务端 bulk API 配额。现有单项端点继续逐次鉴权。未提交清单不持久化；确认提交后的恢复仅保证同一 tab session，关闭标签页或清除存储后不能依赖日志恢复，应先核对实际业务记录。不会在后台自动继续或跨窗口协调。
