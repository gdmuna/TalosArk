# P11 实施与验收记录

日期：2026-10-20。结论：本轮确认的四类单件库存操作已接通公开契约、后端事务、前端实际表单与流水展示，本地真实 HTTP、PostgreSQL 和 Web 定向验收通过。业务依据为 [对齐记录](mvp-p11-alignment-2026-10-20.md)，模块分工见 [代码层方案](../../packages/backend/docs/design/mvp-p11-plan-2026-10-20.md)。

## 交付范围

| 动作 | 真实效果 |
| --- | --- |
| 登记消耗 | 扣减实际消耗量，禁止过期实物正常消耗；余量为零转为已耗尽，保留占位 |
| 单件转移 | 更新同件实物的唯一 Placement，检查来源和目标设施授权及空位置，数量和所有权不变 |
| 核实数量 | 将余量调整到核实后的非负值，可高于初始量；初始量、位置与旧流水不变 |
| 移出管理 | 正量或零量均可明确退出库存管理，余量归零、释放位置，保留身份和历史，不能复活 |

四类原因均选填。未知有效期不要求额外确认，材料/批次归档不阻断既有存量操作。整件借出、普通归还、拆分合并、单位换算、批量执行和审批均未加入。

前端入口在库存列表的逐条操作及库存实例详情，共用有类型的动作对话框。单件转移使用现有真实可用位置选择器。移出管理要求明确确认，但不把系统记录解释为现实中的销毁程序已完成。

## 实现边界

InventoryActionService 复用 OrganizationWriteKernel 和 IdempotencyKernel。库存版本更新、占位变更、流水、审计及幂等完成在一个受管事务内提交。纯领域计划函数只计算数量、状态和占位意图；没有新增锁平台、任务表、状态机库或自动写重试。

共享的操作回执 codec、操作授权及回执位置投影收拢到 InventoryOperationService，入库、整体搬迁与新动作复用。新请求校验当前版本和状态；原成功请求在当前权限仍有效时返回原结果，不因后来耗尽、处置或停用而再次执行或错误拒绝。

纯数量调整不额外要求设施读取/使用权，但仍通过 Facility 内部事实检查来源有效生命周期。当前位置、历史来源和目标位置、公开回执均按当前设施读取权隐藏；数据库快照和持久回执保留原事实。无权位置过滤条件也被拒绝，避免通过 nodeId 查询推断隐藏占位。

本轮明确收紧 P09：来源设施、位置或祖先停用后，不再允许新发起的带存量整体搬迁。已完成操作的受权只读重放仍保留。公开契约新增 Stock.actions、动作回执分支、位置受限标记及 nullable 回执 nodeId；前后端需同步更新，不提供旧客户端兼容层。

前端发送前将完整原命令与 key 保存到按账户隔离的 sessionStorage。未知结果刷新后复用原请求；已知成功后读取失败只重读原实物、对应流水及当前页面。明确的首次业务拒绝保留草稿，显式加载新库存后才能生成新命令；该加载会清空旧目标位置和处置确认。关闭标签页或换浏览器不承诺恢复。

## 数据库操作

仅连接获准的 `talos-ark_backend_test`。先读取实际数据库名、枚举及现存状态/数量，再定向添加 CONSUMPTION、DISPOSAL 和 `StockItem_status_quantity_check`。未运行全库 db push、清库或修改 dev/prod。

新增 CHECK 约束 IN_STOCK 必须正量，DEPLETED/DISPOSED 必须为零；既有预留状态不在本轮强行定义。DISPOSED 无 Placement 由事务维护，未伪装成跨表 CHECK。验收只新增合成账户关联的业务记录；保留其流水便于追溯。故障注入使用的临时数据库触发器和函数已在 finally 中移除。

## 真实验证

环境为隔离后端 3109、前端 4459、普通非超级管理员合成所有者及显式授权成员；Playwright 驱动本机 Edge。库存验证不依赖对象存储，也没有发送真实邮件。

| 场景 | 结果 |
| --- | --- |
| 部分/全部消耗、零量和超量拒绝、精度、等价数量规范化 | 通过 |
| 调整高于初始量及归零、耗尽保留占位、零量/正量处置和终态禁止操作 | 通过 |
| 过期禁止消耗，未知无额外确认，归档材料/批次存量允许消耗 | 通过 |
| 同键重放、改动作/数量冲突、耗尽/处置后的原成功回执 | 通过 |
| 两次竞争最后余量、两件争同一空位置 | 各仅一项提交，另一项 409 |
| 独立动作权限、调整无设施读取/使用权、撤权后重放 | 通过 |
| 隐藏当前位置、历史快照、公开回执及 nodeId 过滤保护 | 通过 |
| 来源祖先停用冻结四类新写入、隐藏位置调整及 P09 搬迁 | 通过；停用前的成功操作仍可受权重放 |
| 真实数据库审计失败发生在占位删除之后 | 技术错误 500；库存版本/数量、占位、流水、审计、幂等记录全部回滚，同原键随后可成功 |
| Web 四类表单、真实空位置选择、选填原因、提交后读取 | 通过 |
| Web 真实版本冲突 | 保留数量草稿、禁用再次提交，显式加载后才继续 |
| 服务端已提交但浏览器丢失响应，完整刷新后恢复 | 原 body/key 逐字段一致，只有一条成功流水 |
| 已知成功后读取故障，再点击“只重新加载” | 无新增 POST，读取同步后清除回执 |
| 对话框 1440、1024、390 宽度 | 边界检查、截图复核通过，内部无横向溢出；不代表整个应用移动端验收 |

真实 HTTP/PostgreSQL 验证共九组；实际 Web 流程和无页面异常检查共七组。契约构建、Prisma client 生成、后端构建与类型检查、前端类型检查和 Vite 生产构建通过。定向 ESLint、Prettier 与 diff 检查通过，没有新增永久测试脚本或重跑全仓历史测试。

默认 ESLint 启动链接指向缺失的 10.10 文件，本轮直接调用本机已安装的 10.12 执行，未更改依赖安装。Vite 的已有主包体积警告仍在。

临时脚本及原始证据位于忽略目录 `output/p11-2026-10-20/`：`schema.mjs/schema.json`、`api.mjs/api.json`、`browser.mjs/browser.json`、`final.mjs/final.json`、`fixture.json` 和对话框/恢复截图。最终只读复核确认新 CHECK 已验证，数量/状态冲突、已处置仍占位、在管实物缺占位均为零；无遗留故障触发器或函数。它们是本机验收产物，不是永久业务代码或测试套件。凭据位于已有隔离运行时的私有文件，不进入文档或版本控制。
