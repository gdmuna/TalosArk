# P09 带存量搬迁前端交付与验收

日期：2026-10-20。接续 [P09/P10 真实验收](mvp-p09-p10-acceptance-2026-10-20.md) 中尚未交付的搬迁发起入口。本轮只补齐现有 P09 业务，不新增 P11 单件转移，不修改后端、公开契约、数据库结构或授权规则。

## 用户现在能做什么

在库存的存储浏览、管理中心的设施详情/存储结构、存储设施治理三个页面中，选择有结构管理能力的容器，即可使用“带存量搬迁”。原有“移动空子树”保留，两者使用不同业务入口。

用户选择目标设施、父容器或设施顶层，按需调整目标编号和网格坐标，然后获取服务端影响预览。预览显示旧/新路径、节点及实物数量、实物编号/数量/所属工作区，以及源/目标管理工作区和设施准入工作区。已知工作区显示真实名称，未知名称保留 ID，不猜造标签。

填写原因并明确确认治理变化后才能执行。更改目标、父级、编号或坐标会清除原预览和确认。后端继续检查完整子树、所有受影响工作区的成员和权限、目标设施准入及当前指纹；不能选择性跳过部分存量。

实物和库存身份、数量、状态、工作区归属及 POSITION ID 不变。变化的是容器子树的当前位置和结构治理上下文；历史由既有后端原子流水、审计和幂等机制记录。

## 实现边界

`module/inventory/data` 增加已有搬迁预览、执行及操作回执查询的 HTTP 适配，继续使用公开 Zod 契约、响应关联校验和显式关闭自动重试。没有在页面直接调用原始 HTTP。

`module/inventory/model/relocation.ts` 持有跨路由恢复状态。账户限定的 sessionStorage 只保存组织、原执行参数、幂等键及已确认回执，不保存影响预览的实物列表。写入前先保存恢复信息；保存失败不发请求。关闭标签页或换浏览器不承诺恢复。

未知结果只重放原参数和原幂等键；恢复期间的拒绝不能推定先前未提交，因此不清除未知请求。第一次明确的 4xx 拒绝允许用户重新预览。确认成功后只通过 GET 核对回执和重新读取结构，后续合法搬迁不能反过来否定已有成功回执。退出或更换账户清理状态并忽略迟到结果。

跨模块 UI 编排位于 `page/inventory/component/InventoryStorageBrowser.vue` 和 `InventoryRelocationDialog.vue`，三个页面复用这一份实现。Facility 的 StorageBrowser 只新增节点操作插槽，NodePicker 从现有 UI 公开入口导出；未放宽架构依赖限制，也未让设施和库存模块相互引用。

## 真实验证

沿用先前隔离验收环境：test.local 的 `talos-ark_backend_test`、后端 3109、前端 4459、Playwright 驱动本机 Edge。仅使用先前的合成组织和账户，未运行 DDL、清库或操作 dev/prod；未依赖对象存储或真实邮件发送。

| 场景 | 结果 |
| --- | --- |
| 三个实际页面打开同一搬迁界面 | 通过 |
| 真实服务端预览显示 6 个节点、4 件实物及治理范围 | 通过 |
| 编辑目标编号后旧预览/确认失效 | 通过 |
| 预览后真实修改拓扑修订，再提交 | 409 拒绝，要求重新预览 |
| 搬迁成功，目标设施重读被故障注入阻断 | 明确提示已成功但未同步 |
| 恢复上述同步失败 | 只发 GET，不新增搬迁 POST |
| 服务端真实提交后丢弃响应，再刷新页面 | 恢复原请求；逐字段复用相同 body/key/fingerprint |
| 重放成功后的实物和流水核对 | 4 件实物身份/数量/状态/占位 ID 不变，原操作只有一条流水 |
| 1440、1024、390 宽度的搬迁对话框 | 边界检查及截图复核通过，对话框内部无横向溢出；不代表整应用移动端验收 |
| 15 项定向单元回归 | 通过：预览/回执关联校验、持久化先于写入、刷新重放、只读恢复、冲突、撤权后未知结果保留、存储故障及退出迟到结果 |
| vue-tsc、Vite 生产构建、定向架构/ESLint、Prettier、diff 检查 | 通过 |

测试把同一台有存量的冰箱搬回原设施，再搬回先前验收结束时的目标设施。数据库累计仍为 6 个实例、6 条库存、6 个占位；操作/流水从 7 增至 9，明细从 10 增至 18，正好对应本轮两次成功搬迁。预览冲突没有产生业务流水，响应重放也没有重复产生业务流水。本轮合成拓扑漂移节点与历史记录保留用于追溯。

运行脚本、请求记录、数据库核对和截图位于忽略目录 `output/acceptance-p09-p10-2026-10-20/` 中的 `relocation-*` 文件。私有合成登录凭据没有纳入版本控制或公开文档。

验收后已关闭本轮临时 3109/4459 服务，未停止原有 3000/4444 开发服务。

## 尚未证明

本轮真实 Web 场景是同组织、同工作区的两个设施；混合工作区治理变更/权限组合仍沿用后端已有验收边界，不宣称本轮已覆盖其全部 Web 组合。没有进行千件性能测试、Tauri 或生产部署验收，也没有修复已知旧前端测试中的失效导入。

默认 ESLint 启动链接仍指向缺失的 10.10 文件，本轮用本机已安装的 10.12 直接执行并通过，未修改依赖安装。Vite 仍提示已有的主包体积警告；未为此改变既定静态路由导入策略。
