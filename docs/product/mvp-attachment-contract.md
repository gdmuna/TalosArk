## 1. 已确认的业务规则

| 项目 | 首发约定 |
| --- | --- |
| 用途 | 仅 `material.attachment`，由材料模块贡献；不细分 SDS、质检报告等用途 |
| 单文件大小 | 最多 100 MiB，即 104,857,600 字节；不能仅依赖浏览器校验 |
| 格式 | 下方列明的常见文档、图片和表格白名单 |
| 上传 | 单次和分片均支持；完成前核验实际字节数和完整 SHA-256 |
| 内容安全 | 暂不识别真实类型、不做病毒扫描；扩展名和声明 MIME 不是安全证明 |
| 展示 | 提供附件列表和下载；不提供内联预览、文件版本或在线编辑 |
| 复用 | 每个 FileAsset 只绑定一个材料，不提供已有附件的跨材料复用 |
| 查看与下载 | 每次检查目标材料的当前 `material.read` 权限 |
| 绑定与解绑 | 每次检查目标材料的当前 `material.update` 权限，并检查材料未归档 |
| 解绑 | 立即停止通过应用获取该附件；保留引用历史，按清理流程回收，不恢复成上传者可访问的未绑定资产 |
| 材料归档 | 已绑定附件只读：有当前读取权限的用户仍可查看和下载，禁止新增绑定及解绑；恢复材料后可继续管理 |

“一个资产只绑定一个材料”不等于“一个材料只能有一个附件”。相同字节内容重新上传形成新资产，不自动共享权限，也不因哈希相同开放已有资产。

### 格式白名单

| 类别 | 扩展名（匹配时不区分大小写） |
| --- | --- |
| 文档 | `.pdf`、`.docx`、`.pptx`、`.txt`、`.md` |
| 表格 | `.xlsx`、`.csv` |
| 图片 | `.jpg`、`.jpeg`、`.png`、`.webp`、`.gif`、`.tif`、`.tiff` |

不包含旧版 `.doc/.xls/.ppt`、宏文档、压缩包、可执行文件、SVG 或音视频。
实现应明确扩展名与允许的声明 MIME 对应关系；不能因为声明为 `image/*` 或通用二进制类型就放行白名单外文件。
具体 MIME 兼容映射已在材料用途定义中固化；公共 schema 不把浏览器提供的 MIME 当作检测结果。
大小、格式准入在签发材料附件上传前校验，绑定时再次校验，防止其他通用上传入口绕过用途限制。

## 2. 权限与归属

- 当前用户来自已经验证的会话；组织、工作区、材料归属从 I04/I05 与材料事实入口解析，客户端不能声明自己是上传者或资源所有者。
- 首次绑定只接受同组织、当前上传者拥有的有效未绑定资产，并要求该用户有目标材料的当前更新权限。
- 未绑定资产继续沿用 I08-A 的上传者私有规则。绑定后不再通过上传者入口下载，必须通过具体材料的有效 FileReference。
- 上传者失去成员资格或权限后，没有所有者旁路；其他仍有材料读取权限的成员可以继续下载有效附件。
- 下载、绑定、解绑及其重复请求都重新检查当前授权。知道 assetId、referenceId 或 resourceId 不等于获准访问。
- 材料归档不删除有效附件或启动未绑定资产回收；但在上传期间材料被归档或权限被撤销时，后续绑定必须拒绝，不能沿用上传开始时的授权。

## 3. 绑定、解绑与失败语义

生命周期为：上传并验证 → 上传者私有的未绑定资产 → 材料附件 → 解绑后逻辑移除 → 满足条件后物理清理。

1. 未验证、过期、已删除、组织不匹配或非当前上传者的资产不能首次绑定。
2. 同一有效绑定的合法重复请求返回原 reference，不创建第二份引用或重复业务副作用。
3. 同一资产同时绑定不同材料，最多一个成功；不能仅靠调用前查询或现有三列唯一索引保证这一点。
4. 首次绑定成功后清除未绑定期限，防止仍有效的附件被当作过期未绑定文件回收。
5. 解绑在同一数据库事务中标记引用移除和资产逻辑删除，保留历史关联，不重新发放未绑定资产访问权。
6. 仍有当前操作权限且材料未归档时，重复解绑返回已移除结果，不重复产生变更。不能清空 `removedAt` 恢复绑定；重新添加须重新上传。
7. 绑定失败不修改有效引用，也不把文件变为公开文件；未绑定资产仍按原期限处理。权限拒绝不能通过响应泄露其他组织的文件或材料信息。
8. 绑定、解绑与清理共用 `FileObject → FileAsset` 锁顺序，在锁内复查状态、期限与有效引用。并发治理、材料归档和附件写入也必须采用一致的授权与锁协议。

逻辑解绑立即影响后续应用访问；它不等于立即从对象存储删除字节，也不能撤回已经发出的签名地址或已下载的副本。

取消上传同样先结束业务会话，不承诺在取消响应前同步 abort 分片或删除暂存字节；物理回收由独立清理流程负责。2026-10-22 的真实取消验收确认了状态终止与禁止继续签名，不等于清理调度已经验收。

## 4. P10 的接口约束

下表定义能力和数据边界。对应的 HTTP 路由与 TypeScript schema 已在 P10 按现有契约规范落地，具体路径见 [P10 实施记录](../../packages/backend/docs/design/mvp-p10-2026-10-19.md)。

| 能力 | 请求信息 | 结果与约束 |
| --- | --- | --- |
| 发起附件上传 | 目标 materialId、幂等 key、文件名、声明 MIME、字节数、完整 SHA-256、单次/分片模式 | 校验用途与材料当前可管理状态；返回 sessionId、期限和服务端分片计划 |
| 签名、进度、完成、取消 | sessionId；按操作传 partNumber 或完整 parts 清单 | 沿用 I08-A 会话所有权与状态协议；用途准入不能绕过；完成得到 assetId，不表示已绑定 |
| 绑定 | materialId、assetId | 服务端确定 `material.attachment` 和真实 resourceId；返回稳定 referenceId |
| 列出附件 | materialId、分页参数 | 授权后查询有效引用；返回明确附件投影，不返回内部存储位置 |
| 下载附件 | materialId、referenceId | 校验该引用确属该材料、当前有效且可读；返回短期下载请求和到期信息 |
| 解绑附件 | materialId、referenceId | 检查更新权限与未归档状态；原子逻辑移除，合法重复请求成功但不恢复引用 |

完成上传与绑定是两个步骤，不把对象存储 I/O 放进材料业务事务。
数据库中的绑定、生命周期更新和必要业务审计同事务提交；签名生成在事务外，签发返回前复查当前引用与授权。
I08-B 已为会话补充可空用途/目标字段，并将用途约束接入上传和绑定入口；通用会话保持兼容，绑定时仍重新校验准入。

公共投影使用 UUID、日期时间字符串和十进制字节数字符串，不泄露 Prisma/SDK 对象、bucket、key、uploadId、lease 或内部错误详情。
文件名、声明类型、大小、上传时间和 referenceId 属于附件投影；签名请求中的临时凭据不得记录日志，也不作为永久附件 URL 保存。
客户端使用服务端返回的签名方法和 headers，保存 sessionId；恢复时重新读取并校验服务端权威的分片 ETag 清单，不把本地镜像当作上传状态。完成响应丢失时重查或重放原会话，不自动新建上传。

前端至少区分：文件准入失败、会话失效、完成中、绑定失败、权限变化、材料归档、下载失败，以及可安全重试的原请求；不能把上传完成提示成附件绑定成功。

## 5. 保留期限与撤权窗口

本轮不修改 I08-A 已有程序化配置默认值，也不把它们表述成新确认的产品 SLA：

- 从未绑定的资产沿用默认 24 小时未绑定期限；会话沿用默认 1 小时期限。
- 上传签名默认 10 分钟且不超过会话余下期限；下载签名默认 60 秒。
- 解绑后的资产逻辑删除，不重新开始 24 小时可访问期；清理在确认无有效引用后执行。
- 撤权或解绑后不再签发新下载地址。已经签发的地址在有效期内仍可能使用，已开始的传输也不保证立即中断。
- 本轮没有“解绑后 24 小时恢复”入口，没有自动清理调度器，也不承诺物理删除完成时间。

**P10 后端已实施：** 公共请求/响应与错误 schema、认证上下文映射、HTTP 入口、上传进度查询、下载签名与解绑服务端授权。**P10 前端代码已接入：** 材料详情附件区、single/multipart 上传模式、服务端分片计划、ETag 进度恢复、绑定、下载与解绑交互。R06 新增分片 UI 已做隔离浏览器复验，真实存储复验仍待完成；不得用前端隐藏按钮代替服务端授权。

**剩余验收：** 本地对象存储真实 PUT、分片、SHA-256 校验及下载签名端到端验证；I08-B 的绑定/清理、归档/解绑、权限撤销与重复请求竞争验证；前端真实登录闭环。`test.local` 已按用户授权同步至当前 Prisma schema；dev/prod 数据库、真实 SMTP、真实 Casdoor 和部署环境均未在本轮操作或验收。证据不足时不宣称完整附件闭环已完成。

2026-10-21 S3 专项补记：本机实际存储的浏览器签名 PUT/下载、ETag/CORS，以及真实后端两片上传、整文件 SHA-256 和合并响应丢失恢复已补验；后端仓储为内存替身，未写真实组织。缺桶/认证/连接等存储依赖故障现映射为 `MATERIAL_ATTACHMENT_STORAGE_UNAVAILABLE`（503），公开 details 为 null；progress 不再初始化分片，旧会话可不依赖存储取消。完整真实登录 UI/绑定/撤权和部署验收仍单列，详见 [S3 补记](../../packages/frontend/docs/remediation/2026-10-15/r06/audit-2026-10-21.md#s3-专项修复补记)。

必须能证明：白名单和大小限制有效；上传完成不自动绑定；并发同资产只绑定一个材料；解绑不恢复上传者访问；归档只读且恢复不复活已解绑附件；当前权限决定下载；清理不删有效附件；签名撤权窗口被如实说明。

真实类型识别和病毒扫描保持延期，不因此引入 I09、任务系统、缓存平台或内联预览。
