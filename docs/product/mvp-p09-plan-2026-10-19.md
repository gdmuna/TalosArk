# P09 真实入库与带存量搬迁实施方案

日期：2026-10-19。状态：用户已批准执行，后端已交付并完成 test.local 定向验证，前端闭环待接入。本文保留实施设计，实际接口及验证边界以 [交付记录](../../packages/backend/docs/design/mvp-p09-2026-10-19.md) 为准，不表示已授权操作其他数据库环境。

产品规则以 [P09 业务对齐记录](mvp-p09-alignment-2026-10-19.md) 为准。本文说明怎么落地，不重新打开已经确认的问题；接口命名、字段命名和技术上限是本方案的实施设计，不冒充现有能力。

## 1. 这次交付到哪里

用户能够维护材料的来源批次，把一件实物登记到合法空位，查到真实库存和入库流水，并在填错描述资料时有审计地更正。随后打通同组织内的整盒、整台冰箱带存量搬迁，保持实物身份、数量和库存工作区归属不变。

本轮后端必须同时交付可供前端调用的读取与写入契约，不能只有入库成功接口、没有库存详情和流水。页面由已交接的前端工作承接，本线程不自动修改页面或向其他会话派发任务。

本轮不做无位置入库、多件入库表单、单位换算、自动拆分、单件领用/归还/转移/数量调整、错误入库撤销、审批、实例删除/归档或硬件执行。单件库存修正留 P11，批量入库留 P13；资料更正不能绕过这些范围。

## 2. 模块职责先分清

| 所有者 | 本轮负责什么 | 不负责什么 |
| --- | --- | --- |
| Material | 材料定义、数量单位与精度、来源批次及其资料/归档、入库来源事实 | 不保存库存余额，不编排 Placement 或库存流水 |
| Inventory | 实物实例的首次登记和资料更正、当前库存/位置、业务操作记录、流水、带存量搬迁编排 | 不直接修改 Facility 私有结构规则，不维护材料定义 |
| Facility | 位置生命周期、设施访问关系、结构修订/锁定、原子树迁移及前后位置事实 | 不解释材料属性，不替库存所属工作区授权或写库存流水 |
| Core | 复用 OrganizationWrite、Authorization、Permission、Resource、Audit、Idempotency | 不新建 InventoryKernel、通用 scope 迁移框架或全局幂等表 |
| Bootstrap | 注册实际模块、配置与错误/权限贡献，配置新建角色的默认授权 | 不在启动或读请求中修复已有角色、写业务记录 |

依赖方向保持 `Inventory -> Material(public) + Facility(public) + Core`。Material 与 Facility 不反向导入 Inventory；设施页面的库存信息由 Inventory 的受权读接口补充，而不是让 Facility 读取库存私有服务。

MaterialInstance 当前只有 Schema、没有已运行的实物用例；本轮将其运行行为与 StockItem 一起归 Inventory 编排。它位于 material.prisma 不等于必须由 MaterialModule 维护，也不为文件整齐顺手搬动全部模型。

现有 Material 对实例存在性/数量的查询、Facility 对 Placement 存在性的检查，继续作为有限的不变量事实读取，不升级为跨模块任意业务写入。

## 3. 模型与公开字段变化

| 对象 | 本轮设计 |
| --- | --- |
| Material | 增加 quantityScale，0～6、默认 6；已有实例后，与单位和分支一样禁止修改 |
| MaterialBatch | 生产日期改为 manufacturedOn；有效期为 expiryKind + expiresOn，三态为 UNKNOWN / NONE / DATED；日期使用 PostgreSQL date；增加 revision，保留批号、备注和归档 |
| MaterialInstance | 增加 manufacturedOn、receivedOn、expiryKind、expiresOn、revision；openedAt 保留带时区时间戳；初始数量保留，含义为首次登记实存量，可为 0 |
| StockItem | 沿用一实例一库存、数量和 version；首次数量与实例初始量一致，0 为 DEPLETED，正数为 IN_STOCK；过期不是另一个持久化 StockStatus |
| Placement | 保留一实物一位置、一位置一实物；零量仍创建并保留占用；整容器搬迁不更换所指孔位 ID |
| InventoryOperation | 新增 Inventory 私有的整次业务操作记录，保存幂等作用域、原始执行人、操作类型、指纹版本/哈希、事务内 lease、完成状态和小型结果快照 |
| InventoryTransaction | 增加 operationId，按实际工作区生成流水头；一操作可产生多个工作区流水。幂等键/请求哈希由 Operation 唯一持有，不在各流水头重复承担整次操作去重 |
| InventoryTransactionLine | 沿用数量/状态前后值、单位与位置快照；补来源/目标设施及拓扑的历史标识，路径快照包含当时设施和节点的可读名称/编号，不只保存 ltree UUID 路径 |
| InventoryTransactionType | 增加明确的 CONTAINER_RELOCATION，避免与 P11 单件 TRANSFER 的执行方式混淆 |

流水与 Operation 使用组织一致的关联约束；同一 Operation 在同一工作区最多生成一个流水头，各实物一条流水明细。数量、状态、来源和目标位置等历史数据在执行时确定，普通编辑不改写。

### 3.1 需要提前说明的破坏性变更

批次和实例原 expiresAt 时间戳将被日历日期及有效期三态取代；实例增加生产日期和到货日。InventoryTransaction 原有 idempotencyKey/requestHash 及对应唯一约束，将迁至整次操作记录。本轮不能用 UTC 零点转换脚本替用户猜测旧日期含义。

这些表目前没有已交付的库存运行接口，但仍须在执行前只读核对目标库。发现实际历史数据时先报告具体影响，不因“快速迭代”自动丢弃或臆造其日期/幂等记录。只实施本轮差异，不以全仓 db push 顺带覆盖并行的 I08 或其他改动。

### 3.2 数量与日期的实际规则

数量从输入、计算到公开响应均使用十进制字符串，复用现有精确解析/格式化；最多 14 位整数、6 位小数，不经 JS number、不接受指数、不四舍五入成合法输入。按数值有效小数位检查 quantityScale，尾随零不导致整数被误拒绝；字段文案和展示不能混淆“实例件数”与“剩余数量”。

日期 wire 值为真实日历的 YYYY-MM-DD，不能靠 Date.parse 自动归一化不存在的日期。DB date 与 Prisma Date 的转换只在持久层处理，业务仍按日历日期理解。生产/到货日期和开封时刻未知可留空；有效期未提供默认为 UNKNOWN，不等于 NONE。

批次日期是表单默认值。提交时发送本件确认的最终生产日期与有效期状态/日期，保存到实例，不留下动态继承分支；选择批次时携带其修订，发现资料或归档变化则重新确认，不静默替换用户已确认的日期。开封后效期不自动推导。

确定有到期日的实例，在业务时区当地日期超过 expiresOn 后才过期。计划新增 INVENTORY_BUSINESS_TIME_ZONE，默认 Asia/Shanghai，启动时校验 IANA 时区并经 typed config 显式注入；落实到应用 example 和实际应用 env，Prisma-only env 不增加无消费者配置。客户端按服务端业务日期/时区展示，不用浏览器时区另算结论。

超出精度、无效日历和明确矛盾的生产/有效期组合拒绝；不猜测统一的“先到货、再开封”顺序，因为历史存量可能在到货前已开封。过期确认只针对首次执行时的风险，不能让原本成功的请求在次日重放时因新过期而再次入库。

## 4. 权限和数据可见性

| 能力 | 计划权限与额外条件 |
| --- | --- |
| 批次读取 | material.read；只返回批次资料，不顺带泄露库存统计 |
| 批次创建/编辑/归档恢复 | material.batch.manage + material.read；内联新建采用同一规则 |
| 库存、实例和本工作区流水读取 | inventory.read + material.read，以及有效组织/工作区成员资格 |
| 单件入库 | inventory.receive + inventory.read + material.read；目标位置另须 facility.use 和真实设施准入 |
| 实物资料更正 | inventory.instance.update + inventory.read + material.read，附原因和 expectedRevision |
| 带存量容器搬迁 | 来源/目标结构管理资格；每个受影响工作区的 inventory.transfer、inventory.read、material.read 与有效成员资格；目标设施向这些工作区全部开放使用 |

MVP 不另外增加一个绕过上述交集的“超级搬迁权”，也不引入组织所有者豁免。迁移是独立命令，不意味着本轮额外实现审批；结构管理能力对参与受控迁移的含义在权限说明和确认界面明确呈现。

新工作区默认角色由 composition 配置。已有工作区通过显式、受控的权限初始化入口升级，不在列表查询、启动 Discovery 或重复登录中悄悄加权；初始化沿用既有组织所有者治理规则，并保留审计。

库存自己的事实与当前设施结构读取分开：能读本工作区库存，不代表能读任意设施结构；设施管理员也不能自动读其他工作区材料。位置详情最多先展示占用事实，受权库存接口才补实例内容。资源标签和深链接按当前真实归属再授权，不能信任前端携带的 workspaceId。

材料/批次归档停止新登记，但不清占位、不隐藏原工作区已获授权的历史，也不阻断合法移出。过期、未知有效期和已耗尽分别呈现；P09 不把 IN_STOCK 或一次入库成功宣传为 P11 已批准可领用。

## 5. 单件入库怎样提交

1. 严格解析 scope、材料、可选批次、实物资料、十进制数量、位置、风险确认与幂等键。实物编号可选；未填表达“系统生成”，此时不提前生成随机编号。
2. 进入 OrganizationWriteKernel，取得组织锁并重新检查当前身份、工作区及材料/入库权限；沿用 ReadCommitted，不另建独立提交的子事务。
3. 在同一事务内申请 InventoryOperation 幂等记录。若已完成，走第 7 节的受权重放，不再次要求“位置为空”或创建新实例。
4. 首次执行才检查材料未归档、单位/精度、批次归属及生命周期；如明确新建批次，经 Material 公开写能力鉴权、创建资源与批次，失败一起回滚。
5. 在组织锁内调用 FacilityPositionReader，再次核对实际设施/拓扑/位置、祖先状态、使用权和占用。位置预检不能代替这一步。
6. 生成或接受唯一实例编号，创建实例及其 ResourceIdentity，再创建 StockItem 及其资源身份；初始数量与当前量相等，零量状态为 DEPLETED。
7. 创建 Placement；唯一约束保底处理竞争。创建 RECEIPT 流水，数量从不存在记为 0 到初始量，statusBefore 为 null；零量入库也有真实登记流水和占位。
8. 记录必要审计，完成幂等小型结果快照；全部随同一物理事务提交。资源、审计、位置或幂等完成任何一步失败，都不能留下孤立实例或成功流水。

实例编号采用有明确前缀的系统随机编号，不编码位置、材料名或可变资料，不为 MVP 开发全局连续编号中心。手工编号冲突明确返回；自动编号碰撞在安全写入前判定并有界重新生成，不能在 PostgreSQL 已失败的事务中 catch 后继续写。

## 6. 带存量容器搬迁怎样执行

先提供只读预览，再提供实际执行。预览展示来源/目标、结构规模、所含实物和工作区范围、治理与结构可见性变化；只有全部授权通过才返回完整影响摘要，否则统一拒绝而不点名无权材料。执行不是预览令牌放行。

1. 取得组织写锁，重新验证操作者；按稳定顺序取得来源/目标拓扑锁，并校验设施/拓扑修订、目标结构和完整受影响集合。
2. 影响集合包含所有实际 Placement，不能因为数量为 0、已过期或材料已归档而跳过。依据实物真实归属逐工作区鉴权，确认目标设施向所有这些工作区开放使用。
3. 核对预览后的内容/版本是否变化。确认版本须覆盖来源/目标设施与拓扑修订、存量集合和库存版本；仅有 topology.revision 不足以发现 P11 以后发生的数量/占位变化。
4. 在树移动前保存前位置事实，调用 Facility 的事务内公开搬迁能力，保持节点/资源 ID；源、目标编号/坐标冲突、循环、状态或版本不符直接失败，不自动改号。
5. 取得新位置事实，按每个库存所属工作区创建 CONTAINER_RELOCATION 流水及明细。数量、状态、保管人和 workspaceId 不变，Placement 所指孔位 ID 不变；受影响 StockItem.version 推进，避免旧操作视图静默继续使用。
6. 保存结构搬迁审计、各工作区必要审计和整次操作结果，统一提交；任一步失败整棵树、全部流水和版本一起回滚。重复请求返回同一操作结果，不重复写流水。

路径快照必须包含设施信息：同一盒子作为根节点跨设施移动时，ltree UUID 路径甚至可能不变，不能据此判断“没有移动”。未来资源描述查询解析新位置，历史记录仍显示当时的位置。

普通 P08 结构接口继续拒绝带占用子树。Facility 公开能力集中承载已存在的结构校验、锁与修订，不让 Inventory 复制私有规则，也不让 Facility 反向依赖 Inventory。准备与实际移动均限定在同一受管事务，不把准备结果当外部可复用凭证。

本轮为同步操作设置明确技术上限，初始设计为最多 10,000 个结构节点、1,000 件有占位实物，执行前完整检查；超过上限明确拒绝，不隐式拆批。数值在实现时结合本地定向验证收敛，不能以列表每页 100 条推断整个子树最多 100 件。

## 7. 幂等必须对应整次操作

沿用 I07 内核，仅新增 Inventory 真实持久化 Adapter。单件入库使用工作区作用域；混合搬迁使用 organization-user 作用域，工作区集合从数据库推导，不由任意“当前工作区”替所有流水承担归属。

InventoryOperation 按组织、作用域种类、作用域 ID、幂等键建立唯一约束。operation 参与指纹，不偷换成新的去重命名空间；指纹包含受信执行人及规范化请求，自动生成编号、服务端时间和新建行 ID 在首次 claim 后确定，不进入每次重算会变化的输入。

claim、实际业务和 complete 同事务。成功结果只保存操作回执及必要 ID/确认值，不保存任意 HTTP Response、完整树或全部库存实体；多工作区搬迁结果按操作 ID 查询，不把无限长明细塞进重放快照。提交后才能对调用方宣称成功。

同键同内容返回原结果，同键不同内容明确冲突；失败回滚不留下“占住键但什么都没做”的成功记录。发现已完成而结果丢失时明确不可重放，不重新执行。网络断开造成提交结果不明时，以同键重试或受权查回执确认，不换键盲目重放。

重放先重新验证当前身份与结果所涉及的真实权限；丢权后不能靠旧键读取敏感结果。已完成重放与首次执行的状态前提分开，不能因原位置现在已占用、节点已离开旧拓扑或材料后来归档，就误判为应再次执行或生成第二份记录。

## 8. 公开接口与错误口径

计划工作区前缀为 `/organization/:organizationId/workspace/:workspaceId`；所有输入/输出为公开 Zod 契约，Controller 保留 ApiRoute + Method 的既有模式，成功包络按声明校验，不直接返回 Prisma 对象。

| 接口组 | 计划能力 |
| --- | --- |
| `material/:materialId/batch` | 批次列表/详情、创建、资料编辑、归档/恢复；写入带 revision，读不到未授权库存统计 |
| `inventory/context` | 当前工作区能力、业务日期/时区和本轮输入规则，不靠前端猜角色名称 |
| `inventory/receipt` | 单件入库，输入幂等键和完整确认资料，返回操作/实例/库存/流水回执 |
| `inventory` 与 `inventory/:stockItemId` | 库存列表和实物详情，明确一行是一件实物，包含数量、批次、风险、当前可见位置和能力 |
| `inventory/:stockItemId/facts` | 更正描述资料，附 expectedRevision 与原因，不接受库存数量/位置字段 |
| `inventory/transaction` 与详情 | 当前工作区流水及明细，可按实物、材料和操作关联查询，保留事件时快照 |
| 组织级 `inventory/container-relocation/preview` 与执行 | 来源/目标结构上下文、修订与影响集合确认；作用域由真实数据验证，执行含幂等键 |
| 组织级 `inventory/operation/:operationId` | 查整次操作回执；按其实际关联范围重新鉴权，不成为公开任务查询或越权状态探针 |

批次选择用明确的“不选 / 选已有 / 新建”联合输入，不用同一个可空 ID 加一堆隐式创建规则。有效期用 UNKNOWN / NONE / DATED 判别联合，DATED 必须有合法日期，其他两态不得偷偷夹带日期。

列表排序稳定且有 ID 次序，过滤、计数、分页先应用合法工作区与材料读取范围；每页最多 100，分页不承诺跨请求冻结快照。历史和当前位置分别展示，不为缺权限字段伪造零值或“无位置”。

错误包括无权限/不可见、资料或版本冲突、编号/批号冲突、位置占用、生命周期不允许、风险未确认与幂等冲突。不存在与不可见沿用项目的不泄露口径。只映射明确识别的约束；未知数据库、CHECK 或程序错误不润色成用户填错表单。公共错误不暴露 metadata、数据库详情或堆栈。

```text
  application/                       单件入库、资料更正、读取和搬迁编排
  domain/                            精确数量、日期与状态规则
  infrastructure/persistence/        当前事实、流水和业务幂等适配
  contribution/ 与 extensions/        权限、真实目标解析和 Resource Provider
backend/src/modules/facility/public/  受控搬迁与受权位置/路径事实
backend/src/config/                  本轮有实际消费者的时区配置
backend/src/bootstrap/composition/   模块、错误、权限和 typed config 装配
```

MaterialModule 需要显式导出真正供 Inventory 使用的公开 Provider；仅有 public/index.ts 导出并不等于 Nest DI 已可用。InventoryModule 当前仍是骨架，本轮才变成实际 Nest 模块。批次、实例、库存分别提供真实归属的 Resource/Authorization 解析，不新增 Core 对业务类型的硬编码。

不恢复 TODO-only use-case/Repository 层作为空转发链，不为一个 Prisma 实现增加假想 Adapter，也不借机重构其他模块的目录和错误体系。

## 10. 按什么顺序交付

| 阶段 | 做到什么 | 交付门槛 |
| --- | --- | --- |
| P09-A 模型与契约 | 数量精度、日期三态、操作/流水关联、公开错误与权限定义 | 列清实际破坏点；契约与 Schema 可检查，未接运行部分不标完成 |
| P09-B 批次与入库 | 批次接口、InventoryOperation Adapter、单件原子入库、显式权限初始化 | 有真实回执；零量占位、位置竞争和重复提交有实际验证 |
| P09-C 读取与资料更正 | 库存/实例/流水读取、受权资源链接、资料修订审计 | 材料、库存、位置、流水可定位同一件实物；资料编辑不改库存事实 |
| P09-D 带存量搬迁 | 预览、全范围授权、受控树移动、分工作区流水及历史快照 | 混合存量完整成功或全部回滚，无原生结构入口绕过 |
| P09 收口 | 实施记录、契约交接、前端接入范围和实际验证边界 | 后端、HTTP、页面和真实依赖分别报告，不以一种代替另一种 |

前端可在 P09-A/B 后开始接入批次与入库，不必等最后搬迁完成。验收重点是业务闭环，不先完成“所有目录、所有扩展点”再开放第一条真实接口。

## 11. 需要证明的结果

按 backend 现有快速迭代约定，本轮不新增或维护永久测试脚本。实现时做构建、类型、定向 lint、Schema 与差异检查；在已批准的 test.local 库中先只读核对，再做本轮必要 Schema/DDL 与合成记录验证。不得触碰 dev/prod、清空库、删除他人的数据或为绕过构建问题停止用户服务。

| 场景 | 必须得到的结果 |
| --- | --- |
| 正量、零量、已开封、过期确认、未知/无期限 | 正确状态与风险，零量仍占位，不补造历史消耗 |
| 精度 0 和精度 3、尾随零、非法日期、业务时区日期切换 | 精确拒绝或接受，不舍入、不提前过期、不受浏览器时区干扰 |
| 批次资料变更与实例资料更正 | 批次不静默改旧实例，旧 revision 冲突，更正有原因与审计 |
| 两人竞争同位置、同编号/批号 | 只有合法结果，失败方无孤立资源、实例或成功流水 |
| 同键同内容、不同内容、响应丢失后重试 | 原操作回执或明确冲突，不重复创建；自动编号和时间不破坏稳定指纹 |
| 审计、资源、幂等完成、树更新中任一步失败 | 同一物理事务回滚，不提交半次成功 |
| 混合工作区授权与目标准入 | 全部满足才搬迁，缺一项整次拒绝，错误不泄露无权材料 |
| 整盒根节点跨设施、零量/过期存量随迁 | 实物/孔位身份保留，版本与流水更新，旧位置快照不变 |
| 预览后结构、授权或存量变化 | 执行重新检查，旧确认不能悄悄覆盖新事实 |
| 归档、设施停用及共享读权限 | 禁止新入库，保留事实与合法移出，不靠资料更正绕开库存操作 |

收口记录只清理本轮合成数据的明确 ID，写清实际库结构变化和并行未同步对象。服务级、合成 HTTP、真实登录 Web 和 Tauri 验收独立列出；前端未接、P11 尚不可执行和设备台账未联动都必须明示。
